# 窗与防盗网

窗与防盗网这两族承载了模组里最多的行为。这些在游戏内没有任何说明，因此本页是最能替你省时间的一页。

## 框窗是一张网格，不是单个方块

`FramedWindowBlock` 声明了三个属性：

| 属性 | 取值 |
|:---|:---|
| `FACING` | 水平朝向 |
| `POS_HORIZON` | 在窗户内的水平位置 |
| `POS_VERTICAL` | 在窗户内的垂直位置 |

**这意味着一扇框窗是由多个方块拼装成一个大开口的。** 每个方块知道自己处在网格的哪个位置——左/中/右 交叉 上/中/下——并据此渲染自己的边框，因此中竖框只出现在内部边缘、外框只出现在周界。

实际效果：放一个 3×3 的框窗方块阵，你得到的是**一扇带正确边框的九格窗**，而不是九扇各带边框的独立窗。位置状态在放置时推导，你只需相邻放置即可。

有三种变体——`framed_window_1`、`framed_window_2`、`framed_window_3`——边框比例不同，另有 `framed_window_slope` 用于坡屋顶下的斜切窗头。

::: tip
窗格碰撞是 `0,0,7 → 16,16,9`——**厚 2/16 且居中**。因此在一格厚的墙上，玻璃两面都凹进，这正是砌体洞口里真实窗户的样子。若想与某一面齐平，就把那一侧的墙加厚一格。
:::

## 预制阳台窗是两格高的，而且能开

`PrefabWindowBlock` 声明了：

| 属性 | 取值 |
|:---|:---|
| `FACING` | 水平朝向 |
| `HALF` | `upper` / `lower` —— 它是**两格高的方块** |
| `OPEN` | **true / false** |

所以 `prefab_window_balcony_*` 是一个**两格高、可以开合的单元**，像门一样。这正是那个年代几乎每户人家都有的封闭阳台窗——而它也是模组里唯一有功能（状态可变）的方块。

请记住[特殊形状](03_special_shapes)里说过的：它们是**互为镜像的左右两半**，`_balcony_left` 占 `x = 1..16`、`_balcony_right` 占 `x = 0..15`。请并排放置两个；只放一个会留下 1/16 的缝。

组合起来，一个完整阳台是**四个方块**：左与右，各自上与下。

## 防盗网刻意不连接玻璃

`SecurityGrilleBlock` 有 217 行——是模组里最复杂的方块。它可含水、朝向取自被点击的面（仅水平面），并会与邻居连接形成连续的笼体。

但模组只随包了**一个**方块标签，而它的存在就是为了阻止一种特定连接：

```
mirage2004:grille_no_connect
  #minecraft:impermeable
  mirage2004:curtain_glass_blue / _clear / _green
  mirage2004:window_glass_panel_blue / _clear / _green
```

**紧贴玻璃放置的防盗网不会与玻璃在视觉上融合。** 这是正确行为而非缺失功能：真实的防盗网是独立的钢框、栓在窗户外面，并不属于玻璃的一部分。没有这个标签，防盗网会与窗格融成一体、失去自己的轮廓。

注意 `#minecraft:impermeable` 也在列表里，所以防盗网同样与原版玻璃保持分离。

防盗网族提供五种构件——`security_grille` 平板，加 `grille_arch`（拱）、`grille_box`（箱）、`grille_cage`（笼）、`grille_cap`（帽）——足以建出外凸的笼式防盗网与平贴式两种。

## 电线杆也有垂直位置

`PoleBlock` 带 `FACING` 加 `POS`（垂直位置），因此堆叠的杆知道自己是基座、中段还是顶端。配合 `pole_arm` 与 `pole_base` 材料族，得到的是一根完整的电线杆而不是重复的柱子。

## 把一个立面拼起来

这些方块是按固定顺序设计来组合的，而顺序错了通常正是东西看着不对的原因：

1. 用 `qianxi_core` 表面材料族砌**墙**。
2. 把**框窗网格**嵌进洞口——相邻放置，让位置状态自行解析。
3. 在该有阳台的地方放**预制阳台**——四个方块，左/右 × 上/下。
4. 在玻璃前放**防盗网**——它会按设计保持视觉分离。
5. 路边放**电线杆与电线**，逐段设置朝向。
