# 技术说明

## 整个内容层由一个 Python 脚本生成

`src/generated/java/` 下的五个 Java 文件都带着直说的文件头：

> `// Generated by tools/generate_content.py. Do not edit by hand.`

| 生成文件 | 行数 | 内容 |
|:---|---:|:---|
| `GeneratedBlockCatalog` | **6064** | **277 条 `BuildingBlockDefinition`** |
| `GeneratedFamilies` | 207 | 18 个 `MaterialFamilySpec` |
| `GeneratedSpecialShapes` | 40 | 15 个手工编写的碰撞形状 |
| `GeneratedPalette` | 37 | 23 个 `ColorPaletteEntry` |
| `GeneratedCollections` | 23 | 2 个 `ContentCollectionSpec` |

::: info
**这是本批第一个把生成的 *Java 源码* 放进独立源集的模组。** datagen 产出生成的 *资源* 很常见，而生成声明内容的 Java 则不然。`ModBlocks.java` 只有 157 行、仅一处 `register(` 调用，因为它遍历 `GeneratedBlockCatalog` 而不是逐个列出方块。

对贡献者的影响：**改生成文件是没有意义的**——规格活在那个 Python 工具里，下一次运行就会覆盖它们。
:::

## 资源规模

| 资源 | main | generated | 合计 |
|:---|---:|---:|---:|
| blockstate | 33 | 242 | **275** |
| 模型 | 259 | 757 | **1016** |
| 物品定义 | —— | 275 | **275** |
| 战利品表 | —— | 275 | **275** |
| 贴图 | 107 | —— | **107** |
| 方块标签 | —— | 1 | **1** |

从中可读出两件事：

**275 个方块、275 份战利品表、275 个物品定义——三个集合完全一致。** 我直接比对了战利品表与物品定义的名称集合：零差异。**每个方块都掉落自身、每个方块都有物品**，因此这个模组里没有任何东西会因破坏而永久损失。这在本批中比应有的更罕见。

**107 张贴图产出 1016 个模型。** 这个比例正是材料族/调色板设计的意义：每种颜色一张瓷砖贴图，在六种形状间复用。

## 本地化是完整的

| 文件 | 键数 |
|:---|---:|
| `en_us.json` | **556** |
| `zh_cn.json` | **556** |

**两份文件恰好都是 556 键。** 规格里每个颜色与材料族都同时带中文与英文显示名（`"小方砖", "Small Tile"`），这正是键数相等而非某一语言落后的原因。这是本批本地化最好的模组之一。

## 刻意缺席的东西

**没有配方。** 模组里任何位置都不存在 `recipe/` 目录。全部 275 个方块只能创造分页或 `/give`。见[获取开始](01_getting_started)。

**没有配置。** `Config.java` 存在，但声明**零个选项**且**从未被注册**——没有 `registerConfig` 调用。`config/` 下不会出现任何东西。模组没有任何可调项，对一套纯建筑方块而言这是合理选择而非疏漏。

**没有命令、没有方块实体、没有菜单、没有实体、除方块默认外没有音效。**

**没有依赖。** `neoforge.mods.toml` 只声明 `neoforge` 与 `minecraft`——真正独立，与本批多数模组不同。
