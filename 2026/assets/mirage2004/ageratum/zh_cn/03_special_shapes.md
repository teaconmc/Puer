# 特殊形状

275 个方块里绝大多数是方块、台阶、楼梯与墙。少数需要额外工作，而那些正是值得了解的。

## 斜坡与三角墙

有两种形状是模组自己的，且**每个表面材料族都提供**：

| 形状 | 是什么 |
|:---|:---|
| `slope` | 斜面坡道 |
| `triangle_wall` | 三角形山墙 / 填充板 |

原版都没有，因此各需一套**自定义模型加载器**。模组随包两套完整的加载器栈——`SlopeGeometry` / `SlopeModelLoader` / `SlopeUnbakedModel`，以及对应的 `TriangleWall*` 三件——这正是它们在每个朝向都能正确渲染、而不必用楼梯去近似的原因。

实际用途：与你的墙同族的 `slope` 能给你**同一材料的坡屋顶或倒角转角**，而这通常正是「只用方块堆出来的立面看着不对」的原因。

## 带手工编写碰撞的方块

有 15 个方块的碰撞形状写在一套盒子 DSL 里，并被旋转到四个水平朝向。源码注释描述为：*「来自 `collision` 盒串 DSL 的数据驱动碰撞形状，按方块 ID 索引；每个值都是以北向编写的形状，旋转到四个水平朝向。」*

| 方块 | 碰撞盒（单位：十六分之一） | 读起来是 |
|:---|:---|:---|
| `concrete_utility_pole_gray_pole` | `6,0,6 → 10,16,10` | 4×4 的柱，满高、居中 |
| `power_line_gray_wire` / `power_line_black_wire` | `6,6,0 → 10,10,16` | 4×4 的横杆，穿过整格 |
| `framed_window_1/2/3_white_clear_pane` 与 `_black_clear_pane` | `0,0,7 → 16,16,9` | 2/16 厚的窗格，**居中** |
| `prefab_window_balcony_*_balcony_left` | `1,0,1 → 16,16,3` | 浅阳台，偏向一侧 |
| `prefab_window_balcony_*_balcony_right` | `0,0,1 → 15,16,3` | 上者的镜像 |

对建造有三点影响：

**框窗窗格是居中的，不与墙面齐平。** 位于 `z = 7..9`，窗格坐在方块正中，因此一格厚墙上的窗户两面都有凹进。这对「砌体洞口里的真实窗户」是正确的——但如果你预期它与某一面齐平，那就是它看起来内凹的原因。

**阳台是左右成对的。** `_balcony_left` 占 `x = 1..16`，`_balcony_right` 占 `x = 0..15`。**它们是要并排放置的镜像两半**；只放一个会在一侧留下 1/16 的缝。请两个都放。

**电线每格只沿一个方向。** `power_line_*_wire` 是沿单一水平轴的横杆，形状随朝向旋转，因此电线走向的转角需要两个朝向不同的方块，而不是一个专门的转角件。

## 电线杆是 4×4 且满高

`concrete_utility_pole_gray_pole` 是 `6,0,6 → 10,16,10` 的柱——比栅栏细、满格高、居中。堆叠起来即成连续杆；规格中的 `pole_arm` 与 `pole_base` 材料族提供了横担与基座件来把它补完整。

## 每个特殊方块都吃朝向

以上全部按 `Direction` 索引并以**北向**编写后旋转。这些方块继承 `AbstractHorizontalShapeBlock` / `FacingSpecialBlock`，因此**它们的朝向取自你放置的方式**——而碰撞跟随外观。若阳台或电线的碰撞看起来位置不对，先检查朝向再怀疑是 bug。
