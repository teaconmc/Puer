# 标签与建筑用法

## 通用（`c:`）标签

模组把所有内容都放进共享的 `c:` 标签命名空间，因此遵循标准宝石 / 矿石 / 储存方块约定的其他模组会自动识别这些方块。

### 方块标签

| 标签 | 成员 |
|:---|:---|
| `c:clusters` | 三种晶簇方块 |
| `c:clusters/topaz` · `c:clusters/ruby` · `c:clusters/sapphire` | 对应的晶簇 |
| `c:ores/gems` | 三种矿石方块 |
| `c:ores/topaz` · `c:ores/ruby` · `c:ores/sapphire` | 对应的矿石 |
| `c:storage_blocks` | 六种储存方块 |
| `c:storage_blocks/topaz` · `c:storage_blocks/ruby` · `c:storage_blocks/sapphire` | 该颜色的粗**与**抛光储存方块 |

### 物品标签

| 标签 | 成员 |
|:---|:---|
| `c:gems` | 六个粗宝石与抛光宝石 |
| `c:gems/topaz` · `c:gems/ruby` · `c:gems/sapphire` | 该颜色的粗宝石与抛光宝石 |
| `c:clusters` 与 `c:clusters/<颜色>` | 晶簇方块物品 |
| `c:ores/gems` 与 `c:ores/<颜色>` | 矿石方块物品 |
| `c:storage_blocks` 与 `c:storage_blocks/<颜色>` | 储存方块物品 |

请注意**原石没有任何物品标签**。`raw_topaz`、`raw_ruby` 与 `raw_sapphire` 不在 `c:gems` 中，也没有对应的 `c:raw_materials/*` 标签。如果需要让其他模组或数据包识别它们，必须自己补标签。

### 原版标签

| 标签 | 成员 |
|:---|:---|
| `minecraft:mineable/pickaxe` | 全部 24 个方块 |
| `minecraft:slabs`（方块） | 六个台阶**以及六个楼梯** |
| `minecraft:slabs`（物品） | 六个台阶物品**以及六个楼梯物品** |

楼梯被放进台阶标签而不是楼梯标签，是当前源码的实际产物：楼梯构建器传入的就是台阶标签。生成资源中完全没有 `minecraft:stairs` 标签输出。实际影响是：任何读取台阶标签的东西（其他模组的配方、数据包，或按标签过滤的工具）都会把这些楼梯当作台阶，而任何读取楼梯标签的东西看不到它们。方块本身在世界中仍然表现为普通楼梯。

## 用两种表面处理建造

每种颜色都给出两种视觉上区分明显的材质，而且两套都是完整的：

| 表面处理 | 外观 | 方块 |
|:---|:---|:---|
| 粗（unpolished） | 较粗糙、颜色更暗的宝石表面 | 方块、楼梯、台阶 |
| 抛光（polished） | 光滑、饱和度更高的宝石表面 | 方块、楼梯、台阶 |

由于楼梯与台阶复用各自表面处理的储存方块贴图，粗宝石楼梯与粗宝石方块完全对齐。把同一颜色的两种表面处理混用，是不离开配色又能拉开对比最省事的做法——例如用抛光方块砌墙，再用粗宝石台阶做腰线或地面收边。

晶簇属于点缀而不是建筑方块。它们可以贴在支撑方块的六个面上并随机取一个旋转，因此只用一种方块也能让整片晶簇天花板或墙面显得不规则。黄玉晶簇较高，红宝石与蓝宝石晶簇较矮。

矿石方块同样可以当装饰用：它的模型是石头立方体外面包一层宝石色壳，看起来像矿脉而不是成品材料。

## 需要注意的事情

- **晶簇不会生长。** 没有注册任何母岩方块，你放下的晶簇就是那个位置唯一的晶簇。想搬走请用精准采集采集。
- **晶簇与矿石不会自然生成。** 详见 [01 上手与获取](01_getting_started.md)。
- **两个宝石转化步骤不能用数据包修改。** 它们是硬编码的物品行为，不是配方——详见 [02 宝石加工](02_gem_processing.md)。
- **楼梯与台阶是单向的。** 没有任何配方能把它们变回方块或宝石，因此按需切割即可。
- **资源包作者请注意：** 蓝宝石晶簇模型指向贴图 `colorful_crystals:block/sapphire_culster`，而磁盘上的文件名确实也拼作 `sapphire_culster.png`。模型能正常渲染，但重做贴图时必须使用这个拼错的名字。红宝石与黄玉晶簇使用的是预期的 `ruby_cluster` / `topaz_cluster` 拼写。
