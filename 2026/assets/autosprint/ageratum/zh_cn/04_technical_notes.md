# 技术说明

参考资料与已知问题，全部读取自当前源码。

## 注册表

模组只注册了一样东西：按键映射 `key.autosprint.auto_run`，位于按键分类 `autosprint:category` 之下。

**没有**任何物品、方块、方块实体、实体、菜单、配方、战利品表、成就、命令、创造分类、音效、粒子、网络载荷、数据附件或 mixin。一切都发生在单个客户端刻处理器中。

## 已知问题：语言文件放在了错误的命名空间

这是关于当前构建最重要的一点。

模组的翻译文件位于 `assets/autorun/lang/*.json`，但模组 ID 是 `autosprint`。Minecraft 按命名空间加载语言文件，因此**`autorun` 下的文件永远不会与本模组匹配**。实际后果是每个翻译键都回退为其原始形式：

| 你本应看到 | 你实际看到 |
|:---|:---|
| 按键控制中的按键名 | `key.autosprint.auto_run` |
| 按键分类标题 | `key.category.autosprint.category` |
| 配置界面标签 | `autosprint.configuration.autoSprint` 等 |
| 切换提示消息 | `autosprint.custom_message.on.3` 等 |

模组功能仍然正常——只有显示文本受影响。修复方法是把资源文件夹从 `autorun` 改名为 `autosprint`；文件内部的键本身已经是正确的。

模组提供了五种语言，且全部同等受影响：`en_us`、`zh_cn`、`zh_tw`、`zh_hk` 与 `lzh`（文言）。

## 输入处理读取物理按键

切换键本身使用常规的按键映射点击队列，因此遵守「仅游戏内」冲突上下文。但前进、后退与疾跑键是通过直接轮询操作系统窗口的原始按键状态检测的，而不是询问 Minecraft 该绑定是否激活。

由此产生两个后果：

- 对这三个键而言**界面焦点不被考虑**。它们的按下边沿读取自硬件状态，因此在界面打开时的行为可能与预期不同。
- **只有键盘绑定能被正确轮询。** 该查询按键码请求一个键盘按键。如果你把前进、后退或疾跑绑定到了鼠标按键，该码就是鼠标按键码，查询无法给出有意义的结果——因此 W 接管与疾跑切换快捷方式可能不响应。

如果自动行走似乎忽略了你的前进或疾跑键，请检查该动作是否绑定到了鼠标按键。

## 文档不一致之处

| 来源 | 声称 | 实际 |
|:---|:---|:---|
| README | 默认键是「Mouse-4」 | 代码绑定的是鼠标按键 5 |

## 元数据

| 字段 | 值 |
|:---|:---|
| 模组 ID | `autosprint`（gradle `mod_id` 与 `@Mod` 常量一致） |
| 版本 | `0.org-itk.0.1` — 不是标准语义化版本 |
| 许可证 | CC0 |
| 作者 | luoxueyasha |
| NeoForge 目标 | 26.1.2.55-beta |
| 依赖 | 仅 `neoforge` 与 `minecraft`，均为必需 |

模组元数据文件是构建模板，因此上表数值在构建时从 `gradle.properties` 替换得到。

请注意，两个依赖条目都声明为 `BOTH` 端，尽管模组本身是纯客户端的；由于模组主类已做客户端限定，这是无害的。

客户端初始化处理器会在启动时打印一条歌名日志——这是无害的彩蛋，不是错误。
