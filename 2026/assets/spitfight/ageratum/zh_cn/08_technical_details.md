# 技术细节

供服务器管理员、资源包作者以及需要与本模组集成的人参考。

## 注册表

| 类别 | ID | 说明 |
|:---|:---|:---|
| 实体类型 | `spitfight:spit` | 继承原版羊驼唾沫；`MISC` 分类，0.3 × 0.3 碰撞箱，免火 |
| 数据附件 | `spitfight:player_spit_data` | 可序列化，并同步给所属客户端 |
| 按键绑定 | `key.spitfight.spit` | 默认 `Z`，玩法分类 |
| GUI 图层 | `spitfight:spit_bar` | 注册在原版经验等级图层之上 |
| GUI 图层 | `spitfight:to_face_effect` | 注册在原版聊天图层之下 |

模组**没有**自己的物品、方块、方块实体、菜单、配方、战利品表、成就、命令、创造分类、音效或粒子。唾沫复用原版羊驼唾沫渲染器。

## 数据包贡献

模组只附带一个数据文件：把 `spitfight:spit` 加入原版 `minecraft:redirectable_projectile` 实体类型标签（`replace: false`）。

## 网络载荷

| 方向 | ID | 用途 |
|:---|:---|:---|
| 客户端 → 服务端 | `spitfight:c2s/player_charge` | 玩家开始蓄力 |
| 客户端 → 服务端 | `spitfight:c2s/spit` | 松开：携带蓄力计数与 50 格瞄准点 |
| 客户端 → 服务端 | `spitfight:c2s/drink` | 玩家从水方块喝水 |
| 服务端 → 客户端 | `spitfight:s2c/to_face` | 命中脸部；携带强度用于覆盖层 |
| 服务端 → 客户端 | `spitfight:s2c/range` | 推送四条生效范围边界；登录时发送 |

五者均注册在协议版本 `"1"` 之下。

## 客户端 / 服务端分工

口水由服务端主导：服务端持有该数值、运行恢复、应用聊天消耗，并决定是否允许吐唾沫。客户端仅保留一份同步副本用于绘制 HUD。

有两项行为由客户端驱动，值得了解：

- **聊天阻止在客户端。** 取消发出的聊天发生在客户端事件中。服务端对任何它确实收到的消息仍会扣 1 点口水。
- **喝水与蓄力由客户端发起。** 客户端检测输入与水目标，然后请求服务端执行。

## 持久化

只有 `spitCount` 会写入玩家数据。蓄力状态是瞬态的，会自然重置。弹射物会保存其携带的效果列表与强度，因此从磁盘加载的唾沫会保留其载荷。

## 实现说明

- **mixin 配置为空。** `spitfight.mixins.json` 在模组元数据中声明且标记为必需，兼容级别为 `JAVA_25`，但其 `mixins` 列表没有任何条目——模组当前没有修补任何内容。
- **命中脸部的角度判定不寻常。** 它先把两个头部偏航角的绝对和与各自的偏航角比较，再决定采用哪种比较方式，因此 140 度阈值并非对所有朝向组合都对称求值。请把命中脸部视为近似判定，而非精确的几何规则。
- **客户端与服务端分别跟踪蓄力。** 客户端统计输入刻（用于唾沫强度），服务端统计自己的蓄力刻（用于窒息计时）。这是两个独立计数器，因此严重延迟会让你消耗的强度与承受的窒息产生偏差。
- **蓄力会抑制恢复**，因为 tick 方法进入了蓄力分支，永远不会到达恢复分支。
- 命中代码中残留着一段**被注释掉的站立人形判定**，表明有一个未完成的姿态分支。它没有运行时效果。
- **唾沫免火**，且作为 `MISC` 实体，不受生物上限或生成规则影响。
