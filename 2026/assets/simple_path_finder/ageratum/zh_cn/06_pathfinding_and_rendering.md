# 寻路与渲染

## 服务端寻路

`server_side_pathfinding` 默认为 `true`。在该模式下：

- 导航数据保存在服务端的每维度 `simple_path_finder:simple_path_finder_data` 存档数据中。
- 客户端发送 `simple_path_finder:pathfinding_request`；服务端执行搜索并发送 `simple_path_finder:pathfinding_result`。
- 服务端队列全局最多同时执行 2 个请求、排队 8 个请求，且每个玩家最多 1 个排队请求。
- 服务端每隔几 tick 在快捷栏上方显示进度，任务完成时发送完成消息。
- 默认不会同步完整导航数据。玩家持有导航或调试导航棒时，服务端会发送玩家已接收的区块、新可见区块，并每 8 tick 发送一次当前区块。

## 客户端寻路

当 `server_side_pathfinding` 设为 `false` 时：

- 服务端会在登录时发送完整每维度导航数据，在图形编辑后发送完整更新，并发送增量 `simple_path_finder:sync_single_chunk` 更新。
- 客户端在 Minecraft 后台执行器上异步搜索，并且同时只允许一个客户端任务。
- 客户端在 `ClientNavDataManager` 中按维度保存导航数据；没有数据时产生 `simple_path_finder.nav.no_data`。

两种模式都会在客户端渲染结果，因此即使使用服务端寻路，路径线仍需要客户端模组。

## 搜索行为

当前 `NavPathFinder` 先执行连通性检查，再执行启发权重为 `110%` 的 A* 搜索。它根据已存步行图层与导航链接构建边，目标曼哈顿距离不超过 1 格时视为成功，并为高度变化与方向变化增加额外成本。当前实现中链接类型不会改变成本。如果起点或终点没有直接落在图层上，搜索会把位置调整一格。

## 路径线

成功结果保存在客户端，并作为穿过路径点的渐变线渲染。启用客户端 `smooth_path` 选项（默认 `true`）时，路径线使用三次 Chaikin 平滑迭代；关闭时改为渲染直线段。

以下情况会清除结果：

- 玩家到达目标（曼哈顿距离不超过 1 格）。
- 执行 `/spf nav clear`。
- 玩家断开连接或切换维度。

模组不会移动玩家，只显示计算出的路径位置。

## 客户端命令

| 命令 | 行为 |
|:---|:---|
| `/spf nav <x> <y> <z>` | 向指定方块位置发起客户端寻路。 |
| `/spf nav clear` | 清除当前渲染路径。 |
| `/spf navserver <x> <y> <z>` | 发送服务端寻路请求。 |
| `/nav ...` | `/spf nav ...` 的别名。 |
| `/navserver ...` | `/spf navserver ...` 的别名。 |

这些是客户端命令，不是管理命令。如果服务端队列已满或玩家已有排队请求，服务端会返回 `simple_path_finder.nav.already_pathfinding`。

## 调试导航棒

主手持有 `simple_path_finder:debug_nav` 且本地有导航数据时，会显示导航图。持有导航物品时也会启用同样的调试渲染。堆叠数量控制调试视图：

| 数量 | 调试视图 |
|:---|:---|
| 1-2 | 半径为 3（数量会向上钳制）。 |
| 3-16 | 曼哈顿半径等于数量。 |
| 17-48 | 半径为 16，只显示图层 `数量 - 32`。 |
| 49-63 | 半径为 16，显示所有图层。 |
| 63 | 同时重新运行到同一目标的当前客户端寻路。 |
| 64 | 禁用调试渲染。 |

调试视图会绘制彩色图层方块、可步行边的白色方块（阻挡边为红色），以及黄色到蓝色的导航链接箭头。正图层的图层颜色以绿色循环，负图层以蓝色循环。
