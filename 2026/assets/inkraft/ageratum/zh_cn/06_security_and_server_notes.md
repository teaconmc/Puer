# 安全与服务器说明

Inkraft 的**命令**权限做得很好。它的**故事**权限是另一回事，而这个区别正是服主在安装前必须理解的东西。

## 信任边界在数据包，不在命令树

`/inkraft` 命令树的门禁是恰当的：开始一个故事需要管理员权限，介入另一名玩家的故事也需要管理员权限。这保护的是**命令层面**。

但它并不约束故事本身运行起来之后能做什么。故事是随数据包分发的已编译 ink，而它可以调用[故事函数](04_story_functions)中列出的命令函数：

| 故事函数 | 命令来源的权限 |
|:---|:---|
| `runCommand` | 触发玩家自己的权限等级 |
| `runUnlimitedCommand` | **所有者等级（4）** |
| `runSilentUnlimitedCommand` | **所有者等级（4）**，且输出被抑制 |
| `runServerCommand` | 服务器自身的命令来源 |

::: danger
`runUnlimitedCommand` 与 `runSilentUnlimitedCommand` 用 **`LevelBasedPermissionSet.OWNER`** 构造命令来源 —— 权限等级 4，也就是最高级。它**不是**从玩家推导的，**也不是**从启动该故事的管理员推导的。因此任何随包提供故事的数据包在你的服务器上都拥有不受限制的命令执行能力，而静默变体还会额外抑制命令输出，使聊天栏里不会出现任何它运行过的痕迹。

实际后果是：**安装一个包含 Inkraft 故事的数据包，等同于授予该数据包作者等级 4 的命令权限。** 请把第三方故事数据包完全按照「装满 `function` 文件的数据包」来对待 —— 因为它严格地比后者更强。
:::

函数命名是诚实的 —— 一个叫 `runUnlimitedCommand` 的函数并没有伪装成安全的东西 —— 但如果你只审计命令树并得出「开始故事需要管理员，所以没问题」的结论，这处提权就很容易被漏掉。

### 为什么 `runCommand` 是安全的那个

`runCommand` 用 `ServerPlayer::createCommandSourceStack` 从玩家构造来源，因此它继承那名玩家的真实权限等级。**只使用 `runCommand` 的故事无法做到玩家自己打不出来的事。** 如果你在为公开服务器编写故事，只用 `runCommand`，你就始终留在玩家自身的权限范围内。

## 审查一个并非你自己写的故事

故事以已编译的 `.ink.json` 形式到达，那是机器生成的、读起来很不舒服，但**函数名会以纯字符串形式存活过编译**。一项实用的预检是在编译后的 JSON 里搜索这四个调用名：

| 搜索 | 出现即意味着 |
|:---|:---|
| `runUnlimitedCommand` | 等级 4 执行 |
| `runSilentUnlimitedCommand` | 等级 4 执行且无可见输出 |
| `runServerCommand` | 以服务器控制台身份执行 |
| `runCommand` | 以玩家自身等级执行 —— 可接受的那个 |

如果你服务器的经济依赖计分板或存储，也请一并搜索 `giveItem` 以及计分板与存储相关函数，因为它们会写入共享的世界状态。

## Inkraft 不添加的东西

为完整起见，也因为这显著缩小了审计面：

- **没有自定义网络包。** 它没有自己的客户端到服务端载荷可被伪造；玩家通过普通命令系统驱动故事，这意味着常规的命令权限与日志对该路径同样有效。
- **没有配置文件。** 既无服务端也无客户端配置，因此**不存在关闭那些无限权限命令函数的开关**。若你不希望它们可用，就必须控制安装了哪些数据包。
- **没有物品、方块或实体**，因此没有自己的世界交互面。

::: warning
由于没有配置，等级 4 的故事函数**无法被禁用**。数据包审查是唯一可用的管控手段。在运维者与数据包作者并非同一批人的服务器上，这是一个需要在安装**之前**而不是之后做出的策略决定。
:::

## 重载与内容的在线变更

`/reload` 会完全替换故事注册表 —— 监听器清空它并从当前加载的包重新填充。有两个后果值得预先规划：

- 从数据包中移除的故事在重载后是真的消失了，不会被缓存。
- 处于故事中途的玩家会保留其存档位置，而该位置对于一个被改写过的故事可能已经不再有效。`/inkraft reset <player>` 是预期的补救手段。

加载期间的读取失败以堆栈跟踪的形式打印到标准输出，而不是在游戏内呈现。因此更改故事内容之后，请查看控制台，而不要在 `/inkraft start` 静默失败时就断定是 ID 拼错了。

## 建议的部署姿态

| 情形 | 建议 |
|:---|:---|
| 单人游戏，或你自己编写的地图 | 自由使用，包括那些无限权限函数 |
| 你掌控每一个数据包的服务器 | 可以；把故事数据包纳入与 `function` 相同的审查流程 |
| 接受第三方故事包的服务器 | 先逐包审计那三个提权函数，否则不要安装 Inkraft |
| 内容不可信的公开服务器 | 不要安装 |

以上没有一条是缺陷报告 —— 那处提权是刻意的，且函数命名也如实反映了它。这里陈述的是**信任边界实际位于何处**，而它比命令权限所暗示的位置还要往外一层。
