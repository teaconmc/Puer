# 快速上手

Inkraft 是一个故事引擎。你在游戏里实际看到的一切都来自数据包，而不是模组 jar——**它本身不添加任何物品、方块或你会注意到的命令**。

## 这是给谁的

两类完全不同的人群，值得先分清自己是哪类：

**玩家。** 你会通过使用 Inkraft 的地图或整合包接触到它。没有任何东西需要配置；你玩的是它随包的故事。你可能见到的两条命令是 `/inkraft start`（管理员）与 `/inkraft next`（所有人）。

**地图与整合包作者。** 这才是真正的受众。你用 **Ink** 脚本语言写故事、把它编译成 JSON、再装进数据包发布。见[故事与数据包](02_stories_and_datapacks)。

## 让一件事发生

1. 用 ink 写一个故事。
2. **把它编译**成 `.ink.json` —— Inkraft 加载编译后的 JSON，而不是 `.ink` 源文件。见[故事与数据包](02_stories_and_datapacks)。
3. 放到数据包的 `data/<你的命名空间>/inkraft_story/<名字>.ink.json`。
4. `/reload`。
5. `/inkraft start <你的命名空间>:<名字>` —— 这一步需要管理员权限。
6. 玩家用 `/inkraft next` 推进剧情，这**不需要**管理员权限。

## 两个平台，一处重要差异

Inkraft 同时运行在 Fabric 与 NeoForge 上，由同一份共享代码构建。

::: warning
**两个平台处理权限的方式不同。**

在 NeoForge 上，命令权限是真实的权限节点，权限插件可以调整它们。在 Fabric 上，它们是固定的原版权限等级。

因此一条在 NeoForge 上玩家可用的故事命令，在 Fabric 上可能只有管理员能用，反过来也可能。如果你的地图依赖「谁能触发什么」，请在你要发布的那个平台上测试。
:::

## ⚠️ 收录进整合包前请先询问

::: danger
**这里的许可状况确实不明朗，所以先拿到作者的准话。**

三份不同的许可声明同时存在：

- 喂给游戏内模组列表的设置写着 **PolyForm Shield 1.0.0**
- 仓库里另一份文件附带*另一个*许可文本（PolyForm NonCommercial）
- 而最朴素的 `LICENSE` 文件本身写着**「保留所有权利」**

三者中最严格的也是最有权威的那份。**在作者另有表态之前，请把 Inkraft 当作需要许可的模组**，而不要单独信任其中任何一份声明。
:::

## 小结

| 问题 | 答案 |
|:---|:---|
| 它自己添加了什么？ | **什么都没有** —— 它是引擎 |
| 给谁用的？ | 地图与整合包作者 |
| 玩家怎么交互？ | `/inkraft next` |
| 谁能开始一个故事？ | 管理员（`/inkraft start`） |
| 平台 | Fabric + NeoForge，权限行为不同 |
| 整合包使用 | **请询问作者** |
