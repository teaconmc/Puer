# 变量与存储

故事变量逐玩家持久化、能跨重启存活，且带类型。正是这三者的组合，让 ink 故事得以充当长期运行的任务状态，而不只是一次性的对话。

## 值类型

墨迹工艺把 ink 值包装进自己的类型体系，以便序列化：

| 类型 | 承载 |
|:---|:---|
| `IntStoryValue` | 整数 |
| `FloatStoryValue` | 浮点数 |
| `BoolStoryValue` | 布尔值 |
| `StringStoryValue` | 字符串 |
| `ArrayStoryValue` | 有序列表 |
| `MapStoryValue` | 键值映射 |
| `JsonStoryValue` | 任意 JSON |
| `InkListStoryValue` | ink 列表 —— ink 自有的类集合类型 |
| `StringifyStoryValue` | 已渲染成文本的值 |

每个值都带一个序列化类型标记，因此「由映射组成的数组」能在存档与重载之间保持结构往返，而不会塌缩成字符串。

::: info
`InkListStoryValue` 之所以存在，是因为 ink 列表不是普通数组 —— 它们是带有自身语义的有序枚举。把它保留为独立类型，意味着故事的 ink 列表在服务器重启后与重启前行为一致，而普通数组无法保证这一点。
:::

## 逐玩家持久化

每位玩家有自己的墨迹工艺玩家数据，保存其当前故事位置与变量。存储形式是一条**已存变量**记录，同时携带值与其类型标记。

这是逐玩家的，不是逐世界也不是全局。两位玩家运行同一个故事拥有完全独立的变量集合，因此一位玩家发现的谜题答案不会泄漏到另一位玩家的进程中 —— 与那些维护单张共享变量表的引擎型模组正好相反。

## 查看与编辑

`/variables` 是维护接口，其每个分支都需要管理员权限：

| 命令 | 效果 |
|:---|:---|
| `/variables get <name>` | 打印某变量的值 |
| `/variables set <name> <value>` | 覆写某变量 |
| `/variables unset <name>` | 删除某变量 |

每个都接受一个尾随的玩家参数以指向他人，同样受管理员权限限制。值是贪婪字符串参数，因此空格无需加引号。

这是修复卡住的任务的受支持方式：读出标记、改正它，让玩家继续。这也正是你自己的故事里变量名值得加类命名空间前缀的原因 —— 运维者脱离上下文读到 `stage` 无法判断它属于哪个故事，而 `myquest_stage` 自带说明。

## 脚本侧访问

在故事内部，同一份状态可通过[故事函数](04_story_functions)中描述的变量函数访问：`setVariable`、`getVariable`、`hasVariable`、`unsetVariable` 与 `clearVariables`。

有两项相邻设施值得与故事变量区分开：

- **计分板函数**读写原版计分板目标，那是对其他所有数据包与命令都可见的世界状态。
- **存储函数**读写原版命令存储，同样是共享的世界状态。

因此故事有三个层级可用：私有的逐玩家变量、共享的计分板值、共享的命令存储。故事记账用第一种，只有当你确实希望其他系统看到该值时才用后两种。

::: warning
`clearVariables` 会移除该玩家**全部**故事变量，而不只是你的故事创建的那些。若装了多个故事、而它们都把标记放在同一张逐玩家表里，一个故事调用 `clearVariables` 会连带清掉其他故事的进度。请优先对具体名称使用 `unsetVariable`。
:::

## 重置

`/inkraft reset` 清空一位玩家的故事状态，即便用于自己也需要管理员权限。当某个故事被不兼容地改写、旧的存档位置不再有意义时使用它 —— 重载会替换故事文本，但不会迁移正站在旧版本中间的玩家。
