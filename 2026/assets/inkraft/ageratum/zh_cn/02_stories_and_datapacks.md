# 故事与数据包

故事是数据包内容。墨迹工艺的重载监听器扫描每一个已加载的数据包，收集找到的故事，并按标识符保存在内存中。

## 故事放在哪里

| 属性 | 值 |
|:---|:---|
| 目录 | `inkraft_story` |
| 文件后缀 | **`.ink.json`** |
| 完整路径 | `data/<命名空间>/inkraft_story/<路径>.ink.json` |
| 得到的标识符 | `<命名空间>:<路径>` |
| 重载监听器 id | `inkraft:story_loader` |

标识符由文件位置推导，因此 `data/mystory/inkraft_story/prologue.ink.json` 会成为 `mystory:prologue`，而这正是你传给 `/inkraft start` 的参数。允许使用子目录，子目录会成为路径的一部分。

::: warning
后缀是 `.ink.json`，**不是** `.ink`。墨迹工艺加载的是由 inklecate 之类工具产出的**已编译** ink JSON；它自身不编译 ink 源码。把 `.ink` 文件丢进 `inkraft_story` 不会产生任何故事，也不会有任何报错 —— 该文件只是不匹配扫描模式，会像不存在一样被跳过。
:::

## 没有随包故事

模组 jar **不含任何可玩故事**。仓库里确实有九个 `.ink` 文件，但每一个都在 `docs/assets/` 或 `src/test/resources/sources/` 中 —— 文档示例与单元测试固件。没有一个在 `src/main/resources` 里，因此没有一个被打包为内容。

因此在全新安装上首次执行 `/inkraft start` 会找不到任何东西。对引擎型模组来说这是设计使然，但也确实意味着游戏内没有可供学习的随包演示；示例改放在项目的 `docs/` 目录里。

## 重载语义

监听器是 `PreparableReloadListener`，因此故事随普通的数据包重载刷新：

1. `prepare` 遍历每一个匹配资源，把每个文件读成字符串。
2. `apply` 先对故事注册表调用 **`clear()`，然后重新加入**它读到的全部内容。

这意味着一次重载是**完整替换**而非合并。删掉一个故事文件再重载，该故事确实会消失 —— 不会留下过期条目，这与另外若干数据驱动模组「已删条目会存活到重启」的行为正好相反。

::: info
由于 `apply` 会先清空注册表再重新填充，加载失败的数据包会让它的故事直接消失而不是留下旧版。这比另一种行为可取，但重载后仍应检查日志，而不要假定故事还在。
:::

### 读取失败是静默的

若某个故事文件无法读取，监听器会捕获异常并调用 `printStackTrace()`。堆栈跟踪进入标准输出而非模组的 logger，游戏内也不报告任何内容。因此从玩家角度看，格式错误或不可读的故事与不存在的故事完全一样。当 `/inkraft start` 毫无反应时，请检查服务器控制台输出，而不只是日志文件。

## 故事状态是逐玩家的

一个运行中的故事绑定到玩家，而不是世界。每位玩家有自己的墨迹工艺玩家数据，保存其当前故事、进度位置与变量；那些查看或推进故事的命令，除非管理员显式指名另一位玩家，否则都作用于「你自己的」故事。

## 战利品集成

墨迹工艺注册了一个战利品条件 `StoryCondition`，并随包一个 `predicate` 目录。这让战利品表能检查故事状态，于是一个箱子可以依据玩家进度掉落不同内容 —— 而故事本身无需执行任何命令。
