# MVEL 与占位符

ChatBox 内嵌了 MVEL 表达式语言。表达式驱动条件、`MVEL` 事件，以及对话正文中的内联替换。

## 文本中的两种语法

| 语法 | 含义 |
|:---|:---|
| `` `<<expression>>` `` | 求值一个 MVEL 表达式并插入结果 |
| `` `<player>` ``、`` `<target>` ``、`` `<target2>` `` …… | 插入某个参与者的名称 |

不带属性的参与者占位符默认解析为**名称** —— `` `<target>` `` 是 `` `<target.name>` `` 的简写。想取别的内容就补上属性，例如 `` `<player.uuid>` ``。无法解析的占位符会原样留在文本中，因此拼写错误会显示出来而不是消失。

内联 `` `<<…>>` `` 块先被求值，然后才处理参与者占位符，所以表达式本身也可以产出一个占位符。

## 目标

`target` 与 `targetN` 在求值前会被改写为 `targets` 数组的下标：`target` 与 `target1` 都表示 `targets[0]`，`target2` 表示 `targets[1]`，依此类推。该数组就是对话启动时传入的实体列表 —— 见[命令](02_commands)中 `/chatbox skip` 的目标参数。

## 可用变量

| 变量 | 含义 |
|:---|:---|
| `player` | 表达式为之求值的玩家 |
| `targets` | 本次对话的目标实体 |
| `gameTime` | 当前世界游戏时间 |
| `random` | 一个共享随机源 |
| `_this` | 事件所属的组件（若存在） |
| `chatbox`、`chatboxScreen`、`chatboxTick` | 仅客户端：访问运行中对话的辅助对象 |

`Math` 已被导入，因此常规算术辅助函数可用。

## 方法

以 `主体.方法(参数)` 调用：

| 方法 | 主体 | 用途 |
|:---|:---|:---|
| `hasItem(id)` | 玩家 | 物品栏是否持有该物品 |
| `getItemCount(id)` | 玩家 | 该物品的总数量 |
| `getItemBySlot(slot)` | 生物或玩家 | 盔甲槽名称，或物品栏下标对应的物品 |
| `getScore(objective)` | 玩家 | 计分板数值；目标不存在时为 null |
| `hasTag(tag)` | 实体 | 实体是否携带该标签 |
| `tell(message[, actionBar])` | 玩家 | 发送消息；`true` 显示在快捷栏上方 |
| `getEnchantLevel(id)` | 物品堆 | 该物品堆上的附魔等级 |
| `enchant(id, level)` | 物品堆 | 施加附魔 |
| `hasAdvancement(id)` | 玩家 | 该进度是否已完成 |

盔甲槽名称接受两种写法 —— `head`/`helmet`、`chest`/`chestplate`、`legs`/`leggings`、`feet`/`boots`。

## 属性

以 `主体.属性` 读取：

| 属性 | 主体 | 结果 |
|:---|:---|:---|
| `name` | 实体、物品、物品堆 | 显示名称 |
| `id` | 实体、物品、物品堆、方块、效果、组件 | 注册表标识符 |
| `uuid` | 实体 | UUID |
| `tags` | 实体 | 实体标签集合 |
| `foodLevel` | 玩家 | 饥饿值 |
| `offHandItem` | 生物 | 副手物品堆 |

## 变量辅助函数

| 函数 | 效果 |
|:---|:---|
| `setVar(name, value)` | 存储一个变量 |
| `setVarIfNoDef(name, value)` | 仅在尚未设置时存储 |
| `hasVar(name)` | 变量是否存在 |
| `removeVar(names…)` | 移除变量 |
| `executeCompEvt(type, value)` | 按类型触发一个组件事件 |

这是在一段对话中记住玩家选择的常规做法：首行用 `setVarIfNoDef` 初始化计数器，随玩家选择更新，再在后续条件中分支。随包演示的昵称与到访计数用的正是这个模式。

::: warning
变量存放在**一张共享表**中，既不区分玩家，也不区分对话。在服务器上，所有玩家的表达式读写的是同一批条目，而这张表在对话之间从不清空。请给键加命名空间前缀（例如用 `myquest_stage` 而不是 `stage`），绝不要假设某变量在开场时不存在，也不要在多人服务器上用变量保存逐玩家进度 —— 那应该交给计分板或进度。已编译的表达式同样全局缓存，且缓存超过 721 条时会被整体丢弃。
:::

## 求值发生在哪一侧

表达式默认在**客户端**运行。加 `server:` 前缀可把求值移到服务端，代价是一次网络往返。当表达式必须读取权威状态或改变世界时才需要服务端求值；表现层逻辑用客户端即可。

`/chatbox mvelTest <expression> <onServer>` 可在任一侧求值并打印结果，这是发布前检查表达式的受支持方式。

::: info
抛出异常的表达式会被吞掉并返回 `null`，而不是中断对话。这让一行出错不至于毁掉整个场景，但也意味着「静默出错的条件」看起来与「条件为假」完全一样。当某处始终不触发时，先用 `mvelTest` 测一遍。
:::
