# 网络与服务器注意事项

## 数据包

| 数据包 | 方向 | 内容 |
|:---|:---|:---|
| `chatbox:simple_payload` | 双向 | 一个名称与一个字符串值，分派到处理器表 |
| `chatbox:execute_click_event` | 客户端 → 服务端 | 一个事件类型 id 与一个值 |
| `chatbox:chat_box_data_to_client` | 服务端 → 客户端 | 主题或对话文档，切分为字符串块 |
| `chatbox:sync_entity_data` | 服务端 → 客户端 | 对话目标实体，以网络 id 为键的 NBT |

`chatbox:simple_payload` 承载了大部分流量。服务端到客户端的名称涵盖启动对话、打开对话框、切换主题、推进、自动播放、界面模式、改写对话框、增删设置清空选项以及 MVEL 测试结果。客户端到服务端的名称为 `request_sync`、`skip_chat_c2s` 与 `test_condition`。

对话与主题文档以分块字符串推送给客户端并在客户端重新拼接，这正是客户端能渲染自己本地没有文件的对话的原因。

## 服务端信任模型

本节正是首页那条警告的由来。它描述的是当前代码的实际行为，不是假设。

::: danger
有三条客户端到服务端的路径会接收客户端提供的字符串并据此行动，且**不做权限检查，也不校验该字符串是否属于一段真实、正在播放的对话**：

1. **`chatbox:execute_click_event`** 在注册表中查找事件类型并执行其服务端一半。内置 `COMMAND` 类型的服务端一半会把该值**以游戏管理员权限执行为命令并抑制输出**。这次查找还没有做 `null` 检查，因此未注册的类型 id 会让处理器出错而不是被拒绝。
2. **`simple_payload` / `test_condition`** 把其字符串**在服务端**作为 MVEL 求值，并把发送方玩家绑定为 `player`。
3. **`simple_payload` / `skip_chat_c2s`** 直接用客户端提供的标识符、组与下标索引已加载的对话表，并执行该行的 `command` —— 绕过触发次数闸门与任何 `criteria` 限制。缺失条目与非数字下标在使用前都没有校验。

在装有 ChatBox 的服务器上，其净效果是：任何已连接的客户端都能引发 2 级命令执行与服务端表达式求值，与它自身的权限无关。`/chatbox` 命令根受权限限制**并不能**保护这些路径，因为它们根本不经过命令系统。
:::

### 关于「safe」变换

送入 MVEL 的输入在编译前会经过一个名为 `safeTransform` 的函数。尽管名字如此，它是一个**语法改写器，不是沙箱**：它把 `主体.方法(参数)` 改写为分派调用、把 `主体.属性` 改写为属性查找，同时小心跳过引号内区域。它不做任何白名单、不阻止任何东西，并且明确保留 `new` 关键字。请不要把这个名字当作「不受信表达式已被围堵」的证据。

### 建议的处理方式

- 把 ChatBox 视为**受信客户端内容**：适用于单人、正在测试的私有地图，或玩家可信的服务器。
- 在公开或半公开服务器上，请在它前面加一层数据包过滤，否则就不要安装。普通权限插件帮不上忙，因为这里没有任何一项是命令。
- 对话与主题文件应与函数、命令方块受同等审阅纪律约束。数据包某一行的 `command` 按设计就是以 2 级权限执行的。
- 不要把 ChatBox 当作权限边界。它是表现系统；任何看似被它限制住的东西都能用别的途径达成。

## 重载与同步流程

1. `/reload` 在服务端重新读取两个目录。对话解析会重建组表与默认触发次数。
2. 进度判据被重新解析 —— 服务器启动时一次，数据包同步时再一次。
3. 文档被推送给客户端，使其渲染器与服务端数据一致。
4. 对话目标以实体 NBT 单独同步，或按请求，或在对话启动时。

由于重载会重建默认触发次数表，它同时也会重置[触发与持久化](08_triggers_and_persistence)中所述的偏移问题。

## 哪些内容不存在

为完整起见：模组不包含以下任何内容 —— 服务端配置、通用配置、权限节点、任何数据包的频率限制，以及对对话标识符、组名或行下标的数据包级校验。
