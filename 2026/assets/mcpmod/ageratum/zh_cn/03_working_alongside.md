# 与游戏并行工作

从外部工具驱动 Minecraft 有一个现实问题：你一 `Alt+Tab` 切到 IDE，客户端就失去焦点并打开暂停界面。于是代理下一张截图拍到的是暂停菜单，而不是你想测的东西。

模组用一个**释放鼠标**控件解决它，并在两处提供入口。

## 两种释放鼠标的方式

| 位置 | 操作 |
|:---|:---|
| 暂停界面 | 按 `Esc`，然后点击 MCP 覆盖层的**释放鼠标**按钮 |
| 3D 视图中 | 点击**右上角**的 MCP 覆盖层按钮 |

任一方式都会把光标从游戏中脱离。之后你可以自由切换窗口——客户端**不会**在失去焦点时自动暂停，MCP 连接保持存活。

## 为什么这对工作流很重要

没有它，设计意图中的循环会崩掉：

1. 你让代理测试某件事。
2. 你切到 AI 工具去读它的输出。
3. 游戏暂停。
4. 从这一刻起代理看到的全是暂停菜单。

释放鼠标后，第 2–4 步就合并成「你读输出时游戏继续跑」。这是工具「可用」与「只是个新奇玩意」之间的差别。

::: tip
请在开始一段长时间代理运行**之前**释放鼠标，而不是之后。如果代理正处于流程中途而游戏暂停了，它接下来做的一切都会被按暂停界面来解读——取决于它点在哪，可能会落到「选项」里，或者一路退回标题画面。
:::

## 暂停界面那个入口是有理由的

请注意暂停界面按钮的描述是让你「自由切换窗口而**不会再次触发暂停界面**」。这个措辞是精确的：你已经按 `Esc` 暂停过了，而点击释放是为了阻止它在此后每次失焦时*再次*发生。3D 视图里那个覆盖层按钮，则是你压根没暂停时用的版本。

## 覆盖层不是什么

覆盖层只有这一个控件。它不是状态面板、不是日志视图、也不是配置界面——那些都在 `/debug` 网页上（见[获取开始](01_getting_started)）。把游戏内的界面控制到只有一个按钮，与模组不添加任何注册表内容是一致的：它试图对游戏本身保持隐形。
