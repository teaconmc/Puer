# 安全与部署

这一页之所以存在，是因为「文档暗示的情况」与「代码实际的行为」之间的差距大到必须说明。

## 三个事实，均已在源码中核实

**1. 服务器绑定在全部网络接口，而不是 localhost。**

```java
server = HttpServer.create(new InetSocketAddress("0.0.0.0", configuredPort), 0);
```

主绑定与端口回退绑定都用 `0.0.0.0`。控制台消息与 README 都把你指向 `http://127.0.0.1:{port}/debug`，很容易读成「这是仅限本机的服务」——但那是**你访问的地址**，不是它**监听的接口**。**凡能路由到你机器该端口的东西都能连上。**

**2. 没有认证。**

没有 token、没有密钥、不检查 `Authorization` 头、没有来源白名单。每个端点对先连上的任何人开放。

**3. 跨域请求被显式允许来自任何地方。**

```java
exchange.getResponseHeaders().set("Access-Control-Allow-Origin", "*");
```

在三个不同处理器中设置。这意味着**你在浏览器里打开的某个网页**可以向 `localhost` 上的模组发请求，而浏览器不会阻止它读取响应。

## 三者叠加的后果

端点清单里有 `/api/cmd`，它前置了 [AI 能做什么](02_capabilities) 中那套完整动作面——点击、按键、视角控制，以及 `executeCommand`。

::: danger
**模组运行时，对你 Minecraft 客户端的完整控制权可被以下各方取得：**

- 同一局域网、咖啡馆 Wi-Fi 或酒店网络上的任何其他设备；
- 你机器上运行的任何其他程序，包括其他用户；
- **你恰好打开着的任何网站**，通过那条通配 CORS 策略。

「控制」的含义是：执行你玩家能执行的任何命令、按任意键、点击任意位置、读取你的屏幕。在单人世界或你是 OP 的服务器上，「任何命令」包括 `/op`、`/ban` 与 `/stop`。
:::

这不是隐藏的 bug——它是一个为「可信单机工作流」而写的开发工具的自然形态。问题只在于：游戏内与控制台都**没有任何东西**告诉你暴露面是全网络的。

## 负责地部署

| 情形 | 该怎么做 |
|:---|:---|
| 你自己的开发机、可信网络 | 照原样用即可。这是设计意图中的场景。 |
| 笔记本在公共或共享 Wi-Fi 上 | **不要运行它。** 把模组从你外出时用的配置档里移除。 |
| 在不可信网络中确实需要它 | 用防火墙拦入站端口（封 9000–9876，或只封你用 `-Dmcp.port` 固定的那个）。 |
| 共享 / 多用户机器 | 把那个端口当作你游戏会话的 shell 来对待，因为它就是。 |
| 真实服务器或任何有其他玩家的地方 | **绝对不要。** 它是客户端开发工具。 |

两条无需改代码的实用加固：

- **固定端口**：用 `-Dmcp.port=XXXX` 或 `MC_MCP_PORT`。否则回退会从 9876 一路走到 9000，你无法有把握地只写一条防火墙规则。
- **用专门的启动器配置档**装这个模组，并把它排除在你日常游玩的配置档之外。

## 两点公平的缓解事实

- 模组是**客户端侧**的：它驱动你自己客户端的输入。它不在专用服务器上开端口，也不授予任何你玩家本来没有的能力。
- 失败在一个方向上是显式的：服务器启不动时控制台会有 `[MCP-MOD] HTTP server failed:`。但**有人连接时没有任何提示**——`/debug` 仪表板是唯一能看到连接的地方。

## 老实说一句

安装这个模组，等价于为你的游戏客户端在所有网络接口上开了一个无认证的远程控制端口。在开发机上这完全合理，在其他任何地方都很糟。而工具本身不会阻止你做其中任何一种。
