# 酒单

## 打开它

拿任何东西右键**吧台**。三件事会同时发生：你的酒单页码被重置为 `0`、菜单打开，同时方块还会对你手中物品触发一次使用动作。

菜单是分页的，而当前页码存放在**玩家身上的数据附件**里，而不是方块上——因此每位玩家各自翻页互不干扰，你在不同吧台之间走动时页码也会保留。三个网络载荷负责同步：一个同步列表内容、一个同步页码、一个同步发放给你的东西。

## 九个条目

价格以**绿宝石**计，每一项都是固定套装：

| 条目 | 价格 | 你得到 |
|:---|--:|:---|
| 橙汁 | **5** | 橙汁 |
| 高球 | **6** | 高球 |
| 威士忌 | **6** | 威士忌 |
| 黑星咖啡 | **6** | 黑星咖啡 |
| 大卫·马丁内斯 | **8** | 大卫·马丁内斯 |
| 黄油啤酒 | **10** | 黄油啤酒 |
| 巨峰葡萄酒 + 高脚杯 | **16** | 巨峰葡萄酒**瓶** + 高脚杯 |
| 香槟 + 香槟杯 | **16** | 香槟**瓶** + 香槟杯 |
| 《Dust To Dust》唱片 | **36** | 唱片 |

有三点值得据此规划：

- **两个 16 绿宝石的条目是套装，不是单杯。** 它们给你一瓶酒和一只空杯，由你自己倒。一瓶能倒好几杯，所以如果你打算不止喝一次，这两项才是划算的。
- **杯装成品不单卖。** `kyoho_wine_cup` 与 `champagne_cup` 从不出现在酒单上——拿到杯装成品的唯一途径就是从对应的瓶中倒出来。创造模式下可以直接取。
- **唱片是全模组最贵的东西**，36 绿宝石，也是酒单上唯一的非饮品。

## 酒单由 Java 定义，不是数据包

这是最重要的结构性事实。目录是**在代码中于 `ServerStartingEvent` 时构建的**：每次世界或服务器启动，映射表都会被清空并重新填入那九个硬编码条目。

由此产生的后果：

- **数据包改不了价格，也加不了酒。** 酒单没有任何 JSON，改文件没有用。
- **但别的模组可以改。** 构建完映射表后，模组会立刻在 NeoForge 事件总线上抛出自己的 **`WineListInitEvent`**，携带那张可变映射表，随后采纳事件处理器留下的结果。附属模组可以在这里增删条目或改价。
- **改动只在服务器启动时生效。** 因为重建绑定在 `ServerStartingEvent` 上，没有重载路径——`/reload` 不会重新执行它。

读取时可以按条目 ID 排序，这正是菜单顺序稳定而非哈希顺序的原因。

## 菜单标题用了别的模组的命名空间

吧台构建菜单标题用的翻译键是 **`container.bakeries.wine_list`** —— `bakeries` 命名空间，**并不属于本模组**。Sip Moment 随后在**自己的**语言文件里定义了这个键（「Wine List」），所以在单装本模组时标题显示正常。

风险出现在同时安装了真正拥有该命名空间的模组时。翻译键是全局的：如果 Bakeries——或它的任何附属——以不同内容定义了 `container.bakeries.wine_list`，**加载顺序更靠后的一方胜出**，本模组的酒单标题会被悄悄改掉。模组内**没有任何 `container.sip_moment.*` 键**。

这不会导致故障——只有标题文字可能不同。见[须知](07_technical_and_limits)。
