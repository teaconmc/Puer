# 服务端选项

## COMMON 配置

名为 `ServerConfig` 的配置规格实际以 NeoForge `COMMON` 类型注册。当前字段如下：

| 配置键 | 默认值 | 作用 |
|:---|:---:|:---|
| `allowServerSentChunk` | `false` | 控制标准客户端界面是否显示服务器区块请求按钮 |
| `overrideSeaLevel` | `false` | 是否覆盖地图编译使用的海平面 |
| `seaLevelOverride` | `0` | 开启覆盖后使用的高度，允许任意整数 |

海平面覆盖只改变地图编译器确定记录下界的方式，不会修改服务器维度的真实海平面、区块或世界生成。

## 两种区块请求

标准界面在 `allowServerSentChunk` 可用时提供：

- **请求地理数据**：以玩家为中心扫描半径 `256` 个区块的正方形，把本地缓存缺失的区块列入请求。请求使用非生成状态，但仍可能给服务端带来大量加载和发送工作。
- **所选区块服务器重发**：为框选列表请求完整区块状态，可能加载或生成所选区块，然后把完整数据发回客户端。

服务端把请求放入批处理队列，同时最多安排 `64` 个活动任务。任务会添加无超时加载票，完成后再移除。

::: warning
当前批处理器无法消费空请求：若列表中没有区块，它会直接返回，却不移除队首。标准“请求地理数据”按钮在没有缺失缓存时仍可能发送空列表，此后同一服务端的后续区块请求都会被堵在该队首之后，恶意客户端也可主动触发。部署前应在网络处理器或批处理器拒绝或丢弃空列表；若已卡住，当前实现需要重新初始化服务端批处理器才能恢复。
:::

::: danger
半径 `256` 的扫描最多覆盖 `513 × 513` 个区块位置。即使只请求本地缺失项，也可能形成非常大的列表。不要把“请求地理数据”当作常规探索或预生成工具。
:::

## 权限边界

当前实现用 `allowServerSentChunk` 控制标准客户端按钮是否出现，但服务端网络处理器本身没有逐玩家的游戏管理员权限检查，也没有再次读取这个布尔值。它不应被当作可靠的访问控制层。

需要严格控制资源消耗的服务器应限制可连接客户端、监控请求造成的加载，并在部署前自行验证或补充网络层权限策略。路径点“传送”则是另一条路径：它发送 `/tp`，由原版命令权限决定。

## 部署检查

1. 确认客户端与服务器使用兼容版本。
2. 在测试环境分别验证一般地理数据请求和小范围选择重发。
3. 观察服务端 tick 时间、区块加载数量和网络流量。
4. 确认客户端 COMMON 配置是否显示预期按钮，不要假设专用服务器配置会自动成为客户端权限状态。
5. 只在明确接受资源成本后开放请求功能。
