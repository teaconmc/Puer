# 进度板

`progress_pad` 是本附属的监控物品，而它的呈现方式是整个模组中最出人意料的一点：**你把它装进一个普通的物品展示框。**

## 它如何运作

本附属修补了「附着于方块的实体」的 tick。在服务端，每一刻，对每个物品展示框：

- 若框内物品是**进度板**，
- 且 tick 计数能被 **5** 整除——即约每秒刷新四次，
- 就读取该板存储的元数据，其中含有**一名女仆的 UUID**，
- 把该 UUID 解析为一个活着的女仆，
- 然后向**所有正在追踪该展示框的玩家**推送更新数据包。

所以板是绑定到特定女仆的，而展示框是一个**公共显示器**：任何能看到该框的人都能看到她的进度，无需打开任何界面。

## 🔑 旋转展示框会改变它显示的行数

这是没人猜得到的部分。展示框的**旋转值**被当作一项设置读取：

| 展示框旋转 | 显示条目数 |
|:---|:---|
| 0 | **1** |
| 1 | **15** |
| 2 或 3 | **10** |

而板自身的样式还会乘上一个倍数：

| 样式 | 倍数 |
|:---|:---|
| 普通 | ×1 |
| **`SMALL`** | **×2** |

因此一块 `SMALL` 样式的板在旋转 1 的框中显示 **30** 条，而同一块板在旋转 0 时只显示 **2** 条。**旋转物品展示框在这里是一个 UI 控件，而游戏内没有任何提示。**

这张表的实用读法是：**旋转 0 是单行滚动条**，旋转 1 是**最大**细节，旋转 2 与 3 是折中档。**如果你的板只显示一行而你期待的是列表，请旋转展示框。**

## 它渲染成地图而不是物品

两个客户端 mixin 改变了展示框的绘制。对于那些自称「地图式」且当前可用的物品，本附属会：

- 通过自有接口把物品堆存入展示框的渲染状态，并
- **抑制该框默认的方块模型提交**。

效果是板会**填满整个展示框、成为一块平整可读的表面**——就像地图那样——而不是作为一个悬在框里的小物品模型出现。这正是墙上的看板能被看清的原因。

同一套地图式渲染路径也服务于本附属的其他纸质物品，因此那个接口是通用的而非专为进度板。

## 复用而非重做

进度板有**三条配方**，多于任何其他物品：

| 配方 | 类型 |
|:---|:---|
| `progress_pad` | 魔法阵 |
| `progress_pad_filled_map` | 魔法阵 —— 一条变体路径 |
| `progress_pad_reuse` | **`list_clear`** |

那条**填充地图变体**强烈暗示了该物品的性质：**它像地图一样制作，因为它像地图一样显示。**

`list_clear` 路径意味着一块已绑定某女仆的板可以被**擦除并重新绑定**给另一位，而不必丢弃。

## 搭一面监控墙

1. 为每个你想监视的女仆各做一块板。
2. 把每块绑定到对应女仆。
3. 成排装进展示框。
4. 按你想要的信息量设置每个框的旋转——**正在排查的那位用旋转 1，只需要心跳的用旋转 0。**
5. 想在同样空间里获得双倍行数时使用 `SMALL` 样式。

由于更新是推送给所有追踪该框的玩家的，**这样一面墙在服务器上是共享基础设施而非私人读数。**
