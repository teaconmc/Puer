# 配置与限制

## 配置规模很大，而且多数是关于别的模组

配置规格由跨四个区域的数十个条目构成：

| 分节 | 覆盖内容 |
|:---|:---|
| `compat.*` | 全部集成 —— 迄今最大的一节 |
| `speed.*` | 六个逐活动倍率 |
| `behavior.*` | 重试上限与活动范围 |
| `debug_msg` | 调试输出 |

`compat` 分节见[与其他模组一起玩](07_integrations)。本页覆盖其余部分。

## 速度：六个倍率，全部低于 1.0

| 选项 | 默认 | 范围 |
|:---|:---|:---|
| `speed.crafting` | 0.5 | 0.0–3.0 |
| `speed.collect` | 0.5 | 0.0–3.0 |
| `speed.place` | 0.5 | 0.0–3.0 |
| `speed.follow` | 0.5 | 0.0–3.0 |
| `speed.view_change` | 0.5 | 0.0–3.0 |
| **`speed.view`** | **0.3** | 0.0–3.0 |

每一个默认值都在 `0.5` 或以下，而 **`view` 是最慢的**。这个节奏是刻意的：**女仆会先可见地读一遍容器再动手。** 若吞吐比动画更重要，调高 `speed.view` 是最有效的单项改动，六项都可以调到 `3.0`。

范围允许把任一项设为 `0.0`——**这值得作为风险而非特性来提示。**

## 行为：三个上限与一个范围开关

| 选项 | 默认 | 含义 |
|:---|:---|:---|
| `behavior.max_store_tries` | **3** | 放弃存放前的尝试次数 |
| `behavior.max_logistics_tries` | **50** | 放弃一次物流运输前的尝试次数 |
| `behavior.max_craft_tries` | **600** | 放弃一次合成前的尝试次数 |
| `behavior.use_all_storage` | **`false`** | 允许访问**全部**仓库而非仅已定义的 |

3 / 50 / 600 这个跨度是整份文件中信息量最大的东西——为什么合成需要比存放多两百倍的耐心，见 [04 合成引擎](04_crafting_engine)。

`use_all_storage` 默认**关闭**意味着**默认情况下仓库标记是强制的**。打开它是一种便利，代价是失去对「女仆会碰什么」的控制；**在共享基地上，请刻意做这个决定。**

## 两个调试命令，且没有权限门槛

本附属注册的命令树提供：

| 命令 | 用途 |
|:---|:---|
| `debug_crafting <control>` | 准备并逐步执行合成调试 |
| `debug_maid <control>` | 为某女仆附加调试上下文 |

有两点需要知道：

**两棵命令树上都没有发现权限要求。** 命令注册中不存在 `requires(...)` 门槛，这意味着**任何玩家都能用，而不限于管理员**。在公开服务器上值得用外部手段限制——与本批若干其他调试命令是同一类注意事项。

**它们的回复是硬编码的英文字面量**，而非翻译键——例如提示你点击一名女仆以建立调试上下文。因此**无论你的语言设置如何它们都显示英文**，也无法用资源包翻译。

它们是开发者工具而非玩法，但在正常安装中确实存在。

## 本地化完全对等

| 文件 | 键数 |
|:---|--:|
| `en_us.json` | **512** |
| `zh_cn.json` | **512** |

两种语言键数相等。除上述硬编码命令输出外，本附属的本地化是规范的。

## 刻意缺席的东西

| 缺席项 | 为何这是正确的 |
|:---|:---|
| **方块** | 每一件东西都是佩戴或携带的物品 |
| **战利品表** | 没有方块可以掉落 |
| **世界生成** | 它不向世界添加任何东西 |
| **自己的女仆实体** | 它扩展母模组的女仆 |
| **原版合成配方** | 一切都在母模组的魔法阵制作 |

**零战利品表这一条尤其值得说明**：它在检查清单上看着像缺口，实则不是——**没有方块注册表，战利品表就无处附着。**

## 其他打包事实

| 关注点 | 数值 |
|:---|:---|
| 版本 | `2.0.0-neoforge+mc26.1.2` |
| 作者 / 许可 | xypp / **MIT** |
| 访问转换器 | 有 |
| 音效 | 1 个，配 `sounds.json` |
| 贴图 | 84 |
| 进度 | 13 |
| 标签 | 11 |
| 实体 | 2 个，都是不可见的显示辅助体 |
| 记忆模块 | 已注册 —— 新增女仆大脑记忆 |

那两个实体值得一提：**它们不是生物。** 它们的存在是为了让模组能在世界中显示东西——标记与持物展示——这也是它们被注册在 `MISC` 类别并各配渲染器的原因。

## 从它的数字读出设计取向

三个数字放在一起，比任何叙述都更能说明这个模组的设计：

- **600 次合成重试** —— 深链条被预期且被支持。
- **`speed.view` 为 0.3** —— **被看见在干活**比干得快更重要。
- **`use_all_storage` 默认关闭** —— 你被期望始终掌握「女仆会碰什么」。
