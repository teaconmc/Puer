# 获取开始

## 运行前提

- 八角需要同时装在服务端与客户端：服务端构建选项卡数据，每个客户端根据同步到的载荷重建自己的创造模式选项卡列表。
- 内容完全来自数据：一个同时提供八角选项卡 JSON 与战利品表的数据包，以及这些战利品表产出的物品（原版物品或其它模组的物品）。八角自身不注册任何物品。
- 安装 JEI 可获得数据驱动物品变体的最佳体验；Better Creative Tabs 同样受支持。

## 选项卡定义

每个八角选项卡是 `data/<namespace>/anisum/` 下的一个 JSON 文件（文件名即选项卡路径）。JSON 加载器应用数据包条件，因此带条件的选项卡文件与其它条件数据一样工作。支持的字段：

- `location` —— 选项卡的标识符，用作其注册表键。
- `name` —— 以 JSON 文本组件表示的显示名；资源包通常提供配套的 `itemGroup.*` 翻译键。
- `icon` —— 作为选项卡图标的物品堆模板，默认使用屏障。
- `include` —— 战利品表模式的列表，其产出的物品属于该选项卡。
- `sort` —— 可选列表，定义所纳入物品的显示顺序。

## 匹配与排序

服务端只处理不在 `minecraft` 命名空间内、且恰好包含一个战利品池与一个 `LootItem` 条目的战利品表。抽取出的物品堆会附加到每个 `include` 模式命中该表的选项卡上；未命中任何 `include` 模式的战利品表不会在任何位置展示。

模式支持三种形式：完整路径（`namespace:path1/path2/location`）、通配符（`namespace:path1/path2/*_cell`）与正则表达式（`namespace:path1/path2/.*_cell`）。`sort` 列表用同样的语法定义选项卡内物品的顺序；未命中任何排序条目的物品排在最后，同序时按 ID 比较。

## 客户端配置

客户端配置文件 `anisum-client.toml` 暴露一个条目：

- `placeSideBySideInventoryAndCreativeTabs` —— 实验性，默认关闭。启用后，创造模式物品栏界面变为并排布局：左侧为创造选项卡面板，右侧为完整玩家物品栏面板（快捷栏、主物品栏、盔甲槽、副手与销毁槽）。该布局下原版物品栏选项卡被禁止选中。

## 网络同步

模组通过 `anisum` 上的频道版本 `1` 通信，共有两种载荷：`AnisumSyncStartPayload` 宣布客户端应期待的选项卡载荷数量；`AnisumTabSyncPayload` 携带每个选项卡的 location、名称、图标与排序后的物品堆。客户端收齐全部预期载荷后，保留既有非八角选项卡，把八角选项卡注册在「工具与实用物品」之前，并触发选项卡清理/加载事件。

## 集成

- JEI：通过物品模型数据组件注册物品子类型（原版例外列表如药水、喷溅箭与附魔书除外），向 JEI 报告并排布局的真实宽度以避免面板重叠，并在运行时增删选项卡内的素材。
- Better Creative Tabs：每次选项卡重建后使其内部索引失效。
- 事件：`AnisumTabClearEvent`（旧选项卡移除前）与 `AnisumTabLoadedEvent`（新选项卡注册后）发布于 NeoForge 事件总线，供其它模组订阅。
