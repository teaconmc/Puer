# Subspace Relay

## Purpose and data flow

Subspace is a voice relay process independent of the Minecraft server. When enabled, the Minecraft server still handles login, tokens, and configuration delivery, while clients send Opus audio directly to Subspace for forwarding.

Channel must remain installed on the Minecraft server. One Subspace process can serve multiple Minecraft servers when later instances use the same protocol and security level as the first. The same UUID connecting simultaneously from multiple servers is undefined behavior.

## Server configuration

Current `ChannelServerConfig` fields are:

| Field | Default | Purpose |
|:---|:---:|:---|
| `useSubspace` | `false` | Enable relay |
| `subspaceAddress` | Empty | Relay address or hostname |
| `subspaceServerPort` | `0` | Port accepting the Minecraft server |
| `subspaceClientPort` | `0` | Port accepting Channel clients |
| `subspaceFrequency` | Empty | Shared passphrase from Minecraft server to Subspace |
| `subspaceProtocol` | `TCP` | Client transport protocol |
| `subspaceSecurityLevel` | `MID` | Client-connection security level |

Environment variable `CHANNEL_SUBSPACE_FREQUENCY` overrides the configured frequency when present. Port default `0` is not a deployable recommendation; both values must match the actual Subspace listeners.

## Current protocol support

The enum and README show `TCP`, `UDP`, and `GRPC`, but the current Java client throws unsupported-operation errors for UDP and GRPC, while the C++ Subspace main program leaves both as TODO branches. Select only `TCP` for real deployments.

::: danger
Do not select UDP or GRPC in production merely because configuration can save them. The current implementation does not fall back to TCP.
:::

## Security levels

Under TCP:

- `NONE` sends both handshake and voice in plaintext.
- `LOW` verifies the handshake with AES-GCM and sends voice in plaintext.
- `MID` uses AES-GCM for the handshake and AES-CTR for voice encryption without full tamper authentication.
- `HIGH` uses AES-GCM for both handshake and voice, providing encryption and authentication.

The Minecraft-server-to-Subspace connection always uses AES-GCM. The client passphrase is generated by the Minecraft server when the player joins and is not `subspaceFrequency` itself.

## Operations checklist

1. Validate both ports with TCP on one machine or a controlled LAN first.
2. Confirm that Minecraft server and Subspace frequency match exactly.
3. Choose a security level for the threat model and observe its CPU cost.
4. On connection failure, inspect Minecraft server, client, and Subspace logs together.
5. After configuration changes, use `/ch reset_subspace` to rebuild the connection.
