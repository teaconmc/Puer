# 平台与故障排查

## 原生平台范围

当前资源包含 Windows、Linux、macOS 的 `x86_64` 与 `aarch64` WebRTC 原生库。生产环境会把对应库提取到临时目录并加载；不支持其他操作系统或 CPU 架构。

README 只承诺对 Linux 提供有限支持，不积极支持 macOS。存在原生文件不等于所有音频设备、JVM 和驱动组合都经过测试，服务器活动前应使用目标机器验证。

## NVIDIA 平台限制

NVIDIA AI 降噪只在 Windows 启用，并检查渲染器名称包含 RTX、驱动主版本至少 `570`。界面提示的最低硬件是 GeForce RTX 2060、Quadro RTX 3000、TITAN RTX 或更高，采样率必须为 `16000` 或 `48000 Hz`。

Linux 和 macOS 仍可使用固定 WebRTC 降噪、高通、增益和空间音频，只是不能使用当前 NVIDIA AFX 客户端路径。

## 没有麦克风输入

依次检查操作系统隐私权限、其他程序是否独占设备、Channel 的设备名称、设备是否支持所选硬件采样率。命名设备消失时模组会尝试默认输入；完全没有可用设备则 HUD 显示错误。

开发环境不会从 JAR 自动提取 WebRTC 库，而是尝试从运行目录直接加载 `webrtc.dll`、`webrtc.so` 或 `webrtc.dylib`。这只影响开发运行配置，正常发布 JAR 使用内置 natives。

## 能发话但听不到

先让双方在同维度、相距少于 `64` 格并关闭全体/个人静音。检查发话者 HUD 是否停在静音、VAD、响度或仅 OP 状态。频道测试还要确认发送端和音响都是相同正频道，接收者在音响 `64` 格内，并等待路由更新。

若只有路径追踪开启时无声，临时关闭 `rayTraceAudio` 区分声学计算与网络问题。若只有 Subspace 无声，回到普通 Minecraft 转发验证基础语音，再检查 TCP 地址、双端口和 frequency。

## 依赖与打包

源码广泛引用 T88，但当前 `neoforge.mods.toml` 只声明 NeoForge 与 Minecraft，没有显式声明 T88。整合包必须主动包含兼容的 T88，不能依赖加载器提前给出清晰的缺失依赖提示。

按键分类语言键也沿用旧式 `key.category.channel.channel`，而当前分类对象使用资源 ID；若控制设置中分类显示未翻译，这是语言键与新 API 形式不一致，不影响 `Alt+C` 和 `Y` 本身注册。

## 已知限制清单

- UDP 与 GRPC Subspace 尚未实现。
- 流体声学、绝对响度和水下低通尚未完成。
- 手持话筒已实现，但 README TODO 尚未更新。
- 设备没有配方或战利品表，只能创造模式/命令获取。
- 方块频道设置包缺少服务端距离与权限复查。
- 路径追踪、AI 降噪和短帧传输组合需要按机器压测。
