# 分享与限制

全息作品与幻灯机特效使用同一套发布系统：你在本地创作、上传到服务器，其他玩家下载、点赞与展示。

## 发布循环

| 操作 | 效果 |
|:---|:---|
| 上传 | 把你的本地作品发布到服务器 |
| 下载 | 把分享的作品复制到你的本地列表 |
| 更新 / 重新下载 | 拉取你已持有作品的较新版本 |
| 点赞 / 取消点赞 | 添加或移除你的点赞 |
| 删除（本地） | 仅移除你的本地副本 |
| 从服务器删除 | 永久移除已发布的作品 |

服务器列表可按**点赞**、**最新**或**最早**排序，也可筛选为**我的**。每一行显示作者、首次发布与更新时间、点赞数，全息作品还显示模型名。标注 **（有更新）** 的行表示服务器副本比你的更新。

下载是分块进行的，运行期间显示百分比。

## 你只能发布一件作品

这是最可能让你意外的限制：**每位玩家的发布上限是 1。**

要发布新东西，你必须先删除已发布的那一件。界面写得很直接——*你最多可以发布 1 件作品，请先删除自己的一件。* 你的**本地**库不受影响；你可以持有任意多个本地作品，只需选择哪一件公开。

在服务器上请据此规划：把你的发布位当作展品位，而不是仓库。

## 全部尺寸上限

| 限制 | 值 |
|:---|:---|
| 打包模型 | 2 MiB |
| 打包贴图（总计） | 4 MiB |
| 上传载荷 | 8 MiB |
| 解压后大小 | 32 MiB |
| 传输分块 | 24 KiB |
| 每次传输分块数 | 2048 |
| 并发传输数 | 2 |
| 每位玩家已发布作品 | 1 |
| 计分板行数 | 10 |

**32 MiB 解压上限**是与 8 MiB 载荷上限相互独立的另一道保护——它防止一个体积很小的压缩上传在服务端膨胀成庞然大物。这是有意的防御，不是疏漏。

成功时对话框会明确报告发出了什么：*已打包 N 张贴图、N 个模型、N KB。*

## 上传为何被拒

服务端与客户端都会校验，且每种失败都指明原因：

| 提示 | 原因 |
|:---|:---|
| 需要描述 | 你把描述留空了 |
| 图无法编译 | 请先修好图 |
| 缺少着色器函数 | 作品引用了你已删除的函数 |
| 打包贴图为 N MB（上限 N MB） | 超出贴图预算 |
| 打包模型为 N MB（上限 N MB） | 超出模型预算 |
| 已达发布上限 | 你已经有一件已发布作品 |
| 请等待 N 秒后再上传 | 冷却中 |
| 进行中的上传过多 | 并发传输上限 |
| 分块过大 / 作品过大 / 作品格式错误 | 服务端拒绝 |

**「缺少着色器函数」这一条最值得记住。** 删除着色器函数资源并不会清理使用它的节点，因此一件作品在本地看起来没问题，之后却拒绝上传。提示会列出名字——恢复它们，或移除引用它们的节点。

另请注意**作品必须能编译才能发布**。你无法分享一张损坏的图，这也意味着你从服务器下载的任何东西至少在结构上是有效的。

## 查看点赞排名

**全息点赞计分板**方块是一块列出最受欢迎分享作品的公告牌，在数据变化时刷新而非按定时器刷新，最多显示 10 行。

把它与一排服务器全息投影搭配，就能做出一个由榜单为当前热门作品署名的展廊。
