# 无人机节点

无人机程序就是一张 KilaGraph 节点图。模组提供十二个节点，分为**消耗时间**的与只**报告信息**的两类。

## 动作节点——这些消耗刻

这些节点都会推进运行时钟。确切的刻开销显示在每个节点的游戏内提示文本中。

| 节点 | 作用 |
|:---|:---|
| 移动 | 朝选定方向移动一格 |
| 移动到 | 直飞到绝对目标格（x, z） |
| 种植 | 在当前格种下一颗南瓜种子 |
| 收获 | 收获当前格的成熟南瓜，把它的分数入账 |
| 清除 | 清掉当前格上的任何东西——作物或腐烂的南瓜 |
| 等待 | 空转给定刻数，让南瓜生长 |

**「移动到」按距离计价而非按次计价：每移动一格 4 刻。** 这使它成为最值得围绕优化的节点。短距离跳跃用「移动」可能更便宜；长距离穿越才是「移动到」的价值所在。由于开销随距离缩放，路线规划比指令条数更重要。

**「收获」会拿走整个合并块。** 若成熟南瓜已合并成一个正方形，收获该格会一次性把整块的分数入账。先生长与合并、再收获，是高分的核心——详见 [04 农场与评分](04_farm_and_scoring)。

**「清除」是应对腐烂的唯一手段。** 腐烂的南瓜毫无价值，且会一直占着它那一格直到被清除，因此从不检查腐烂的程序会慢慢把自己的田堵死。

## 信息节点——这些免费

这些节点报告状态而不推进时钟，因此你可以在一刻之内任意查询——只受 [02 无人机编程站](02_drone_station) 中所述的 10000 步保护限制。

| 节点 | 报告内容 |
|:---|:---|
| 无人机位置 | 无人机当前所在格（x, z） |
| 扫描格 | 某格的状态：可种植、成熟、腐烂，以及合并尺寸 |
| 分数 | 本次运行已入账的分数 |
| 刻信息 | 当前运行刻 |
| 打印 | 向运行日志追加一个值 |

## 「扫描格」有两种坐标模式

这是最容易让人栽跟头的细节：

- **RELATIVE（相对）**接受相对无人机当前位置的 `dx`/`dz` **偏移量**。
- **ABSOLUTE（绝对）**接受 `x`/`z` **田地坐标**——与「移动到」所用的是同一坐标空间。

把两者搞混会产出一个看起来正确、却在扫描错误格子的程序。若你要把扫描与「移动到」配对使用，请用 ABSOLUTE，让两者指向同一空间。

扫描除阶段之外还报告**合并尺寸**，这正是让程序判断某个正方形值得继续等待、还是已经到达上限的依据。

## 打印与日志面板

打印会向滚动日志追加内容，显示在编程站的日志面板中。它是你唯一的内省工具，并且天然与单步配合：单步一刻、读一下图打印了什么、重复。

请记住日志只保留**最近 200 行**。

## 建议的第一个程序

一个能产出非零分数的最小循环：

1. **扫描格**检查当前位置是否可种植。
2. **种植**一颗种子。
3. **等待**足够长的时间让它成熟。
4. **收获**。
5. **移动**到下一格并重复。

这能跑通，但它忽略了合并与腐烂——正是这两个机制把低分与高分区分开来。优化之前请先读 [04 农场与评分](04_farm_and_scoring)。
