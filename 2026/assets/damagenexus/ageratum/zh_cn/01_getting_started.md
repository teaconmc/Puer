# 入门

## 没有任何东西可以合成

伤害枢纽不注册物品、方块、实体或配方。没有创造分页，没有指南物品，也没有起始任务。它做的一切都在战斗中自动发生，而你能改动的一切都通过配置、数据包、属性修饰符或 Java API 完成。

## 安装后立即改变的内容

模组加载的瞬间，每一次由它接管的伤害事件都会走它自己的管线，而不是原版的减免数学。按随包默认值，这意味着：

- 原版**护甲**减免被压制，改由伤害枢纽重算。
- 原版**攻击性附魔**缩放（锋利、亡灵杀手、节肢杀手、力量、致密等）被压制，改以桥接贡献重建。
- 原版**状态效果**缩放（力量、虚弱、抗性提升）被压制并重算。
- 原版**内置抗性**被压制。

伤害还会依据伤害类型标签被**归类到通道**——物理、火焰、冰冷、闪电、魔法、凋零、毒素、动能——每个通道有自己的抗性属性与自己的护甲行为。

因此即使不装任何数据包，战斗数值也会与原版不同。这是设计如此，不是缺陷。若你希望原版减免继续并行运行，请把兼容模式改为 `COOPERATIVE`；见[07 它如何改变伤害](07_vanilla_compatibility.md)。

## 哪些**不会**走管线

有两类被排除：

1. 位于 `#damagenexus:bypasses_damagenexus` 中的任何伤害类型。**该标签虽被声明却没有随包文件，因此在你自行编写之前它是空的**——开箱状态下没有任何伤害通过它绕过。
2. 位于 `#minecraft:bypasses_invulnerability` 中的任何伤害类型——即 `/kill` 类与虚空伤害。源码注释说明这道守卫是刻意保留的，好让「硬原版特殊伤害」留在模组之外。

## 如何确认它在运行

由于模组默认是隐形的，请用以下任一方式：

- **物品提示文本。** 把提示调试等级设到 `OFF` 以上，带有伤害枢纽词条或条目的物品、以及被桥接的原版附魔，会获得 `[DamageNexus]` / `[DN Debug]` 提示块。按住 `Shift` 展开。
- **诊断日志。** 提高诊断域，服务端日志就会开始输出逐次命中的计算追踪。
- **命令。** 打开开发者测试命令或调试模式之一，重启后 `/damagenexus` 就会出现。

三者都在 [08 配置与诊断](08_configuration_and_diagnostics.md) 中说明。
