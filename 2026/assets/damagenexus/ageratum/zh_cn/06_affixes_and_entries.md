# 词条与条目

除数据包规则之外，伤害枢纽还能通过两个**数据组件**把行为直接附加到物品堆上。两者都持久化且网络同步，因此能存档保留，也能被客户端用于提示文本。

| 组件 | 内容 |
|:---|:---|
| `damagenexus:damage_affixes` | 词条定义列表 |
| `damagenexus:damage_entries` | 条目定义列表 |

## 词条

词条是二者中较丰富的一种，它携带：

- **稀有度** —— `common`、`uncommon`、`rare`、`epic`、`legendary`、`unique`
- **槽位** —— `item`、`weapon`、`armor`、`projectile`、`entity`、`global`
- **层级**
- 由掷值范围产生的**掷出值**，因此同一词条在不同物品上可以生成不同数字
- **显示**信息 —— 名称、提示行与风味文本
- 自己的**叠加**方式与校验器
- 它贡献的规则

由于词条会掷值，词条定义是「蓝图 + 生成规格」，而存放在物品上的实例保存的是掷出结果。

## 条目

条目是较轻的形式：同样的六个槽位值、自己的叠加方式与校验器、显示信息，以及它贡献的规则——但没有稀有度、没有层级、也没有掷值范围。固定、确定性的追加用条目；生成式、可变的用词条。

## 槽位

两者共用同一套槽位词汇：

| 槽位 | 意图 |
|:---|:---|
| `item` | 任意物品语境 |
| `weapon` | 攻击用武器 |
| `armor` | 穿戴的护甲 |
| `projectile` | 弹射物 |
| `entity` | 实体自身 |
| `global` | 无条件 |

## 它们如何呈现给玩家

词条与条目通过提示文本系统展示，而该系统**默认关闭**。提示调试等级有四档：

| 等级 | 显示 |
|:---|:---|
| `OFF` | 什么都不显示 |
| `AFFIX_SUMMARY` | 仅词条提示 |
| `AFFIX_AND_RULES` | 词条提示加规则细节 |
| `FULL` | 全部，包括完整追踪 |

请注意条目与词条名称由翻译键显示，而随包 `zh_cn.json` **遗漏了 `en_us.json` 提供的所有测试条目与测试词条名称**——共 22 个键。你自行编写的内容不受影响；此缺口只涉及随包的测试样例。

## 贡献归因

诊断开启时，对一次命中的每项改动都会被归因到一种来源类别，好让提示文本与日志能解释数字的出处：

`rule`、`entry`、`affix`、`vanilla_bridge`、`vanilla_enchantment`、`vanilla_mob_effect`、`vanilla_damage_type`、`java_api`、`unknown`

这正是提示文本能区分「这 +3 火焰来自词条」与「这 +3 火焰来自被桥接的原版火焰附加」的原因。

## 拥有者类别

内部会记录一条规则的拥有者是 `rule`、`affix` 还是 `entry`。叠加解析会考虑这一归属，因此由词条提供的规则与同名的数据包规则不会默默合并成一条，除非它们的叠加方式如此规定。
