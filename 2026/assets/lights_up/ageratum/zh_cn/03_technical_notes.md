## 已知问题：着色器资源位于不同的命名空间

模组 ID 是 `lights_up`——带下划线——代码基于它构建的每一个资源位置都使用该命名空间，包括两个渲染管道位置 `lights_up:pipeline/spotlight_beam` 与 `lights_up:pipeline/spotlight_beam_unlit`。

然而四个着色器定义文件却位于 `assets/lightsup/shaders/program/`——命名空间是 **`lightsup`**，不带下划线。模组的 Java 包名同样是 `lightsup`，差异很可能由此而来。

位于与模组 ID 不匹配的命名空间下的资源，不会被模组构造的任何标识符寻址到。后续接手这个模组的人在依赖这些着色器文件之前应先统一两者；稳妥的修法是把资源目录改名为 `lights_up`。

## 所有外观相关内容都缺失

除着色器命名空间问题之外，模组完全不附带客户端资源：

| 缺失 | 后果 |
|:---|:---|
| 方块状态 + 方块模型 | 已放置的方块渲染为缺失模型占位图 |
| 物品模型 | 手持与物品栏中的物品渲染为缺失模型占位图 |
| 贴图 | 没有任何可用于方块外观的图像 |
| 语言文件 | 方块名称显示为 `block.lights_up.spotlight_block` |

也不附带任何数据包内容：

| 缺失 | 后果 |
|:---|:---|
| 配方 | 无法合成 |
| 战利品表 | 破坏时不掉落任何东西 |
| 标签 | 不属于任何标签 |
| 创造分类 | 无法从创造物品栏获取 |

## 方块属性

| 属性 | 值 |
|:---|:---|
| 方块状态属性 | `facing`——六个方向，默认向上 |
| 形状 | 12 × 6 × 12 单位，位于方块空间下部 |
| 强度 | 1.0 |
| 遮蔽 | 已禁用 |
| 遮挡视线 | 已禁用 |
| 造成窒息 | 已禁用 |

放置时采用视线最近方向的反方向。旋转与镜像未被重写，因此结构工具不会调整朝向。

## 渲染内部实现

声明了两条渲染管道。光束管道基于方块片段构建，使用半透明混合与不写入深度的深度测试；第二条无光照管道基于实体片段构建，采用相同混合并附加额外的着色器定义。

渲染设置绑定了两个采样器：以原版白色混凝土贴图作为基础采样器，以及原版光照贴图。还提供了一个无贴图变体与一个按贴图记忆化的变体，但渲染器只使用带贴图的光束类型。

请注意，无光照管道与备用渲染类型虽已声明，却**从未被渲染器使用**——它们是为将来预留的。
