# 游戏时间与现实时间

模式切换是本模组中后果最重的一个选择，两个选项的行为完全不同。枚举恰好只有两个值——`GAME_TICK` 与 `REAL_TIME`——而已封存的胶囊会记住你用的是哪一个。

## 游戏时间

显示为**游戏时间**。倒计时以世界自身的时钟为准，这意味着：

- 它**只在世界运行时**推进。
- 关闭单人世界会**暂停**它。
- 睡过一夜，或任何推进世界时钟的行为，都会**推进**它。
- 存档在磁盘上放置多久，对它毫无影响。

想要「从现在起若干游戏日」这种语义时选这个模式——一枚在累计**游玩**时间达到一定量后才打开的胶囊。

## 现实时间

显示为**现实时间**。倒计时以真实世界的挂钟时间为准，这意味着：

- 它**无论世界是否加载都在推进**。
- **关掉游戏也不会暂停它。**
- 在游戏里反复睡觉对它没有任何作用。
- 一枚封存一个真实周的胶囊，在一个真实周之后就可启封，即使这期间你从未启动过游戏。

真正意义上「下个月再打开」的信件用这个模式。

## 真正要紧的对比

| 情形 | 游戏时间 | 现实时间 |
|:---|:---|:---|
| 世界关闭一个月 | 毫无推进 | **完整流逝** |
| 长时间连续游玩 | 推进 | 推进 |
| 反复睡觉 | **快速推进** | 无影响 |
| 服务器 7×24 运行 | 大致跟随现实时间 | 跟随现实时间 |
| 单人、每周玩一次 | 极慢 | 正常 |

::: warning
**在单人世界上这两者可能相差极大。** 一枚在游戏时间下设为「30 天」的胶囊，可能要经过许多个真实周末才打开；同样的胶囊在现实时间下则恰好 30 天后打开，无论你是否游玩。两者都不算错——但它们不可互换，而且**已封存的胶囊无法在两者之间切换**。
:::

::: tip
在常开的服务器上差异会缩小，因为世界时钟同样一直在走。如果你是在这种服务器上为其他玩家写胶囊，**现实时间是更可预测的承诺**——它对每个人的含义相同，与他们何时登录无关。
:::

## 睡觉是那个锋利的边缘

游戏时间会响应任何推进世界时钟的行为，而**睡觉能在几秒内把时钟推进整整一夜**。一群玩家轮流过夜，可以让游戏时间的倒计时消耗得远比实际游戏时长所暗示的更快。

如果一枚胶囊的意义是一份承诺而不是一个玩法机制，仅这一点就足以构成偏向现实时间的理由。

## 胶囊里存了什么

模式是 `time_capsule:time_capsule_data` 组件四个字段之一，与物品、留言，以及作为单个 long 值的解锁时间并列。因此解锁时间是**按存储的模式来解释**的——同一个数字在两种模式下含义不同，这正是模式在封存后无法更改的原因。
