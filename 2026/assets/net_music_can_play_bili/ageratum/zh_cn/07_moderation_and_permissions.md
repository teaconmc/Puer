# 审核与权限

一个允许任意玩家让附近每个客户端去取任意互联网媒体的模组，是一个审核问题。**本附属认真对待了这个问题，结果是本批中最完整的审核层。**

## 链接白名单

服务器可以启用一份允许播放的 B 站资源白名单。启用后，只有被批准的资源可以播放。

### 它在六个独立位置强制执行

| 执行点 | 它守住的行为 |
|:---|:---|
| NetMusic 的设置音乐消息 | **创建唱片或音源头** |
| NetMusic 的音乐播放器方块 | 通过母模组自己的播放器播放 |
| 现代化唱片机方块实体 | 在本附属的唱片机上播放 |
| MP4 播放控制包 | 开始 MP4 播放 |
| MP4 播放同步管理器 | MP4 同步 |
| 平板播放控制包 | 平板播放 |

**没有侧门**：检查同时位于**创建**时刻与**每一条播放**路径上，甚至通过 Mixin 深入到母模组内部。被拒时会产生一条指明你试图做什么的消息——「播放」「创建唱片/音源头」或「Pad播放」。

### 链接如何匹配

原始输入在比对前会被**规范化**，因此同一视频的 `BV…` 号、`av…` 号与完整 URL 会归到同一条白名单条目。**你只需为一个视频加一次白名单，而不是每种链接格式各加一次。**

**有一处细节很关键。** 如果某个输入**无法**被规范化为 B 站资源，白名单就**不适用于它**。白名单治理的是可识别的 B 站资源，**它不是一份适用于 NetMusic 所能接受的其他一切来源的通用 URL 允许清单**。服主不应把它理解为对所有可能音源的全面防护。

作为补充，B 站原始流地址会被独立识别为**被禁止的直链**，因此最显而易见的绕过手段——粘贴 CDN 链接而非 ID——被堵住了。

### 名单存在哪里

白名单**按世界存储**，以带缩进的 JSON 放在世界目录下一个以模组命名的文件夹中。它按需惰性加载，并在世界路径变化时重新加载；**读取失败会回退为空名单并给出警告——即失败时收紧而非放开。**

## 人工复审

白名单不只是一份命令行清单。存在一个**复审界面**，管理员可以打开，背后由四个数据包支撑：

| 数据包 | 用途 |
|:---|:---|
| 复审 | 把当前条目清单发给正在复审的管理员 |
| 复审动作 | 对条目执行操作——包括移除 |
| 预览 | 在决定前查看某条目 |
| CSV 导出 | 导出整份清单 |

**CSV 导出是体现「这是为真实管理设计的」的细节**：一份你可以拿出游戏、在表格软件里阅读并归档的清单。

## 审计日志

一个**播放审计管理器**记录被播放的内容。配合下面的 `sources` 命令，管理员既能看到当前正在播放什么，也能回查曾播放过什么。

## 权限节点，做得很规范

权限被声明为 **NeoForge 权限节点**，而不是硬编码的管理员等级检查。**这意味着服务器可以把它们接到权限插件上、按角色授予，而不必发放管理员身份。**

| 节点 | 默认 | 授予 |
|:---|:---|:---|
| `audit.sources` | **管理员等级 2** | 查询当前正在播放的唱片机 / MP4 音源 |
| `pad.refresh` | **管理员等级 2** | 刷新服务端平板状态 |
| `whitelist.manage` | **管理员等级 4** | 管理白名单并打开复审界面 |

存在两处刻意的绕过，都很合理：

- **没有玩家**的来源——控制台或命令方块——一律通过；
- **单人游戏宿主**一律通过，因此单人世界无需任何权限配置。

权限求值失败时返回 **false**，同样是失败时收紧。

## 命令

注册了一个服务端根命令与一个短别名，两者树结构相同：

| 命令 | 需要的节点 |
|:---|:---|
| `sources [limit <1–100>]` | `audit.sources` |
| `pad refresh` | `pad.refresh` |
| `whitelist add <ID 或链接>` | `whitelist.manage` |
| `whitelist list` | `whitelist.manage` |
| `whitelist remove <ID 或链接>` | `whitelist.manage` |
| `whitelist export` | `whitelist.manage` |
| `whitelist review` | `whitelist.manage` |

另有一个独立的**客户端**根命令用于本地操作，例如刷新平板地图缓存——这与刷新服务端平板状态是不同的事，服务端命令的回复也这么说明。

请注意命令输出写作**硬编码中文文本**，因此使用英文的管理员会看到中文回复。见 [08 技术说明与限制](08_technical_and_limits)。

## 限流

一个网络限流器守护本附属的数据包。考虑到存在多少控制与同步包——设备 ID、播放控制、时间轴、状态镜像、平板文档、白名单复审——这是必要而非装饰性的补充。

## 建议的服务器姿态

| 若你运营 | 请这样做 |
|:---|:---|
| 公开服务器 | **启用白名单**，`whitelist.manage` 只授予可信管理员，并保留审计日志 |
| 与朋友的私服 | 白名单可以不开；`audit.sources` 保持等级 2 是合理默认 |
| 单人世界 | 什么都不用做——你一律通过 |

而无论规模大小，请记住：**每个客户端都会自己去取流**，因此一个被允许的音源，就是每位听众的机器都会去连接的音源。
