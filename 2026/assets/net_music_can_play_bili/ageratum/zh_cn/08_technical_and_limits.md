# 技术说明与限制

## ⚠️ 你的 B 站登录以明文存储

**这是关于本模组最重要的实际事实。**

配置位于 **`config/net_music_can_play_bili.json`** —— 一个自定义 JSON 文件，而不是 NeoForge 的 TOML。登录时会有两个字段写入其中：

| 字段 | 内容 |
|:---|:---|
| `sessdata` | 你的 B 站 **`SESSDATA` 登录 Cookie** |
| `webCookie` | 拼装好的完整 Cookie 头 |

两者都以普通的、**未加密**的 JSON 字符串存储，并在启动时被读回以恢复会话。

**一个 `SESSDATA` Cookie 就是一次登录。** 任何拿到它的人都能在其过期前以你的 B 站账号身份行事。因此：

- **分享整合包、配置文件夹或世界压缩包时不要带上这个文件。**
- **不要把它附在 bug 报告里**，并检查任何会打包 `config/` 的支持日志归档。
- **谨慎对待云同步的游戏目录**，以及屏幕共享你的配置文件夹。
- 若你认为它已泄露，请**在 B 站网页端退出登录**以使其失效。

**这一切都不是恶意的**——持久化会话本来就常这么做，很多工具都如此。但这是把未加密凭据放在一个人们经常分享的文件里，**这个组合值得一条警告而不是一个脚注**。

## 配置文件

一切都在那一个 JSON 文件里。**没有配置界面，也没有 TOML。**

| 字段 | 默认 | 含义 |
|:---|:---|:---|
| `sessdata` | —— | 登录 Cookie（由登录写入） |
| `webCookie` | —— | 完整 Cookie 头 |
| `dolbyEnabled` | `true` | 是否解码 Dolby 流 |
| `dolbyJocEnabled` | `true` | 对象音频层 |
| `dolbyMaxObjectSources` | `64` | 对象音源上限 |
| `stereoCrossfeed` | `0.16` | 耳机交叉馈送量 |
| `userAgent` | 空 | 覆盖 User-Agent |
| `rotateUserAgent` | 关 | 逐请求轮换 User-Agent |

CDN 选择器状态也持久化在同一文件中。文件格式损坏会被捕获并记为一次加载失败，而不会导致崩溃。

有两个系统属性提供默认值：`ncpb.bili.user_agent` 与 `ncpb.bili.rotate_user_agent`。

## 原生库

jar 中随包 **40 个原生二进制**，覆盖 Windows、macOS、Linux 的 x86-64 与 ARM64。每平台含 `avcodec`、`avutil`、`swresample`、`swscale`，加上模组自己的 `video_jni` 与 `eac3_jni`；Windows 另加 `libwinpthread-1`。

后果：

- jar **体积大**，鉴于覆盖面这是不可避免的。
- **专用服务器完全不需要它们**——解码在客户端。
- 覆盖面真的包含 Apple Silicon 与 ARM64 Windows，**很多媒体模组做不到这一点**。

## Mixin

十九个，其目标清单说明了与母模组的集成有多深：

| 分组 | Mixin |
|:---|:---|
| **深入 NetMusic** | CD 刻录机界面、计算机界面、大喇叭界面及其启动消息、音乐播放器方块实体、设置音乐消息、音乐下发客户端消息 |
| 渲染 | GUI 渲染目标、手持物品渲染器、GL 设备 YUV 着色器跳过 |
| 界面管线 | 抽象容器界面、界面访问器、按钮访问器、GuiGraphics 提取访问器、客户端提示组件 |
| 声音管线 | 音频引擎访问器、声音管理器访问器、库访问器 |
| 客户端 | 客户端包监听器方块更新 |

由此可得两点。第一，**本附属深入到了 NetMusic 自己的界面与消息内部**——它不是外挂式的，**NetMusic 一旦更新这些表面，附属就必须同步更新**。这正是依赖被声明为最低 `1.5.1` 且 `ordering = "AFTER"` 的原因。

第二，三个桥接类——库、音频引擎与声音管理器——的存在是为了把这类访问收在一道边界之后，而不是让访问器调用散落各处。

## Iris 被使用但未声明

Iris 是一个 `compileOnly` 构建依赖，**未**出现在模组的已声明依赖中。但与裸的未声明依赖不同，**每一次访问都经过带回退的兼容辅助类**，并有守卫把模组的着色器覆盖限定在自己的管线内。见 [05 视频与投影](05_video_and_projectors)。

因此实际风险很低，但元数据仍然没有提及一个代码 import 了的模组——排查类加载问题时值得知道这一点。

## 本地化不对等

| 文件 | 键数 |
|:---|--:|
| `en_us.json` | **111** |
| `zh_cn.json` | **121** |

共 12 个键不同。**其中 11 个只存在于中文**，因此英文客户端在这些位置显示原始键，而这 11 个里有两个尤其显眼：

| 英文缺失项 | 显示位置 |
|:---|:---|
| **按键绑定分类名** | **控制设置**菜单——一个未翻译的分类标题 |
| **全息眼镜配置按键** | 控制设置菜单，紧挨着它 |
| MP4 解除链接消息 | 游戏中 |
| 歌词投影仪「已链接物品」消息 | 游戏中 |
| 视频投影仪「已链接 / 已解除 / 已链接物品」消息 | 游戏中 |
| 全息眼镜「已链接数量 / 槽位已满 / 数量提示」 | 游戏中 |
| 全息眼镜「需先装备才能配置」消息 | 游戏中 |

唯一只存在于英文的键是一个调试日志配置标签。

因此 [02 设备](02_devices) 与 [05 视频与投影](05_video_and_projectors) 中描述的**链接流程在英文客户端上大体是未翻译的**——你会对着原始键而不是句子操作。

命令输出则是镜像问题：它是**硬编码中文文本**，在两个方向上都无法翻译。

## 安全审查结果

因为这个模组要访问互联网，特意逐项检查：

| 检查项 | 结果 |
|:---|:---|
| 监听套接字或 HTTP 服务器 | **无** |
| 绑定所有网卡 | **无** |
| 宽松的 CORS 头 | **无** |
| 执行外部进程 | **无** |
| 任意 URL 播放 | **有守卫** —— 直链被拒、白名单六点强制 |
| 服务端复查 | **有** —— 播放与创建唱片都在服务端检查 |
| 权限检查 | **有** —— 三个权限节点，失败时收紧 |
| 限流 | **有** |

**唯一真实的暴露面是上文所述的明文凭据文件。** 所有面向网络的行为都是纯出站的。
