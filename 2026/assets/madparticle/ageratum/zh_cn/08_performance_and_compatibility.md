# 性能与兼容性

## 核心配置

客户端配置类 `MadParticleConfig` 的当前默认值包括：

| 配置 | 默认值 | 作用 |
|:---|:---:|:---|
| `maxParticleAmountOfSingleQueue` | `100000` | 每种渲染队列容量上限 |
| `limitMaxParticleGenerateDistance` | `false` | 始终拒绝两倍视距外的粒子生成 |
| `bufferFillerThreads` | `8` | 填充渲染缓冲的辅助线程数 |
| `optimizeCommandBlockEditScreen` | `true` | 扩展命令方块输入框并加入设计器入口 |
| `forceMaxLight` | `false` | 强制粒子按光照 `15` 渲染 |
| `translucentMethod` | `DEPTH_FALSE` | 半透明处理方式 |

单次指令数量、执行频率、寿命和 `expireThen` 分支共同决定真实峰值。提高队列上限只允许保存更多粒子，不会自动提高 CPU、GPU 或网络能力。

## 渲染与计算接管

`takeOverRendering` 与 `takeOverTicking` 默认都是 `VANILLA`：尝试让支持的原版粒子使用实例化渲染和并行 tick。`NONE` 关闭相应接管，`ALL` 还会尝试处理其他模组粒子。

其他模组可能使用自定义渲染类型、生命周期副作用或非线程安全状态，因此设置为 `ALL` 明确可能产生错误。出现粒子缺失、崩溃或行为异常时，先把两项改为 `VANILLA` 或 `NONE`，再用类名黑名单缩小范围。

## 半透明处理

三种模式各有取舍：

- `DEPTH_TRUE`：接近原版深度测试，适合以不透明视觉为主的场景。
- `DEPTH_FALSE`：简单混合，适合大量相同半透明粒子，但遮挡关系不精确。
- `OIT`：加权混合顺序无关透明，普遍性更好，但会增加 GPU 压力。

同一演出应在实际使用的光影、分辨率和观看角度下比较，而不是只看设计器缩略图。

## 光照缓存

默认水平半径 `256`、垂直半径 `128`，刷新频率为每帧。范围越大，占用内存越多；刷新越频繁，高速移动时越准确，但 CPU 成本更高。界面会根据范围估算额外内存。

修改光照缓存范围后应重启客户端。`forceMaxLight=true` 可绕过部分光照计算并让所有粒子全亮，但会改变场景意图。

## 光影兼容

源码检测 Iris 是否存在及光影包是否启用，并包含 Iris 最终合成阶段的兼容注入。OptiFine 类也会被检测，但实例化渲染器仍留有“OptiFine 光影启用时”的 TODO，不能据此承诺完整兼容。

遇到只在光影下出现的问题时，分别测试关闭光影、改用 `DEFAULT` 渲染类型、关闭渲染接管和切换半透明方式，记录最小复现组合。

## 已知风险

手动配置线程值时要保守：配置访问器允许的范围比部分底层管理器实际接受范围更宽，过大的值可能触发参数异常。设计器设置页只提供较小的常用值，优先使用界面选项。

模组对包含 `mp` 的命令执行路径使用虚拟线程优化。复杂 `execute`、大量目标与其他命令修改模组组合时，应在专用服务器验证命令顺序和线程安全，不要只依据单人预览。

## 部署检查

1. 先以 `VANILLA` 接管和低 `amount` 建立基线。
2. 分别测试无光影、Iris 光影和目标整合包渲染模组。
3. 观察客户端帧率、显存、内存和服务端网络流量。
4. 逐步增加寿命、发射周期与链深度，每次只改变一个变量。
5. 为公开演出保留能快速停止命令方块或函数调度的控制手段。
