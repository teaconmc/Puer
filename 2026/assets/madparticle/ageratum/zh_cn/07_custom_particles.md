# 自定义粒子纹理

## 本地目录

客户端在注册粒子类型时检查游戏运行目录下的 `customparticles` 文件夹。文件夹不存在时会创建后直接结束本次扫描，因此首次生成目录后，需要放入 PNG 并完整重启客户端。

这不是普通资源包热重载功能。运行中加入新文件不会补注册粒子类型，按 `F3+T` 也不能替代重启。

## 文件名到资源 ID

只扫描目录根部的 `.png` 文件，文件名应全部使用小写 ASCII：

| 文件名 | 注册粒子 ID |
|:---|:---|
| `spark.png` | `madparticle:spark` |
| `demo~spark.png` | `demo:spark` |

波浪号 `~` 代替资源 ID 的命名空间分隔冒号。没有波浪号时自动使用 `madparticle` 命名空间。无效资源名称会被跳过并写入日志。

## 多帧纹理

同一粒子的多帧文件使用连续编号：`spark#0.png`、`spark#1.png`、`spark#2.png`。当扫描到同名组的多个文件时，源码会按从 `0` 到“匹配文件数减一”逐个查找；缺号会导致相应帧缺失并记录错误。

不要把无编号的 `spark.png` 与 `spark#0.png` 混在同一组，也不要让一个粒子基础名只是另一个名称的子串。扫描使用文件名包含匹配，清晰且互不重叠的名称最可靠。

## 资源注入方式

模组为每个本地类型动态生成粒子 JSON，并把 PNG 注入客户端的 `textures/particle` 资源列表。动态类型自身的普通粒子提供器返回空；这些纹理主要作为 MadParticle 指令和设计器可复用的目标纹理。

单帧与多帧纹理仍受 `spriteFrom` 控制。多帧按年龄切换时使用 `AGE`，希望每个粒子随机挑选一帧时使用 `RANDOM`。

## 多人边界

动态注册类只在客户端环境订阅注册事件，专用服务器不会扫描这个文件夹，也不会向连接者下发 PNG。每个客户端都必须自行准备一致文件；额外客户端注册表项在专服环境中的同步兼容性也需要实机验证。

::: warning
不要把本地自定义纹理当作服务器资源包分发机制。公开服务器应优先复用双方已经注册的普通粒子，并在封闭测试中验证自定义 ID 后再部署。
:::

## 故障排查

未出现目标粒子时，依次检查：客户端是否完整重启、文件是否位于目录根部、扩展名是否为 PNG、名称是否小写且有效、多帧是否从 `#0` 连续编号。日志中的“invalid resource location”“failed to find texture”能区分名称错误与缺帧。
