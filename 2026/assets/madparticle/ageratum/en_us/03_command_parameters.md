# Command Parameters

## Command roots and permission

The short `/mp` command owns the actual argument tree; `/madparticle` redirects to it. Both require game-master permission. There is no short form that omits arbitrary middle arguments: every field from target particle through scale mode must appear in a fixed order.

## Fixed parameter order

The first group is:

| Order | Parameter | Purpose |
|:---:|:---|:---|
| 1 | `targetParticle` | Select a registered particle whose texture will be reused |
| 2 | `spriteFrom` | `RANDOM` selects frames randomly, `AGE` changes with age, and chains can inherit |
| 3 | `lifeTime` | Particle lifetime as a non-negative integer |
| 4 | `alwaysRender` | Whether to bypass the usual distance-based generation limit |
| 5 | `amount` | Number generated by each execution |
| 6 | `spawnPos` | World, relative, or local-coordinate spawn point |
| 7 | `spawnDiffuse` | Random X/Y/Z spawn-position error |
| 8 | `spawnSpeed` | Initial X/Y/Z velocity |
| 9 | `speedDiffuse` | Random error on each velocity axis |

Collision, forces, entity interaction, rendering, color, alpha, and scale follow. Omitting a field while writing by hand shifts every later value into the wrong argument, so routine editing should use the Designer.

## Spawn point and viewers

`spawnPos` accepts vanilla coordinate syntax. `spawnDiffuse` and `speedDiffuse` are signed random error around a base value, not fixed offsets. A high amount combined with a large diffuse range can cover a huge volume in one execution.

The command may end after all fixed arguments, in which case every player in the current dimension receives the packet. It may instead continue with a `whoCanSee` player selector. That selector controls network recipients and does not alter particle world coordinates.

## Texture and lifetime

The target particle primarily supplies texture data. MadParticle carries the final behavior through its own `madparticle:mad_particle` type. Multi-frame textures can select a random frame or advance with age.

Even without meta, lifetime has approximately `+/-10%` random error by default. Set the meta key `life` explicitly to `0` for an exact lifetime. The key is a percentage error limit, not extra ticks.

## Why use the Designer

The fixed sequence exceeds thirty arguments, and several fields can inherit from a parent inside an `expireThen` chain. The Designer preserves ordering, exposes enum choices, and previews continuously, making it more reliable than composing from chat completions. Save final command text in a function or version control because the Designer instance is not a project-file format.
