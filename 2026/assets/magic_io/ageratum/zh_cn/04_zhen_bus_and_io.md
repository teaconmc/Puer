# 阵总线与 IO

## 总线是干什么的

普通阵方块是一台有六个面的机器。**阵总线**则是一个**每面各挂一个处理器**的方块，因此单个方块位置可以运行最多六个互不相干的流程，并暴露六个互不相干的 IO 面。

总线上的一切都是逐面的：处理器、槽位访问映射，以及向相邻物提供的能力。

## 安装处理器

游戏内唯一途径是范例物品，见 [01 入门](01_getting_started)：

1. 手持 `example_item` 对空右键以选择一个面。
2. 右键总线，在该面安装一个**不稳定筛阵**。

安装时会使方块能力失效以便相邻方块立刻重新查询，并标记方块实体需要客户端更新——因此管道与漏斗无需重新放置即可识别新的面。

这里有一处值得记录的曲折。范例物品请求的阵型是 `magic_io:unstable_sieve`，而实际注册的 ID 是 **`magic_io:unstable_sieve_zhen`**——它请求的那个 ID 并不存在。它仍然能工作，因为阵型查找在未命中时会**回退**到不稳定筛阵，而回退逻辑查找的正是正确的 `unstable_sieve_zhen`。结果与意图一致；只是它是经由回退路径而非成功查找达成的。

## 三种 IO 类型

| IO 类型 | 显示 | 说明 |
|:---|:---|:---|
| `item` | Item | 基于槽位，逐面的插入与提取集合 |
| `fluid` | Fluid | 基于储罐，容量由阵型声明 |
| `energy` | **FE** | 基于处理器句柄，不基于槽位 |

能量是特例，而且是刻意的：物品与流体的访问要按「该面暴露了哪些槽位」过滤，而能量访问**完全跳过槽位检查**，只要处理器有能量组件就直接交出句柄。因此能量连接不需要配置面的槽位映射。

## 相邻方块实际看到什么

普通阵方块与阵总线都暴露原版风格的能力，因此其他模组的普通管道、漏斗与线缆都能与它们交互。

对**普通阵方块**，逐面：

- **物品** —— 只有当该面至少有一个插入或提取槽位时才提供句柄。句柄被绑定到「该面槽位」与「方块输入/输出集合」的交集，因此一个面可以是只输入、只输出，或两者兼具。
- **流体** —— 只有当阵型声明了储罐容量且该面有流体槽位时才提供。
- **能量** —— 只要方块有能量组件就提供，**不受面限制**。

对**阵总线**，同样是这三种，但要先经由**该面的处理器**解析：该面没有处理器就意味着该面完全没有任何能力。

在所有情况下，以 null 方向发起的能力请求都返回空。这些方块**没有「无方向」访问**——你必须连接到具体的某个面。

## 槽位区

面在配置中不引用裸槽位号，而是引用**命名区**，例如物品输入全体、物品输出全体、流体输入全体、流体输出全体。默认访问映射给**全部六个面**同时授予物品区与流体区，默认物品布局是一个输入槽加一个输出槽。

读配方时这一点很重要：配方的 `inputs` 与 `outputs` 是以这些同名区来索引的，而不是槽位下标。见 [05 配方](05_recipes)。

## 变更通知

每个句柄都会安装一个变更回调，通知其 IO 组件并把方块实体标记为脏。这正是外部自动化能保持同步的原因——漏斗的一次插入会传播到机器自身的记账中，而不需要轮询。

## 这里没有的东西

- **没有 GUI。** 阵方块与总线都没有注册任何菜单类型，因此没有界面可开、没有槽位布局可点、也没有游戏内的面访问配置。一切都靠外部的范例物品、漏斗与管道完成。
- **除范例物品外没有扳手或配置工具**，而范例物品只能装不稳定筛阵。
- **没有用于 IO 的网络包** —— 只存在一个配方同步载荷，见 [05 配方](05_recipes)。

装了 Jade 之后，你至少可以靠看一眼来**读取**总线的物品与流体内容，这是本模组目前最接近检视界面的东西。
