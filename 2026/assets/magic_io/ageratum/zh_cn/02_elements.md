# 元素

模组自有注册表中注册了十六种元素类型。它们不只是标签——其中十二种在**声明时就由更早的元素组合而成**，构成一棵与阵方块层级结构相呼应的合成树。

## 四种基础元素

| 元素 | ID |
|:---|:---|
| 土 | `earth` |
| 水 | `water` |
| 风 | `wind` |
| 火 | `fire` |

这四种没有父元素。

## 派生的十二种

| 元素 | 由什么组成 |
|:---|:---|
| 木 | 土 + 水 |
| 冰 | 水 + 风 |
| 金 | 火 + 土 |
| 雷 | 风 + 火 |
| 序 | 木 + 金 |
| 空 | 冰 + 木 |
| 时 | 金 + 雷 |
| 混 | 雷 + 冰 |
| 述 | 混 + 序 |
| 能 | 空 + 时 |
| **魂** | 雷 + 土 + 能 |
| **创** | 述 + 能 + 魂 |

其中有两种取**三个**父元素而非两个——魂与创——这明确把它们置于树的顶端。

请注意显示名：ID 为 `consciousness` 的元素在游戏内显示为 **「Soul」（魂）**，而不是「Consciousness」。若你在读日志或写数据包，ID 是 `consciousness`；若你在看界面，它写作魂。

## 把这棵树读作进度线

这棵树与 [03 阵层级与阵型](03_zhen_tiers_and_types) 中的层级门槛是对齐的：

| 深度 | 元素 | 首次出现的阵层级 |
|:---|:---|:---|
| 基础 | 土、水、风、火 | 层级 0 与 10 的功能 |
| 第二层 | 木、冰、金、雷 | 层级 10 与 20 的功能 |
| 第三层 | 序、空、时、混 | 层级 30 的功能 |
| 第四层 | 述、能 | 层级 30 与 40 的功能 |
| 第五层 | 魂 | 层级 40 |
| 顶点 | 创 | 层级 50 —— 唯一的 `creative` 阵 |

因此一个阵所绑定的元素能可靠地指示它在进度中的深度。唯一的 `primeval_creative_zhen` 是唯一绑定「创」元素的方块，也是唯一在层级 50 引入的功能。

## 元素在机制上做什么

每个阵型在注册时携带且仅携带一种元素。元素是阵的**身份标识**而非可消耗资源——当前构建中没有元素燃料、没有元素储存、也没有元素伤害类型。请把元素当作模组的**分类与进度轴**，而不是可以用管道输送的流体。

每种元素都有形如 `element_type.magic_io.<id>` 的翻译键，全部十六种在两份随包语言文件中均已翻译。

## 一处值得知道的查找细节

元素查找辅助函数被刻意写得宽容：遇到未知名称、null 值或无法解析的 ID 时，它**返回「土」**而不是报错。这是合理的安全网，但也意味着数据包里的拼写错误不会产生任何错误提示——它会静默地产生一个「土」元素的结果。如果某个阵表现得像一台土元素机器而你预期的是别的，请先检查你的 ID。
