# 变换工具

工具就是这个模组的真正内容。它们共享同一套约定，一旦你掌握了它，整套工具就变得可预期。

## 通用约定

每件变换工具都遵循同样的双手模式，提示文本里写得很明确：

| 手 | 动作 |
|:---|:---|
| **主手** | 右键载体方块，把调整**应用**到选中的那一层 |
| **副手** | 右键**切换工具模式** |

`pos_trans_item` 自己的提示就直说了：*「主手：右键[实体方块]以调整选中[层]的偏移」*，以及*「副手：右键切换工具模式（共 3 种）」*。

模式会以带颜色的文字显示在动作栏——`pos_trans_item` 循环 **§cMode:X 轴 → §AMode:Y 轴 → Mode:Z 轴**，所以你总能知道自己即将移动哪个轴。

::: tip
提示文本还告诉你**用 F3 来确认该调哪个轴**。调试覆盖层的轴向读数是避免「连着三次把部件挪错方向」的最快办法。
:::

## 工具清单

| 工具 | 注册 ID | 调整什么 |
|:---|:---|:---|
| 层位移器 | `yuushya:pos_trans_item` | 位置，普通步长 |
| 微调位移器 | `yuushya:micro_pos_trans_item` | 位置，精细步长 |
| 旋转器 | `yuushya:rot_trans_item` | 旋转 |
| 缩放器 | `yuushya:scale_trans_item` | 大小 |
| 槽位工具 | `yuushya:slot_trans_item` | 你正在编辑**哪一层** |
| 变换搬运器 | `yuushya:move_transformdata_item` | 在载体之间复制变换数据 |

`pos_trans_item` 与 `micro_pos_trans_item` 的分工，就是「把部件粗调到位」与「收尾精修」的区别。**先用粗的那个。**

## 层

一个载体同时容纳多个外观，而 `slot_trans_item` 决定其他工具作用于哪一个。这是所有复合建造背后的机制：一张桌子是「台阶层 + 桌腿层」共处一个方块，你用槽位工具在它们之间切换，而不是放两个方块。

层集合及其变换存在 `TRANSFORM_DATA` 数据组件里，这正是它们能在中键取方块后存活、并能被 `move_transformdata_item` 整体复制的原因。

## 捕获外观

| 工具 | 用途 |
|:---|:---|
| `get_blockstate_item` | 从世界里把一个 **blockstate** 复制到手上，待应用 |
| `get_showblock_item` | 抓取某个已有展示方块实体的整套配置 |
| `shape_item` | 操作 `SHAPE_DATA` 组件 |

`get_blockstate_item` 是大多数工作的入口——对准世界里任何方块，它的精确状态就成了你能给载体穿上的东西。

## 撤销与检视

| 工具 | 用途 |
|:---|:---|
| `history_item` | 打开**历史菜单**——回退修改 |
| `gui_item` | 直接打开载体的编辑界面 |
| `debug_stick_item` | 模组自带的 blockstate 调试棒 |
| `destroy_item` | 移除工具，**384 耐久**——全套里唯一有耐久的物品 |

历史菜单是能救回建造的那一个。自由变换意味着很容易调过头，而 `history_item` 就是既定的恢复途径，而不是从头重建。

## 为什么所有工具都只能堆叠 1 个

每件工具都是 `stacksTo(1)`，因为每件都携带**逐物品的状态**——当前模式，有时还有捕获的数据。物品栏里两把同款工具就是两把模式独立的工具，这其实很有用：**一把位移器设成 Y 轴，另一把设成 X 轴。**
