# Getting Started

## Creative tab

Everything lives in one tab, `craton:core`, whose icon is the gneiss base block. Its contents are generated by iterating every rock type, then every finish within it, emitting the family's base block, all of its variants, and finally the vertical slab.

## The six rock types

| Rock | Map colour |
|:---|:---|
| `gneiss` | stone |
| `rhyolite` | red |
| `marble` | quartz |
| `limestone` | sand |
| `gabbro` | black |
| `pegmatite` | pink |

## Four finishes per rock

Each rock type is registered as **four separate block families**:

| Finish | Id pattern | Extras |
|:---|:---|:---|
| Raw | `<rock>` | pressure plate **and** button |
| Polished | `polished_<rock>` | — |
| Brick | `<rock>_brick` | pressure plate only |
| Mossy brick | `mossy_<rock>_brick` | — |

Note the asymmetry: only the **raw** finish gets a button, and only raw and brick get a pressure plate. Polished and mossy brick are the plain finishes.

## What each family contains

Every one of the 24 families registers the same core set:

- base block
- `_stairs`
- `_slab`
- `_wall`
- `_vertical_slab`

So a single rock such as limestone yields `limestone`, `limestone_stairs`, `limestone_slab`, `limestone_wall`, `limestone_vertical_slab`, `limestone_pressure_plate`, `limestone_button`, then the same shape set again for `polished_limestone`, `limestone_brick` (plus its pressure plate) and `mossy_limestone_brick`.

## Block properties

All base rocks share the same behaviour: strength **1.5 / 6.0**, `requiresCorrectToolForDrops`, stone sound type, and the map colour listed above.

## Vertical slabs

`VerticalSlabBlock` is Craton's own block class, and every family gets one. Two tags exist for them:

- `craton:vertical_slabs` (block tag)
- `craton:vertical_slabs` (item tag)

These are the mod's **only** tags.

## Stonecutter recipes

Each family is built with `generateStonecutterRecipe()`, so the standard vanilla family recipe set — including stonecutting — is produced by the data generator rather than hand-written JSON.

Because these recipes come from the vanilla `BlockFamily` pipeline and this documentation set only references recipe ids that were individually verified, no recipe component is embedded here. Use the recipe book or a recipe viewer in game to see the exact cutting and crafting outputs.
