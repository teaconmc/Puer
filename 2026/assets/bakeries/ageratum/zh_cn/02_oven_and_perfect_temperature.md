# 烤炉与完美火候

这是整个模组围绕建立的机制，在烘焙任何东西之前值得先弄懂。

## 烤炉用鼠标滚轮控制

打开烤炉，界面告诉你两件事：

```
container.bakeries.oven.temperature = 当前温度
container.bakeries.oven.rolling     = 滚动鼠标中键调节温度
```

**温度是你用滚轮拨定的连续设置**，不是燃料量，也不是固定时长。调节过程中烤炉会显示当前数值。

::: info
这正是本模组不只是「一个更花哨的熔炉」的原因。熔炉只有一种行为；这个烤炉有一个区间，同一份面胚放在区间的不同位置会给出不同结果。
:::

## 配方声明最低温度

物品提示文本携带这个要求：

```
tooltips.bakeries.row_item_temperature = Min %s °c
```

因此每种可烘焙物都有一个下限——低于它烘焙就得不到预期结果。这个下限是机制里容易的那一半。

## 完美火候是难的那一半，而且有真实回报

在仅仅达到最低温度之外，命中正确区间会产出带**完美火候**词条的食物：

```
tooltips.bakeries.pile_item_perfect = 完美火候
```

而手册明确说明了这个词条的作用：

::: tip
**「拥有完美火候词条的烘焙食物，在玩家饥饿值满时也能食用。」**

这是真实的机制性收益，不是装饰性标签。普通食物在饱食状态下会被拒绝，完美火候食物不会。它把细致烘焙变成了**储备可用的治疗手段**，而不只是做出更好看的面包。
:::

## 两个进度追踪它

| 进度 | 描述 |
|:---|:---|
| **精准控温** | 「在烤炉中」 |
| **完美火候** | 「温度更精确，食物会更美味。」 |

这个配对正是设计好的学习曲线：先知道烤炉有温度这回事，再学会精确落点。

## 怎样才真能命中

模组不在提示文本里给出目标区间——只给最低值。区间本身是手册内容，这正是登录消息坚持要你装 Patchouli 的具体原因。

实操上：

1. 在 **Baking Guide** 里读你要烘焙那件物品的条目。
2. 放入之前先滚到所述温度。
3. 检查产物提示文本里有没有**完美火候**那一行。
4. 若没有，说明你达到了最低值但错过了区间——调整后重试。

::: warning
**最低值与完美区间是两个不同的数字。** 提示文本上的 `Min %s °c` 只是下限。恰好按最低温度烘焙，会稳定地产出物品，也会稳定地**不**产出完美火候词条。任何只读提示文本的人都会得出「这个机制没生效」的结论。
:::

## 手册为它单设了一个分类

手册里有专门的分类：

```
guide.bakeries.categories.perfect_temperature = §6完美火候
```

金色（`§6`）、与普通配方分类分开——作者把它当作头号特性对待，本组页面也同意。
