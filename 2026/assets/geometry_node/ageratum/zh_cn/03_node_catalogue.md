# 节点目录

约 **295 个节点类**，按分类体系而非扁平列表组织。本页列出整个结构与每个类别的规模，好让你在标签不可读时也能找到正确的抽屉。

此处**不**逐个记录节点——原因见文末的覆盖说明。

## 五种顶层类别

| 类别 | 节点数 | 作用 |
|:---|---:|:---|
| **动作** | 约 111 | 改变世界 |
| **事件** | 约 74 | 响应发生的事 |
| **数据** | 约 55 | 读取数值 |
| 逻辑、数学、函数 | 约 22 | 分支与计算 |
| 对话 | 6 | 会话流程 |

一张能用的图几乎总是从左到右穿过那三大类：**事件**触发，**数据**与**逻辑**判断，**动作**发生。

## 动作——最大的一组

| 类别 | 节点数 |
|:---|---:|
| 实体 | **42** |
| 物品 | 17 |
| 玩家 | 10 |
| 展示实体 | 9 |
| 物品栏 | 9 |
| 方块 | 7 |
| 视觉 | 6 |
| 世界 | 4 |
| AI | 4 |

**实体动作支配着整个模组**——42 个节点，多于任何其他地方的任何类别。若你要做任何涉及移动、伤害、生成或修改生物的东西，深度就在那里。

**展示实体**拥有自己的九个节点值得注意：展示实体是原版用于悬浮模型与文字的功能，因此模组把世界内的视觉呈现当作一等领域，而不是把它塞进通用实体动作里。

**AI** 只有四个节点则说明了反面——生物行为脚本存在，但与直接操纵实体相比很浅。

## 数据——读取状态

| 类别 | 节点数 |
|:---|---:|
| 实体属性 | **23** |
| 类型 | 10 |
| 容器 | 9 |
| 数值 | 5 |
| 实体 | 2 |
| 玩家 | 1 |
| 世界 | 1 |

**实体属性是这里的意外之处。** 二十三个用于读取实体属性——生命、速度、护甲等等——的节点使它成为模组第三大类别。再加上 42 个实体动作，图景就很清楚：**这首先是一个给生物写脚本的工具。**

九个**容器**节点覆盖读取箱子与物品栏，这正是物品物流逻辑得以成立的原因。

## 逻辑、数学与函数

| 类别 | 节点数 |
|:---|---:|
| 逻辑 | 7 |
| 数学——向量 | 3 |
| 数学——运算 | 2 |
| 函数——颜色 | 3 |
| 函数——图 | 3 |
| 函数——时间 | 2 |
| 特殊 | 1 |

这是刻意做小的部分。七个逻辑节点与五个数学节点足以做分支与算术，但不足以做繁重计算——模组期待你通过庞大的动作与事件词汇来表达意图，而不是靠计算。

**函数——图**这三个很有意思：它们是对图本身进行操作的节点，也就是一张图调用或组合另一张图的方式。

## 覆盖说明

::: info
**本页记录的是目录的结构，而不是它的 295 个具体节点。**

两个原因。第一是规模：逐个说明每个节点的端口与语义，单这一个模组就会写成数百页。第二个更具决定性：**其中 275 个节点名只存在于中文**，因此一份逐条列出它们的英文页面等于在列举未翻译的键——准确但无用。

此处记录的内容可从源码核验且稳定：每个类别都存在，且数量精确。相对规模才是真正有用的信息，因为它告诉你模组在哪里深（实体、实体属性、玩家事件）、在哪里浅（AI、数学）。

要浏览实际节点，请打开编辑器并沿类别树逐层查看。把游戏语言设为简体中文时，名称是完整的。
:::
