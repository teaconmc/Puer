# 技术说明

## 注册表

| 类别 | 数量 |
|:---|---:|
| 附着类型 | 1 个注册器 |
| 物品、方块、实体、菜单、创造分类 | **0** |
| 配方、战利品表、标签 | **0** |
| Mixin | **1** |

模组与原版唯一的注册表交互是一个附着类型。其余一切——编辑器、节点运行时、对话、商店——都活在它自己的系统里。

**587 个文件里只有一个 mixin，是相当难得的克制。** 它修补弹射物命中，且 mixin 配置为 overwrites 设了 `requireAnnotations`，说明作者主动选择了比默认更严格的校验。对这个体量的模组而言，只在一处触碰原版是有意的架构决定。

## 配置是 JSON 而非 TOML

与多数 NeoForge 模组不同，配置是一份普通 JSON 文件而不是 NeoForge 的 TOML 规格：

| 分区 | 设置 | 默认值 |
|:---|:---|:---|
| `viewport` | `gridSize` | 15 |
| `node` | `cornerRadius` | 1.5 |
| `assetBrowser` | `quickAccessPaths` | *见下文* |
| — | `version` | 1 |

该文件带有 `version` 字段，因此它被设计为可迁移而非重置——这是作者预期它会增长的迹象。

请注意**完全没有服务端或玩法配置**。每一项设置都是编辑器偏好。

## 随包配置里是作者本人的路径

::: warning
仓库中随包的 `quickAccessPaths` 是：

- 一条指向原作者 IDE 工程目录的绝对路径
- `C:\`
- `D:\`
- `E:\`

第一条在任何其他机器上都无意义。由此有两点：**请把这些路径换成你自己的**；并且请注意这份文件是从一个工作环境中提交的，而不是干净生成的。

那条开发者路径还记录了工程的历史——它指名的是一个 **1.21.1** 的 ModernUI 分支，而本构建面向 26.1.2。模组是向前移植过来的。
:::

## 翻译覆盖率是模组最大的实际问题

| 文件 | 键数 |
|:---|---:|
| `en_us.json` | 138 |
| `zh_cn.json` | 543 |

差额的构成：

| | 键数 |
|:---|---:|
| 两者共有 | 114 |
| **仅中文** | **429** |
| 仅英文 | 24 |

而这些仅中文的键是什么：

| 前缀 | 仅中文键数 |
|:---|---:|
| `geometry_node.node.*` | **275** |
| `geometry_node.port.*` | 53 |
| `geometry_node.shop.*` | **38** |
| `geometry_node.menu.*` | 31 |
| `geometry_node.common.*` | 6 |

**缺失的翻译正是内容本身。** 275 条节点条目与 53 条端口条目没有英文文本，因此节点浏览器与端口标签——你在使用编辑器时不断阅读的两样东西——都会回退到原始键。整个商店界面没有翻译。

这不是外观上的缺口，而是「可用的工具」与「无标签的工具」之间的差别，也是 [01 开始使用](01_getting_started) 建议以中文运行游戏的原因。

## 两份语言文件都含分隔条目

一个会略微抬高上述计数的怪癖，若你自己数键则值得知道：两份文件都用假条目作为视觉分节。

- `zh_cn.json` 中有形如 `--- ACTIONS/WORLD ---`、`--- DATA/ATTRIBUTION ---`、`--- CLIENT ---` 的条目
- `en_us.json` 中有三个**中文命名**的键——`菜单`、`1级菜单`、`2级菜单`——其值是一排 `=` 字符

它们无害，因为没有任何游戏键与之匹配，但这意味着原始键数比真实翻译数高出几条。中文命名的分隔条目出现在*英文*文件里，是这些文件当初组织方式留下的痕迹。

## 命令权限

只有一条命令有门槛，而它的门槛是正确的：`/geometry_node debug area` 要求 **gamemaster** 权限。

图相关命令（`graph_bind`、`graph_unbind`、`graph_list`、`graph_download`）注册时没有显式权限要求。在不希望玩家自行重绑图的服务器上，请用外部手段限制它们。

## 网络

四个数据包处理远程图——列表的请求与响应一对，下载的请求与响应又一对。两者都以带命名空间的标识符规范定义。

## 元数据

| 字段 | 值 |
|:---|:---|
| 模组 ID | `geometry_node` |
| 版本 | 1.0.0 |
| 许可证 | **保留所有权利（All Rights Reserved）** |
| 组 ID | `com.mine.geometry_node` |
| Minecraft | `[26.1.2]`——单一精确版本 |
| NeoForge | 26.1.2.75 |
| 必需依赖 | ModernUI（客户端）、Architectury（双侧） |

模组 ID 在**四个来源中一致**。元数据文件使用 `${mod_id}` 占位符，这意味着构建属性确实在为它供值——值得说明，因为这一点并非总是成立。
