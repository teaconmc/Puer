# 让图在世界中运行

编辑器里的图什么都不做。本页介绍图抵达游戏的四种途径。

## 绑在按键上的蓝图

模组在自己的按键分类中注册了**十个蓝图按键**，且**全部默认未绑定**。在「按键控制」中绑定它们，每一个就成为你可以从中释放一张图的槽位——实际上是一条自定义技能栏。

这是最直接的途径：搭好一张图、放到某个蓝图槽、按下按键。

## 绑定一张图

有四条命令管理图与世界之间的关系：

| 命令 | 用途 |
|:---|:---|
| `/graph_bind` | 挂上一张图 |
| `/graph_unbind` | 解除挂载 |
| `/graph_list` | 列出可用的图 |
| `/graph_download` | 从服务器拉取一张图 |

请注意 `graph_list` 被注册了**两次**——一次作为客户端命令、一次作为服务端命令——因此模组既能列出你本地持有的，也能列出服务器提供的。

`/graph_download` 背后有一对规范的请求-响应数据包，列表也有配套的一对。这意味着**服务器可以托管一个共享图库**，玩家把它们拉到自己的编辑器里，而不必手动传文件。对建筑服或冒险地图而言，这就是预期的分发路径。

## 区域调试

有一条命令位于模组自己的根下，也是唯一带权限门槛的一条：

```
/geometry_node debug area on [半径]
/geometry_node debug area off
```

半径接受 **1.0 到 2048.0**，省略时有内置默认值。

**该命令要求 gamemaster 权限。** 这点值得作为优点指出：本批中许多模组注册的命令树完全没有 `requires` 子句，任何人都能执行。而这里的调试命令有正确的门槛。

它的作用是可视化**区域事件**——那个依据区域触发的唯一事件节点——好让你看见图正在判定的那块区域，而不是靠猜。

## 对话

对话子系统有六个节点、自己的事件、自己的渲染器，以及带 **`choose`** 与 **`close`** 子命令的独立命令根。

形态与你预期的一致：图呈现台词、提供选项，玩家的选择把执行导向某条分支。`choose` 提交一个选项、`close` 关闭会话，这意味着对话既能由点击驱动、也能由命令驱动——用于测试会话树时不必真的走到 NPC 面前。

对话渲染器会替换当前界面并在结束时恢复上一个界面，因此会话可以打断你正在看的任何东西，并干净地把控制权交回。

## 商店

存在一套商店系统，带自己的菜单与一个游戏内**编辑器覆盖层**。交易条目以 id 标识，若某条目没有显式 id 则会依其序号生成一个——因此商店是一份你就地编辑的条目列表，而不是一份你手写的数据文件。

::: warning
**商店系统有 38 个翻译键，其中没有一个是英文的。** 全部 38 条只存在于 `zh_cn`。商店功能完整，但它的界面在英文客户端上没有标签——这是受 [05 技术说明](05_technical_notes) 所述翻译缺口影响最严重的子系统。
:::

## 图存放在哪里

图是**磁盘上的文件**，通过编辑器的资源浏览器浏览。它们不是世界数据，这带来两个后果：

- 一张图是**可移植的**——你可以把文件复制到另一个世界，或发给别人。
- 一张图**不属于你的存档**，因此备份世界并不会备份你的图。

结合下载命令，预期的流程是：本地创作、发布到服务器、让玩家拉取副本。
