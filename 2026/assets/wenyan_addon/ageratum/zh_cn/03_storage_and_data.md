# 存储与数据

有两项内容负责持久化，它们也是 `wenyan_addon` 命名空间里唯一带状态的东西。

## 符咒收納櫃

`wenyan_addon:storage_rune_block`，包名 `「納」`。

其提示文本称它是「用來存儲包含物品、方塊等數據的符咒的櫃子」。它是**本命名空间唯一带方块实体的方块**，正是这一点让它能跨存档与区块卸载保留内容。

它**仅限方块形态**——见 [02 设备方块](02_device_blocks)。把柜子作为物品携带不会向脚本暴露 `「納」`，必须放置出来。

## 數據磁盤

`wenyan_addon:data_disk`，本命名空间唯一的非方块物品。

- **最大堆叠为 1**，因此每张磁盘都是独立个体，而非可计数的资源。
- 其提示文本称它「用持久化儲存資料，包括方塊，物體的數據」。
- 它本身不是带包名的设备，而是存储系统读写的介质。

模组为它配套了 JSON 编解码与世界快照映射代码，这与「能捕获结构化世界数据而非仅作物品缓冲」的定位相符。具体某个文言版本往磁盘里写什么由母模组的脚本 API 决定，因此请把磁盘内容视为**与版本绑定**——README 关于数据格式可能在版本间变化的警告，最直接适用于此处。

## 那个写进母模组命名空间的标签

本附属生成了一个位于**自身命名空间之外**的数据文件：

```
data/wenyan_programming/tags/item/paper_module_item.json
```

该标签列出了全部 **18** 项——17 个方块物品加 `data_disk`——好让核心模组把它们全部识别为可用的纸模块。由此有两个后果：

- **这个标签就是集成接缝。** 如果未来某个核心模组版本重命名或移动了该标签，本附属的全部设备会同时不再被识别，即使 `wenyan_addon` 自身毫无改动。
- 由于该文件未设置 `replace`，它会与 `wenyan_programming` 在同一路径下自带的内容**合并**而非覆盖。想从模块清单中移除某个设备的数据包必须覆盖合并后的标签，而不是删掉这个文件。

`example_block` 与功能设备一同被列入该标签，因此这个参考范例对玩家而言也是一个普通模块。

## 这里没有的东西

- **没有配置。** 没有注册任何配置类，也从不生成配置文件——尽管语言文件里存在三个配置界面翻译键。见 [05 本地化与限制](05_localization_and_limits)。
- **没有命令。**
- **没有自己的网络包** —— 一切都经由母模组的脚本运行时传递。
- **没有 Mixin，也没有访问转换器**（模组元数据中这两个块都被注释）。

这种「什么都没有」恰是重点：本附属添加的是**供他人解释器使用的能力**，而不是自成一体的系统。
