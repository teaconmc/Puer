# 本地化与限制

## 两份语言文件都是中文

每个命名空间都随包提供 `en_us.json` 与 `zh_cn.json`，而且每一对在**键层面完全匹配**——`wenyan_addon` 两边各 57 键，`pong` 两边各 17 键，没有任何键只存在于一边。按这个标准，本地化是完整的。

但**值也完全相同**：全部 57 条与全部 17 条字符串在英文与中文文件中逐字一致，而且全都是**中文文本**。

实际结果是：

- **英文客户端看到的是中文名称与提示**，而不是英文。
- 由于 `en_us` 是回退语言，**其他任何语言也都会回退到中文**。
- 因此尽管存在 `en_us.json`，**实际上没有英文本地化**。

## 两个命名空间用了不同的汉字字形

- **`wenyan_addon` 使用繁体中文** —— 範例石、附靈石、實體召喚石、藥水石、符咒讀寫石、微塵石。这与母模组的文言主题相称。
- **`pong` 使用简体中文** —— 香槟瓶、香槟刀、香槟杯、调试棒。

于是同一个分页里混排着繁体的设备石与简体的香槟物品。在 `wenyan_addon` 内部还有 [02 设备方块](02_device_blocks) 中提到的標記石不一致：方块名是 標記石，而脚本包名却是 `「标」`。

## 孤儿资源与死代码

| 项目 | 状态 |
|:---|:---|
| 3 个 `wenyan_addon.configuration.*` 键 | **孤儿** —— 没有配置类、没有 `registerConfig`，因此配置文件与配置界面都从不存在 |
| `pong_1.ogg` 及其 `sounds.json` 条目 | **孤儿** —— 未注册声音事件，无任何东西播放它 |
| `ChampagneTower` 类 | **死代码** —— 从未被引用或注册 |
| `pong:debug_rod` | **已注册但隐藏** —— 不在分页、无配方，仅 `/give`；自述为开发工具 |
| `example_block` | **有意的范例** —— 已注册、已入标签、已入分页，但唯一处理器只写一行日志并返回空 |

这些都不会破坏游戏。它们之所以值得记录，是因为从外部看很像功能：一个有名字却不存在的配置界面、一个永不播放的第二声音，以及一个暗示着从未接线的机制的塔类。

## 基岩的副作用

如 [02 设备方块](02_device_blocks) 所述，范例能力同时被挂到了 `minecraft:bedrock` 上，使基岩也暴露 `「example」` 包。这本身无害，但提醒我们：本附属演示技法的成分与提供内容的成分同样重。

## 实验性定位的实际含义

README 没有丝毫回避，本页同样不回避：

- **版本之间预期会破坏兼容。** 更新后存档、配置、脚本或代码可能需要手工调整。
- **功能可能被移除。** 此处记录的任何内容都可能被并入 `wenyan_programming` 正式版、被更改，或被丢弃。
- **设备集合是最易变的部分。** 像 `「移形」`、`「藥」` 这样的包名是你的脚本所依赖的契约，而它们恰恰也是「并入核心模组」时最会被搬走的东西。

具体来说，在你珍惜的世界上更新本附属之前：

1. 记下你的脚本用到的包名。
2. 记住 **`「納」` 与 `「染」` 只在放置为方块时有效**，因此某个脚本忽然失效，可能只是因为设备被捡了起来。
3. 预期数据磁盘的内容是你手上最不具可移植性的东西。
