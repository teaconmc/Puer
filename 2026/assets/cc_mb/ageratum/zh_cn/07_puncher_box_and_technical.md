# 打孔盒与技术说明

## 打孔盒用红石打孔

打孔盒装着一条音符纸带，并在红石信号**上升**时向它写入。**信号强度就是指令**：

| 信号强度 | 动作 |
|:---|:---|
| **1** | 前进到下一拍但**不打孔** —— 即一个休止 |
| **2 – 15** | 前进到下一拍并打上音高 **强度 − 2** |

因此强度 2 打音高 0、强度 3 打音高 1，依此类推。对盒子使用**锥子**可读取它当前的位置与状态。

这把作曲变成了一个红石问题：一串受控强度的脉冲即可自动写出旋律，而由比较器驱动的循环能在不点一次鼠标的情况下转写重复乐句。

### 音高上限是真实存在的

红石强度止于 15，而最低的打孔值是 2，因此打孔盒只能触及**音高 0 到 13**。而音符纸带支持 **25** 个音高。

**最高的十一个音高（14 到 24）完全无法由红石打出。** 用到它们的作品必须在穿孔台上手工补完，或者写在书里。这是信号编码方式的固有后果而非疏漏，但它是设计自动作曲机时首先要规划的一点。

## Mixin

两个，且都各有明确用途——这里没有空壳脚手架。

| Mixin | 端 | 作用 |
|:---|:---|:---|
| `MixinMob` | 双端 | 一个访问器，暴露生物的环境音，供声音引诱逻辑使用 |
| `MixinSoundEngine` | 客户端 | 对模组自己的声音实例**跳过原版音高计算** |

第二个在音乐上很关键。原版会把音符盒音高限制在自己的两个八度范围内；通过对自己的声音跳过该计算，模组让**完整的 25 个音高 × 五档八度偏移**得以真正正确发声，而不是在极端处被压平。作者在 Mixin 内注明了这个理由。

## 数据组件

| 组件 | 承载者 | 内容 |
|:---|:---|:---|
| `cc_mb:notes` | 音符纸带 | 打孔图样 |
| `cc_mb:tick_per_beat` | 锥子、八音盒 | 速度，1–20 |
| `cc_mb:sound_info` | 声响碎片 | 声音事件加一个可选种子 |

三者都持久化且网络同步，因此一切都能经受存放、传递与死亡掉落。

## 两处炼药锅交互

模组在原版炼药锅上注册了行为，这一点很容易被忽略：

| 炼药锅 | 物品 | 结果 |
|:---|:---|:---|
| **水** | 纸 | 16 个纸浆，并降低锅内水位 |
| **粉雪** | 装有声音的碎片 | 擦除所录声音 |

## 打包事实

| 关注点 | 数值 |
|:---|:---|
| 版本 | `0.5.4` |
| 许可 | **GPL-3.0** |
| Minecraft | `26.1.2`，单一精确版本 |
| NeoForge | `26.1.2.36-beta` |
| Logo | `cc_mb.png`，**存在且正确** |
| 命令 | 无 |
| 配置文件 | **完全没有** —— 无配置类，也无可配置项 |
| 本地化 | 英文与中文**各 42 键**，键集完全一致 |

「没有配置」在这里值得正面记录：所有可调之处——速度、八度、乐器、声音——都是你在世界中交互的实体对象，而不是要去编辑的文件。

## 完整性核对

考虑到本批很多模组都有缺口，这里给出对照：

- **8 个配方对应 8 个已注册物品与方块** —— 一切皆可合成。
- **4 个战利品表对应 4 个方块** —— 一切皆可挖回。
- **8 个进度**，全部是配方解锁。
- **零孤儿翻译键。** 创造分页复用八音盒自身的名称键而不另行声明，因此常见的 `itemGroup` 孤儿问题不可能出现。
- **没有未注册内容、没有死物品类、没有缺失贴图。**

唯一需要向玩家说明的实质限制，就是上文所述打孔盒的音高上限。
