# 选项列表与操作

选项列表在每一帧 HUD 渲染时都会重新构建。它读取准星当前指向的目标，收集为该目标注册过的交互，并按注册顺序绘制。

## 什么会被当作目标

- 命中方块时提供方块坐标，模组按该坐标处方块的注册表 ID 查找交互。
- 命中实体时提供实体，模组按实体类型的注册表 ID 查找交互。
- 落空、世界为空、玩家为空，或有任何界面处于打开状态，都会清空列表且不绘制任何内容。

由于方块查找按命中位置的方块 ID 进行，为 `minecraft:oak_door` 注册的交互会作用于世界中的每一扇橡木门，而不是某一处特定放置。

## 操作方式

| 输入 | 效果 |
|:---|:---|
| 交互键（默认 `F`） | 执行当前选中的选项 |
| 鼠标滚轮上滚 | 选择上移，到顶后循环 |
| 鼠标滚轮下滚 | 选择下移，到底后循环 |
| 按住 Ctrl（macOS 为 Command） | 强制显示全部已注册选项，包括你无法使用的 |

选中行以黄色绘制，并附带一个小的按键帽渲染，显示当前交互键的绑定，因此改键后屏幕上也会同步反映。

::: warning
当你看向的目标拥有**两个及以上**选项时，鼠标滚轮会被选项列表占用并取消该事件，此时无法用滚轮切换快捷栏。只有一个选项时不会占用滚轮。
:::

## 与原版按键的冲突

默认的 `F` 键同时也是原版的「与副手交换物品」键。一个客户端 mixin 包裹了原版按键处理中的一次 `consumeClick()` 调用（第十次，序号 `9`），并在同时满足以下两个条件时强制其返回「未点击」：

- 被检查的按键与交互键绑定为同一个键；
- 选项列表当前至少有一项。

实际效果是：当选项显示在屏幕上时，按交互键执行的是交互，而**不是**同时触发该键上的原版动作。没有选项显示时，原版动作照常工作。在「控制」中重新绑定交互键也完全受支持。

## 可用与锁定的选项

每个交互都带有一个条件。构建列表时，每一项都会针对当前玩家与目标进行测试：

- 条件通过时，该项被加入并标记为可用。
- 条件不通过时，**只有**在按住强制显示键的情况下才会加入，并标记为不可用。

不可用的项会用挂锁图标代替交互自身的图标。对不可用项按交互键不会执行任何内容，而是把该交互的提示以红色消息显示在快捷栏上方。

## 提示信息

一个交互可以携带任意数量的提示字符串，每次随机选取一条。当交互完全没有提示时，会从三个回退键中随机取一个：`extra_interaction.default_tip0`、`extra_interaction.default_tip1`、`extra_interaction.default_tip2`。

提示通过翻译系统显示，因此提示若是有效的翻译键就会被本地化，若是纯文本则原样显示。

::: info
随包资源中存在两处本地化特征。`extra_interaction.default_tip*` 三个条目在 `en_us.json` 与 `zh_cn.json` 中都是同一段中文，因此回退提示没有英文翻译。随包的实体对话交互也直接把一句中文原文当作提示传入，而不是翻译键，因此该句在任何语言下都原样显示。
:::

## 标签与图标

选项标签分两步解析：先把注册名当作翻译键查找，若没有对应键则回退为字面字符串；随后对结果解析[占位符](04_placeholders)。这正是一个交互既可以用语言键注册、也可以用纯文本注册、还可以用 `` `<name>` `` 这类占位符注册的原因。

图标是可选的。没有图标的交互只是把标签绘制得更靠左。模组自带的贴图为：行背景 `extra_interaction:textures/option.png`、锁定项 `extra_interaction:textures/lock.png`、随包对话交互 `extra_interaction:textures/talk.png`。

## 滚动与溢出

同时完整可见的行数是可配置的，该区域会按此高度裁剪。一旦选择移出可见窗口，整个列表会整体上移，使选中项保持可见。当选项数量超过可见行数时，列表左侧会绘制一条细滚动条，滑块的尺寸与位置反映当前选择。
