# 网络与服务器注意事项

更多交互使用两个数据包，均注册在 `extra_interaction` 命名空间下。

## 数据包

| 数据包 | 方向 | 内容 |
|:---|:---|:---|
| `extra_interaction:send_interaction` | 客户端 → 服务端 | 选项名称，以及实体网络 ID 或方块坐标之一 |
| `extra_interaction:send_talk_data` | 服务端 → 客户端 | 已加载实体对话文件的完整映射，按文件标识符索引 |

交互数据包先写入一个布尔判别位，随后写入实体 ID 或方块坐标。两者都不是的目标会被写成实体 ID `-1`，在服务端解析为没有实体，因此不会执行任何动作。

## 对话数据同步

实体对话数据由服务端的 `extra_interaction:entity_talk` 重载监听器加载，随后在数据包同步时广播：

- 单个玩家同步时（即加入时），数据发给该玩家。
- 不存在单个玩家时，例如服务端 `/reload` 之后，数据发给所有在线玩家。

客户端需要这份表，因为选项条件在客户端求值，用来决定该行是否绘制为可用。

## 服务端信任模型

在公开服务器上安装本模组之前，请务必阅读本节。

::: danger
`extra_interaction:send_interaction` 的服务端处理器会按给定目标查找同名交互并直接执行其动作。它**不做**条件复查、**不做**距离或视线检查、**不做**权限检查。因此发送构造数据包的客户端可以按名称调用任何已注册的交互，作用于它所选择的任意方块坐标或实体 ID，无论玩家身在何处，也无论该交互自身的条件是否允许。
:::

由此产生三个后果：

1. **距离没有被约束。** 没有任何机制把数据包中的目标限制在玩家的触及范围内，甚至不限制在玩家附近已加载的区域内。假定「靠得够近」的动作可以从任意远处被触发。
2. **条件只是参考。** 条件决定*列表*显示什么，以及*客户端*是否认为某行可用。它不是服务端的闸门，因为当前源码中执行路径内的复查处于注释状态。
3. **数据包命令继承 2 级权限。** 实体对话命令以游戏管理员权限执行并抑制输出，与触发玩家自身的权限等级无关。参见[实体对话数据包](03_entity_talk)。

把第 1 点与第 3 点结合起来：在数据包定义了实体对话条目的服务器上，任何能发送该数据包的玩家都能执行那些 2 级命令，无论其面前是否真的有匹配实体。

## 建议的处理方式

- 把每个 `entity_talk` 文件都视为受信任的管理员内容，用审阅函数或命令方块的谨慎程度来审阅。
- 优先编写「任何玩家执行都安全」的命令，并使用 `@s` 而非宽泛的选择器，这样被伪造的触发也无法影响其他玩家。
- 如果你通过[开发者 API](06_developer_api) 提供交互，请在动作内部校验全部前置条件 —— 玩家到目标的距离、目标的状态、玩家的权限 —— 而不要依赖条件。
- 请记住动作会在两端各执行一次，因此仅限服务端的效果必须显式加以判断。

## 哪些内容不存在

为完整起见：模组不包含以下任何内容 —— 服务端或通用配置、命令、权限节点、数据包频率限制，以及 `neoforge` 与 `minecraft` 之外的任何依赖声明。
