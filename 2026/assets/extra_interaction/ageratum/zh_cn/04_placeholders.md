# 占位符

更多交互自带一个小型占位符解析器。字符串中任何 `<...>` 记号都会在解析表中查找并替换；表中没有的内容原样保留，尖括号也一并保留。

## 占位符在哪里生效

- **选项标签。** 每个选项名称在绘制前都会用本地玩家与当前目标解析一次。
- **实体对话命令。** 每条命令字符串在执行前都会用交互玩家与目标实体解析。

## 可用占位符

下列 `<...>` 记号针对**目标**（你正在看的实体或方块）解析：

| 占位符 | 解析结果 |
|:---|:---|
| `` `<name>` `` | 实体时为其显示名称；方块时为翻译后的方块名 |
| `` `<uuid>` `` | 实体时为其 UUID 字符串；方块时不解析 |
| `` `<pos>` `` | 实体所在方块坐标，或方块坐标本身，以空格分隔 |

下列记号针对正在交互的**玩家**解析：

| 占位符 | 解析结果 |
|:---|:---|
| `` `<player.name>` `` | 玩家的显示名称 |
| `` `<player.uuid>` `` | 玩家的 UUID 字符串 |
| `` `<player.pos>` `` | 玩家所在方块坐标，以空格分隔 |

## 解析规则

- 只有内部不再包含 `<` 或 `>` 的记号才会被识别，因此不支持嵌套。
- 没有对应解析器的记号原样复制。像 `` `<player.names>` `` 这样的拼写错误会在标签或命令中字面出现。
- 解析器无内容可返回时 —— 例如目标是方块却使用 `` `<uuid>` `` —— 同样保留原记号，而不是产生空字符串。
- 坐标由短坐标形式去掉逗号得到，这正是 `` `<pos>` `` 与 `` `<player.pos>` `` 可以直接当作三个命令参数使用的原因。

## 实用写法

由于坐标不含逗号，对话命令可以毫不费力地指向自己的对象：

```json
"commands": [
  "summon minecraft:firework_rocket <pos>",
  "tp @s <player.pos>",
  "tag <player.name> add greeted"
]
```

又因为标签也会被解析，注册名字面为 `` `<name>` `` 的交互会显示成目标自己的名字 —— 这正是随包[实体对话](03_entity_talk)选项显示其所属实体的方式。

::: info
标签解析发生在翻译查找之后，因此**值**中含占位符的语言键同样有效：先翻译键，再替换翻译文本中的占位符。
:::
