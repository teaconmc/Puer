# 路线与版式

路线把原始管道站台变成可排班的交通线路。**路线**拥有一个或多个**版式**，每个版式是平台停靠点的有序列表。

## 路线编辑器

合成路线编辑器并右键使用：

<recipe id="superpipeslide:route_editor"/>

编辑器初始为空，会提示「创建一条路线开始」。之后可以：

- 创建、更新与删除路线。
- 设置路线名称、一个备用译名与最多三个主题颜色。
- 为路线添加一个或多个版式。
- 从可用已认领站台列表中设置版式的站序。
- 切换版式是否双向，或是否构成环线。
- 把双向版式拆成两条单向版式。
- 删除版式或单个平台停靠点。

一个版式在单次保存的站序中最多包含 512 个平台停靠点。

## 路线区段

服务端会计算相邻有序平台之间的路线区段。区段需要方向正确的有效管道连接，编辑器会显示以下状态：

| 状态 | 含义 |
|:---|:---|
| Valid（有效） | 区段路径可用。 |
| Disabled（禁用） | 区段被有意禁用。 |
| Stale（过期） | 网络或属性变化后需要重新计算。 |
| Incomplete（不完整） | 寻路器在找到完整路径前停止。 |
| Broken（无路线） | 不存在可用路线。 |
| Ambiguous（歧义） | 路径求解器找到多条冲突路线。 |

修改管道属性或方向限制会把相关区段标记为过期，服务端会排队推送路线数据更新，让客户端刷新路线缓存。

## 区段求解限制

单个路线区段的寻路受 `routePathfinderMaxVisitedNodes`（默认访问 `16384` 个节点）限制。超出预算的区段会标记为不完整，而不是阻塞整个网络。

## 保存与版本

每次路线编辑都带客户端最后看到的路线版本号。如果其他玩家在此期间修改了路线数据，服务端会拒绝过期编辑并要求客户端刷新，从而避免丢失更新。
