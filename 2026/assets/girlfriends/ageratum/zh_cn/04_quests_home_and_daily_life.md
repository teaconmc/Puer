# 任务、家与日常

## 任务

存在两种：

| 类型 | |
|:---|:---|
| **固定任务** | 人工编写、具体 |
| **随机任务** | 由模板生成 |

从互动界面打开**查看任务**可看到**目标**列表，然后选择**接受任务**或**再想想**。完成后用**交付任务**提交会显示*「任务完成！」*。

::: warning
**只有沫沫有任务内容。** 数据文件把这一点摆得很清楚：

| 角色 | 固定任务 | 随机模板 |
|:---|---:|---:|
| **沫沫** | **10** | **8** |
| 渔溪 | 0 | 0 |
| 梅疏 | 0 | 0 |
| 绾樱 | 0 | 0 |
| 幽若 | 0 | 0 |

其他一切在五人之间都是均衡的——礼物偏好、礼物台词、日程、祝福、拾取清单每人都有。任务是唯一只为单个角色填充过的系统。

因此若你想体验这个模组的任务那一半，请召唤沫沫。另外四人作为同伴是完整的，但没有任何事要托付你。
:::

任务可在服务器范围内关闭，此时会显示*「本服务器已禁用任务」*。

## 邀请她回家

这是关系的最后一步，而它有一条精确且极易被忽略的要求。

::: danger
**你的重生点必须是一张双人床。**

失败提示直说了：*「邀请回家失败。请检查你的重生点是否为双人床。」* 而若你根本没有重生点：*「请先设置重生点再邀请回家。」*

因此流程是：**并排放两张床**、在那里睡觉以设定重生点，然后使用**邀请回家**。成功会显示*「成功邀请同居！」*，角色随之达到**同居伴侣**等级。

单张床不行，重生锚也不行。
:::

邀请回家同样可在服务端禁用，此时给出*「本服务器不允许邀请回家」*。

## 跟随模式

**跟随模式**按钮在四种状态间循环：

| 模式 | 行为 |
|:---|:---|
| **无** | 无跟随行为 |
| **跟随** | 跟着你 |
| **留守** | 保持原地 |
| **回家** | 前往并留在家中 |

**回家**正是与上述邀请配套的模式——角色成为同居伴侣之后，这就是你把她送回去而不是一直带着走的方式。

去危险的地方之前请设为**留守**。角色会注意敌对生物并寻找庇护，但她们是与玩家同尺寸的同伴，不是战斗单位。

## 每日日程

五人各有一份**在数据中定义的日程**，这也是本模组技术上最有意思的功能。

一份日程是**跨越 24000 刻主世界日**的一组关键帧，驱动该角色的活动轨道：

| 时刻（刻） | 活动 |
|:---|:---|
| 0 | 早晨 |
| 2000 | 日间工作 |
| 6000 | 午后 |
| 11000 | 日落 |
| 13000 | 夜间休息 |

因此角色的行为取决于当日时刻，而不只取决于你要求她做什么。清晨与日落时去沫沫的花园，按设计就是两种不同的体验。

五份日程是各自独立的文件，因此数据包可以为任何角色重新排时——挪动她的工作时段、增加关键帧，或给她完全不同的节奏——都无需触碰代码。

## 确认关系

**确认关系**是通往**亲密**等级的那一步，会显示*「你们的关系更近了……」*。与另外两项里程碑功能一样，它可在服务端禁用，此时给出*「本服务器不允许绑定关系」*。

三个开关——任务、关系绑定、邀请回家——**默认全部开启**，因此全新安装即拥有全部功能。见[05 须知](05_technical_notes)。

## 死亡时会发生什么

模组为角色死亡设有专门处理，而不是交给原版。该处理具体做什么不是数据文件所能确立的，因此这里只记录它存在而不加描述——但这意味着「失去一名同伴」是作者考虑过的情形。
