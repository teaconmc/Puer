# 好感与赠礼

## 六个等级

好感按「每位玩家对每个角色」分别记录，并以有名称的等级呈现：

| 等级 | |
|:---|:---|
| 陌生 | 起点 |
| 熟悉 | |
| 信任 | |
| 好感 | |
| 亲密 | 通过**确认关系**达成 |
| **同居伴侣** | 通过**邀请回家**达成 |

最后两级不是被动阈值，而是你从互动界面执行的动作。达到亲密会显示*「你们的关系更近了……」*，而成为同居伴侣需要 [04 任务、家与日常](04_quests_home_and_daily_life) 所述的特定条件。

## 五种赠礼结果

每次赠礼都会落入五类之一，且都会报告好感变化：

| 结果 | 提示 |
|:---|:---|
| **最爱** | 逐物品的专属回应 |
| **喜欢** | *「…… 接受了你的礼物，好感 +N」* |
| **接受** | 礼貌接受 |
| **拒绝** | *「…… 对这份礼物不感兴趣……」* |
| **厌恶** | *「…… 似乎不喜欢你的礼物，好感 −N」* |

**厌恶的礼物会降低好感**，因此赠礼不是单向棘轮。*拒绝*与*厌恶*的区别很要紧：拒绝是中性的不感兴趣，厌恶则是真正的惩罚。

## 最爱是逐物品而非逐类别

最爱是针对**具体物品**记录的，并配**三段不同台词**，因此重复赠送不会读起来一模一样。已确认的例子：

- 沫沫——**蜜脾**与**花束**
- 渔溪——**鹦鹉螺壳**

台词是按人物性格写的，而非通用模板。沫沫对花束的回应从*「每一朵花你都是精心挑的吧？」*到*「这束花永远不会枯萎——因为它来自你。」*。语言文件中共有 **133 条礼物台词**，这使赠礼稳居模组书写量之首。

## 每日上限

::: warning
**每个角色每天只接受有限数量的礼物。** 达到上限后你会收到*「…… 今天不想再收礼物了……」*，此后赠礼无效。

这是模组中最重要的一条节奏事实：好感无法靠把一箱花束倒给同一个角色来加速。请按几个游戏日来规划一段关系的推进。
:::

另有一条独立的拒绝提示*「无法向 …… 赠送礼物」*，覆盖的是「根本不允许赠礼」而非「今日额度已尽」的情形。

## 语音伴随赠礼

每次赠礼回应都可播放一段语音。这套系统做得很扎实：语音事件与台词一一对应——沫沫对最爱花束的回应会播放为那条台词注册的音效——而且由服务端告知客户端该播哪一条，而不是客户端去猜。

::: info
**音频只有中文，但字幕有翻译。**

全部 103 个语音文件位于一个 `zh_cn` 目录之下，而音效事件名本身就包含 `zh_cn`。这个结构显然是为容纳更多语言而设计的，但目前只录了中文。

字幕是另一回事，并且处理得当：它们使用真正的翻译键，因此开着字幕的英文客户端会在中文语音之上读到形如「沫沫——最爱」的字幕。二十五个字幕键覆盖了各种情形。
:::

## 缎带与喷壶

四种缎带被归入它们自己的物品标签之下，这表明它们是被当作一组而非逐个处理的。它们可堆叠到 16，与只能单个的花束和喷壶不同。

喷壶带有一个**水位组件**，而模组还附带一个 `grass_to_weed` 方块标签，列出了草、蕨、灌木、落叶与下界菌须。把这两者放在一起读，指向的是围绕沫沫主题的园艺互动——但具体行为不是数据文件本身能确立的，因此请把这种关联当作提示而非定论。

## 直接查看好感

管理员可用一条命令查看、设置与增减好感，若你把它指向五名角色之外的东西，它会礼貌地拒绝。该命令**要求 gamemaster 权限**——见[05 须知](05_technical_notes)。
