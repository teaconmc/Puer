# 多人游戏与须知

## ⚠️ 必须安装 PlayerAnimationLib

::: danger
**Momentum 需要 PlayerAnimationLib，但缺失时它不会提醒你。**

由于这个依赖没有按常规方式声明，缺少 PlayerAnimationLib **不会**弹出那种友好的「你缺少依赖」界面。你会遇到的是一次莫名其妙的失败。

**如果 Momentum 崩溃或无法工作、而报错内容看不出道理，请先检查 PlayerAnimationLib 是否已安装。** 那是最可能的原因。

MochaFloats 也是必需的，但它会随 PlayerAnimationLib 一起来。
:::

**Curios 是真正可选的**且处理得当——模组会先检查它是否存在再使用，因此缺少它完全安全。

## ⚠️ 它可能与其他移动类模组冲突

Momentum 在很深的层面改变玩家的移动方式——台阶高度、坡度处理、空中与水中移动、跳跃力度、爬梯加速、镜头倾斜与视野。

::: warning
**任何其他改动玩家移动的模组都是潜在冲突源。** 跑酷类、飞行类、攀爬类与疾跑修改类模组都会碰到同样的行为。

**在把整合包定下来之前请先测试这个组合。** Momentum 单独能用，完全不能说明它与另一个移动类模组共存时也能用。
:::

## 什么会保留、什么不会

| 项 | 重新登录后 | 死亡后 |
|:---|:---|:---|
| **机动模式开关** | **保留** | **保留** |
| 你当前的移动状态 | **重置** | 重置 |

所以你的偏好设置会留下，但你总是以地面上的中性状态回来，而不是停在半空的墙上疾跑中。这是有意为之，不是故障。

## 给服主的说明

::: warning
**这套移动系统不是反作弊边界。** 服务端接受客户端上报的移动状态，而不会重新验证玩家是否真的贴着墙、或速度是否真的够快。

服务端的功能开关仍然是有意义的控制面——它们决定了一个正常客户端会尝试哪些动作——但**请不要把它们当作针对被修改客户端的防护**。
:::

## 其他玩家能看到你的动作

你的状态会广播给世界里的所有人，因此其他玩家能看到你的墙上疾跑与冲刺，并带有正确的动画。这也意味着 **Replay Mod 的录制能正确捕捉状态切换**，包括录制者自己的。

## 已知的粗糙之处

**游泳冲刺状态显示为原始翻译键**而不是可读名称。仅外观问题——动作本身正常。

**有两处配置注释与它们的实际默认值矛盾**（`minWallRunSpeed` 与 `fadeInSpeed`）。

::: warning
**请信数值，不要信注释。** 如果注释写着一个数字而设置项显示另一个，游戏用的是设置项里的那个。见[配置](07_configuration.md)。
:::

**项目的 README 已经过时。** 它报告的是更旧的版本号、把移动状态数写成十七而实际是十八、动作表里完全漏掉了力量跳跃，并把闪避充能写成一次而默认是两次。

::: tip
**请以本组页面为准，而不是 README** —— 那份 README 描述的是更早的构建。
:::

## 没有命令

Momentum 完全没有命令。一切都通过它的**三个按键绑定**与两个配置文件完成。

## 小结

| 项 | 状态 |
|:---|:---|
| **PlayerAnimationLib** | ⚠️ **必需，且缺失时没有友好报错** |
| Curios | 可选，处理安全 |
| 其他移动类模组 | ⚠️ **请测试冲突** |
| 机动模式偏好 | 重登与死亡后都保留 |
| 移动状态 | 重登后重置 |
| 反作弊 | ⚠️ **不是** |
| 命令 | **没有** —— 只有按键与配置 |
| 整合包使用 | 需要许可 |
