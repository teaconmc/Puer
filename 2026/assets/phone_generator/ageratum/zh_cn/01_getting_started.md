# 获取开始

## 获得方块

**两个方块都无法合成。** 模组不随包 `recipe/` 目录，请用创造分页（**「手机发电机」**）或：

```
/give @s phone_generator:generator
/give @s phone_generator:motor_block
```

两者**都有**战利品表，挖掘时掉落自身。它们被标记为 `minecraft:mineable/pickaxe` 与 `needs_stone_tool`，因此**至少需要石镐**才能回收。

## 放置发电机

放下后它立即尝试在 API 服务器上创建房间。方块面随后显示四种状态之一，而面上的文字准确说明了流程走到哪一步：

| 面上显示 | 含义 |
|:---|:---|
| **连接中…** | 创建房间的请求正在发出 |
| **服务器无法访问** | HTTP 调用失败 —— API 服务器不可用或被拦截 |
| **重新连接中…** | 房间已存在但 Socket.IO 链路断开，正在重试 |
| **已连接** + 二维码 + **当前等级：N** | 正常工作 |

::: tip
这四句是真实的翻译键（`screen.phone_generator.connecting` / `api_failed` / `socket_failed` / `connected`），因此**方块本身就是诊断工具**。看到「服务器无法访问」说明问题在网络或服务器可用性 —— 不是方块坏了、不是放错位置，也不是缺依赖。
:::

## 扫码

连接成功后，方块面渲染一个二维码。它编码的是一个**加入链接**，而该链接是逐玩家构造的：

```
<joinUrl>&playername=<你的名字>&uuid=<你的 UUID>
```

因此某位玩家看到的二维码会向该服务标识出这位玩家。用普通手机相机扫描即可；手机端之后发生什么属于该服务的范畴，不由模组决定。

::: warning
由于该链接携带你的**玩家名与 UUID**，而默认端点是**第三方服务器且走明文 HTTP**，任何能观察流量的人 —— 或运营该服务器的人 —— 都能看到这两项。使用前值得了解这一点；详见[网络、隐私与自建服务](03_network_privacy_and_hosting)。
:::

二维码在客户端生成，纠错等级为 **L**、边距 1 模块。`qrCodeSize` 默认 **21**（标准最小值），可取 5–100；渲染器按 URL 缓存矩阵，因此不会每帧重新生成。

若编码失败，面上显示 `[二维码错误]`。

## 读取等级

连接后面上还会显示**当前等级：N**。这个数字是手机端产出的，也是发电量的唯一输入 —— 见[发电与风扇](02_power_and_fan)。

## 服主应先做的三件事

1. 判断默认的第三方端点是否可接受，或用 `/phone_generator_server set <url>` **指向自己的服务器**（需 gamemaster 权限）。
2. 确认服务器能出站访问它 —— 模组**不建立任何入站连接**，因此无需端口转发。
3. 按整合包的电力尺度调整 `energyBufferCapacity`（默认 100000 FE）与 `pushEnergyPerTick`（默认 100）。
