# 网络、隐私与自建服务

本页精确陈述网络行为，因为模组的核心功能就是一个网络服务，这件事值得清楚交代，而不是渲染恐慌或含糊其辞。

## 模组**不会**做的事

先说这部分，因为它排除了最严重的一类问题：

| 关注点 | 结论 |
|:---|:---|
| 开启监听端口 | **不会** —— 全模组无 `ServerSocket`、无 `bind`、无 `listen` |
| 接受入站连接 | **不会** —— 全部流量为出站 |
| 执行来自网络的命令 | **不会** |
| 需要端口转发 | **不需要** |

**所有网络活动都由本地发起、方向向外。** 这个模组不会让你的机器变得可以被外部访问。

## 模组**会**做的事

两条通道，都指向同一个配置的基础 URL：

**HTTP，经 `java.net.http.HttpClient`（HTTP/1.1）：**

| 端点 | 方法 | 时机 |
|:---|:---|:---|
| `<apiBaseUrl>/api/room/create` | `POST`（无请求体） | 发电机放下 / 需要房间时 |
| `<apiBaseUrl>/api/room/destroy` | `POST`（带请求体） | 房间销毁时 |

创建请求的响应会被解析出 `roomId` 与 `joinUrl`。

**Socket.IO 持久连接**，开向同一个基础 URL，这是手机端等级实时传回游戏的通道。失败时按**指数退避**重试：`retryInitialDelaySec` 5 → `retryMaxDelaySec` 120，乘数 `retryDelayMultiplier` 2.0。

## 需要权衡的三件事

::: danger
**1. 默认端点是第三方服务器，且硬编码在配置里。**

```
apiBaseUrl = "http://phone-generator.karlcx.cn:10841"
```

开箱状态下，你世界里放下的每台发电机都会联系那台主机。

**2. 是明文 HTTP 而非 HTTPS。** 传输过程未加密。

**3. 玩家名与 UUID 被放进加入链接发送：**

```
joinUrl + "&playername=" + userNameStr + "&uuid=" + userId
```

因此该端点的运营者 —— 以及任何能观察这段未加密流量的人 —— 都能看到哪些具名账号、以哪些 UUID 在使用它。

这一切都不是隐藏的或恶意的：手机到游戏的桥梁本来就需要一台会合服务器，作者提供了一台以便开箱可用。但**「第三方主机 + 明文 HTTP + 玩家标识符」这个组合值得一个有意识的决定**，而不是默认值带来的既成事实。
:::

## 自建服务：官方支持的缓解手段

模组随包一条专门用于改指端点的命令，且权限设置得当：

```
/phone_generator_server get
/phone_generator_server set <url>
```

**需要 `LEVEL_GAMEMASTERS`** —— 通过 `.requires(Commands.hasPermission(Commands.LEVEL_GAMEMASTERS))` 显式声明，因此普通玩家无法改指。`set` 会把值写回配置文件（它调用了 `save()`），因此重启后仍然生效。

::: tip
**对任何在意玩家标识符的服务器，这是推荐部署方式**：自行搭建一份该服务的实例，然后 `/phone_generator_server set https://你的主机/...`。由于这个设置是同时用于 HTTP 调用与 Socket.IO 连接的纯基础 URL，**HTTPS 端点可以直接工作** —— 这也顺带消除了明文传输的问题。
:::

## 失败行为

模组的失败是**可见且安全**的：

- API 不可达 → 面上显示**服务器无法访问**，不产电
- 套接字断开 → 面上显示**重新连接中…**，按退避重试
- 两种状态都不会崩溃游戏或阻塞主循环；调用是异步的（`sendAsync`）

不存在「方块看起来正常但其实不产电」的静默失败模式 —— 面上那四句连接状态始终反映真实情况。见[获取开始](01_getting_started)。

## 给整合包作者的结论

| 如果你… | 那么… |
|:---|:---|
| 把它放进公开整合包 | 说明默认端点，或在发布前改成自己的 |
| 运行私人服务器 | 自建并用 HTTPS；那条命令让这件事只需一行 |
| 在意玩家标识符 | 自建 —— 链接始终携带名字与 UUID |
| 单人离线游玩 | 模组只是不产电，不会有任何东西损坏 |
