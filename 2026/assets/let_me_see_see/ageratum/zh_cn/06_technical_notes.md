# 排障

## ⚠️ 扫描器毫无反应时，请去看日志

::: danger
**扫描器没有失败反馈。** 如果底层的类检查支持没能启动，右键方块会**什么都不发生**——聊天栏没有消息、没有报错、也没有导出文件。

这看起来完全像物品坏了，但它不是。**在断定扫描器有故障之前，请先在日志里找 `Cannot export class, instrumentation not available`。**
:::

## 三个工具的失败表现完全不同

这是某样东西看起来坏了时最有用的一条信息：

| 工具 | 类检查不可用时 |
|:---|:---|
| **类浏览器** | 显示清晰的**类浏览器不可用**界面 |
| **物品数据导出器** | **照常正常工作** —— 它不需要类检查 |
| **扫描器** | **静默什么都不做** |

::: tip
**所以「物品数据导出器能用，说明一切正常」是错误推论。** 导出器从不检查类检查支持，因此它能用并不能说明另外两个的状态。

如果类浏览器显示不可用界面，那么扫描器很可能也已静默失效。
:::

## ⚠️ 请重启游戏 —— 重开界面没有用

::: warning
**类检查一旦启动失败，就会在整个会话中保持失败状态。** 模组不会重试。

关掉再打开类浏览器不会解决问题。**你必须重启游戏。**

如果你是在开发环境而非打包好的 jar 中运行，可能还需要设置 `LET_ME_SEE_AGENT_JAR_PATH` 系统属性。
:::

## 导出的文件在哪

模组写出的一切都落在：

```
<游戏目录>/let_me_see_see/
```

按 `包/路径/类名.class` 的结构排布——所以 `net.minecraft.world.item` 里的类会出现在对应的文件夹层级下。

::: info
**导出的字节码是真正的运行时版本**，即所有模组补丁都已应用之后的状态。这正是这个工具的意义：你拿到的是游戏实际在运行的东西，而不是原始 jar 里的内容。
:::

## 导出为什么会过期

模组会记录导出时在场的模组集合。若该集合发生变化，你会看到：

> *Some mod changed since the export and may influence class contents*

::: tip
这条警告意味着**你导出的文件可能已与游戏实际运行的内容不符**。请重新导出，而不要信任旧输出。见[类浏览器](03_class_explorer)。

它在每次新启动时也会触发，因为每个会话都是单独记录的。
:::

## 你不需要额外安装任何东西

所有支持库——包括反编译器与语法高亮器——都**打包在模组自己的 jar 内**。没有需要单独下载的东西，也没有版本需要对齐。

## 关于服务端安装

物品在专用服务器上也会注册，但**所有实际功能都是客户端侧的**。装在服务端不会带来任何好处；请装在你想检视类的那个客户端上。

## 一些外观层面的说明

**模组在模组列表里没有图标。** 它声明的 logo 文件不在构建产物中，因此条目显示为无图。无害。

**部分界面标题写着「Retriever」与「Exported Classes Data Base」。** 这是类浏览器与物品数据导出器早先的名字，被保留作为界面标题。如果某个窗口标题与你使用的物品不一致，原因就在这里。

## 版本支持

Minecraft **`[26.1.2, 26.2)`**——是一个真正的范围而不是单一锁定版本，因此它能容忍小版本更新。

## 速查

| 症状 | 原因 / 处理 |
|:---|:---|
| 扫描器毫无反应、没有消息 | 类检查不可用 —— **请查日志** |
| 类浏览器显示不可用 | 同一原因 —— **请重启游戏** |
| 重开界面没有用 | 预期行为 —— **只有重启才会重试** |
| 物品数据导出器仍能用 | 正常 —— 它不需要类检查 |
| 导出提示模组已变化 | **请重新导出** |
| 模组列表里没有图标 | 仅外观问题 |
