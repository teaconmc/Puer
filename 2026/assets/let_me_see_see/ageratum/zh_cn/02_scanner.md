# 扫描仪

扫描仪只回答一个问题：*我正看着的这个东西，是哪些代码负责的？*

## 用法

| 目标 | 操作 |
|:---|:---|
| 世界中的方块 | 右键它 |
| 生物实体 | 右键它 |

两条路径都把结果送进类扫描视图，因此你最终会到达与[类浏览器](03_class_explorer)相同的地方，只是已经预先过滤为与该目标相关的类。

## 它收集什么

对**方块**而言，分析从被点击 `BlockState` 背后的 `Block` 实例开始；对**生物**而言，从实体实例开始。随后 `RelateClassFinder` 向外遍历相关类型——这正是模组自己的注释指出方块路径**必须**在客户端执行的原因：它会触及渲染器类，而那些类只存在于客户端。

::: warning
**两种交互都仅限客户端。** `ScannerItem` 的每个分支都由 `level.isClientSide()` 守卫，且无论如何都返回 `InteractionResult.SUCCESS`。在专用服务器上这件物品**什么都不做**——不是数据包被拒绝，而是根本没有代码运行。它是一个恰好长成物品形状的客户端检视工具。
:::

::: danger
**如果类检查不可用，扫描仪会毫无反馈地失效。** 你右键一下，然后没有消息、没有报错、也没有文件。请在日志里找「Cannot export class, instrumentation not available」，并参见[排障](06_technical_notes)——在你重启游戏之前它不会重试。
:::

## 为什么这是正确的入口

类浏览器能列出每一个已加载的类，而在大型整合包里那是数万条。从「就是这个方块，就在这儿」出发，会把范围收缩到少数几个直接相关的类型，而这几乎总是你问「他们是怎么做到的」时真正想要的东西。

实用循环：

1. 右键你好奇的那个方块或生物。
2. 读取收集到的类名。
3. 把感兴趣的导出，使其持久化（见[类浏览器](03_class_explorer)）。
4. 若已配置 Fernflower，就地阅读反编译源码；否则跳转到你的 IDE。

## 外观

扫描仪有一套手工 Blockbench 模型（模型 JSON 中署名 XeKr）并带有动画覆盖层——`scanner_fx.png` 附带 `.mcmeta`，因此特效贴图是动画而非静态。另外两件物品采用同样的双层处理。
