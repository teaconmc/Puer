# 直播助手（LiveHelper）

直播助手是 Burning_TNT 的 TeaCon 2026 参赛作品，模组 ID `live_helper`，组 ID `net.burningtnt.livehelper`，版本 `1.0.0`，面向 Minecraft 26.1.2。

作者自己那句一行总结是最好的描述：**「ReplayMod，但是直播。」**

它是一个**多机位转播工具**。你定义机位、编写 WebAssembly 程序来移动它们并决定哪一路上画面，然后由直播助手把渲染结果通过 Spout 推送给 OBS 或任何其他 Spout 接收端。配置在**模组从游戏内部提供的网页控制台**中完成。

## 它完全不添加任何游戏内容

没有物品、没有方块、没有实体、没有配方、没有创造分页。**根本不存在 `data/` 目录。** 你的世界不会有任何变化。

这是一件恰好以模组形式发布的制作工具。如果你不做直播或录制，它对你毫无用处。

## 两条必须先确认的硬约束

**它是纯客户端的。** 模组声明为 `Dist.CLIENT`，因此在专用服务器上什么都不做。（其元数据仍把两个依赖都声明为 `side="BOTH"`——这只是外观上的不一致，真正起作用的是 dist 注解。）

**推流输出仅限 Windows。** Spout 桥接是一个以 Windows DLL 形式随包的原生库。在 macOS 或 Linux 上可用性检查返回不可用，**推流那一半功能等于不存在**。其余部分——控制台、程序、机位数学——依然运行，只是帧没有地方可去。

## 许可 —— 做直播的请务必读这条

许可是 **AGPL-3.0-only**，本批中最强的 copyleft，而它在这里比通常更重要，因为**这个模组会运行一个 HTTP 服务器**。

AGPL 的网络条款覆盖「用户通过网络与之交互」的软件。如果你修改了直播助手并让任何人能经网络访问它的控制台，你就有义务向对方提供对应源码。对于普通用法——运行未修改的模组、控制台只绑定在本机——这不构成负担；但如果某个整合包给它打了补丁又把控制台暴露出去，就必须认真对待这项义务。

## 注册了什么

| 注册表 | 条目 |
|:---|:---|
| 物品 / 方块 / 实体 / 配方 | **均无** |
| 配置 | **1 项**，客户端侧，带配置界面 |
| Mixin | 4 个，**全部客户端** |
| 着色器 | 2 个 —— 一个 blit 顶点着色器、一个 mix 片元着色器 |
| 按键绑定 | **未注册任何** |
| 命令 | 无 |
| 随包原生库 | `libSpoutBinding.dll`（Windows） |
