# 入门

## 控制台会自己招呼你

直播助手在客户端初始化阶段启动一个 HTTP 服务器。有两处提示告诉你它已就绪：

- 一行日志：`LiveHelper is started at http://localhost:23512/`
- 一条**带可点击链接的聊天消息**——「[LiveHelper] 访问 `<url>` 配置」。

点击那条聊天消息会在浏览器中打开控制台。这是设计上的入口；**游戏内没有用于搭建机位的界面。**

## 端口固定为 23512

服务器端口在代码中被设为 **23512**，且**没有任何配置项可以改它**。如果你机器上已有别的程序占用该端口，服务器就无法在你预期的位置启动。

它公布的 URL 绑定在 `localhost`，因此默认只能从你本机访问控制台。若你想用手机或第二台电脑来配置，那已进入模组未作准备的领域——而考虑到 AGPL 的网络条款，那也是值得先读一遍许可的领域。

## 游戏之外你需要什么

| 需要 | 原因 |
|:---|:---|
| **Windows** | Spout 桥接是仅 Windows 的原生库 |
| **一个 Spout 接收端** —— 装了 Spout 插件的 OBS 或类似软件 | 渲染好的帧要送到那里 |
| **一个浏览器** | 控制台是唯一的配置界面 |
| **一套能产出 WebAssembly 的工具链** —— 作者推荐 AssemblyScript | 机位行为是编程出来的，不是点选出来的 |

在 macOS 或 Linux 上你依然可以打开控制台、定义分镜头、运行程序；只是没有 Spout 输出。**不会报错**——可用性检查返回 false，推流路径被直接跳过。

## 唯一的配置项

只有一个客户端侧配置项，通过模组列表里正规的配置界面暴露：

| 选项 | 默认 | 用途 |
|:---|:---|:---|
| `enable_multi_context_workaround` | **false** | 针对多渲染上下文情形的一个变通开关 |

它默认关闭。只有当你的环境确实出现它要解决的问题时才打开——一个针对渲染上下文的无条件变通开关，默认关闭正是有原因的。

除此之外没有任何可配置项。端口、机位行为、镜头清单与混合方式全都由代码或控制台定义。

## 没有注册任何按键绑定

模组没有注册自己的按键映射。但你仍会看到这样的提示：

> 按 [**某键**] 设置，ESC 取消

它出现在控制台请求游戏捕获某样东西时——例如一个机位姿态。提示中指名的是你**已经绑定过**的键；模组是在借用现有控制，而不是新增一个。该消息还有一个带倒计时的变体，因此一次姿态请求不会永远等下去。

## 一次工作流程的样貌

1. 启动客户端，点击聊天链接打开控制台。
2. 定义**分镜头（Clip）**——各个机位。见 [02 分镜头与调度器](02_clips_and_managers)。
3. 编写或上传驱动它们的**程序**。见 [03 编程](03_programming)。
4. 定义一个**调度器（Manager）**，决定哪一路上画面以及镜头如何混合。
5. 把 OBS 指向 Spout 源，开始推流。

## 在开发环境中

若模组检测到自己不在生产环境，它会启动一个名为「LiveHelper Debugger」的守护线程，在 20 毫秒的循环中无限 park。它的作用是在开发期稳定计时行为，**在正常安装中不会运行**。如果你在性能分析器里看到这个线程，说明你处于开发环境。

另有一条固定的失败消息——「Cannot setup LiveHelper, probably in development environment?」——它出现在原生初始化无法完成时。
