# API 参考

全部函数从名为 **`LiveHelper`** 的模块导入。句柄类型写作 `i32(handle, …)` 表示拥有句柄，`i32(&handle, …)` 表示借用句柄。

## 技法函数

这些用于构建技法程序所返回的值。

### `Technique.MakeClip`

构建一个位于固定位置与朝向的机位。

| 参数 | 类型 | 含义 |
|:---|:---|:---|
| `pX`、`pY`、`pZ` | `f32` | 各轴位置 |
| `rX`、`rY`、`rZ`、`rW` | `f32` | 以**四元数**表示的朝向 |

返回一个拥有型分镜头句柄。请从入口点返回它。

朝向用四元数而非偏航与俯仰，这正是任意两个机位角度之间插值行为良好的原因。

### `Technique.MakeEntity`

构建一个附着到指定名称实体上的机位，而不是附着到坐标。

| 参数 | 类型 | 含义 |
|:---|:---|:---|
| `pName` | 指针 | 你模块内存中的实体名称 |
| `pMemoryPage` | `i32` | 该指针所在的内存页 |

返回一个拥有型分镜头句柄。

## 调度器函数

这些用于构建调度器程序所返回的帧配置。

### `Manager.Render.Single`

激活恰好一个分镜头 —— 硬切。

| 参数 | 类型 | 含义 |
|:---|:---|:---|
| `clipIndex` | `i32` 无符号 | **从 0 开始**的分镜头下标 |
| `progress` | `f32` | 在该分镜头中的进度，`[0, 1]` |

返回一个拥有型帧配置句柄。

### `Manager.Render.Mix`

以线性插值混合两份帧配置。

| 参数 | 类型 | 含义 |
|:---|:---|:---|
| `frame1` | `i32(handle)` | 帧配置 1 |
| `frame2` | `i32(handle)` | 帧配置 2 |
| `progress` | `f32` | `0` 只显示 `frame1`，`1` 只显示 `frame2`，介于两者之间则插值 |

返回一个拥有型帧配置句柄。

由于两个输入都是配置而非分镜头，**Mix 可以嵌套** —— 把一次 Mix 喂给另一次 Mix，即可构建多路转场。

## 句柄函数

### `Handle.Duplicate`

再取一个指向同一底层值的拥有句柄。当某个值必须被消耗两次时使用。

### `Handle.Release`

放弃一个拥有句柄。**绝不要**对借用句柄调用它，也**绝不要**对同一个拥有句柄调用两次。

请记住：从入口点返回句柄即把所有权转交宿主，因此已返回的配置**不应**再被释放。

## 输入函数

### `Input.GetF32`

按名称读取一个浮点输入。

| 参数 | 含义 |
|:---|:---|
| `pName` | 指向你内存中名称的指针 |
| `pMemoryPage` | 该指针所在的内存页 |

### `Input.GetBuffer`

把一个文本输入读入你提供的缓冲区。

| 参数 | 含义 |
|:---|:---|
| `pName`、`pNameMP` | 输入名称的指针与内存页 |
| `pBuffer`、`pBufferMP` | 你的目标缓冲区的指针与内存页 |
| `lBuffer` | 你的缓冲区长度 |

**返回所需长度。** 若该值大于 `lBuffer`，则什么都没有写入——请分配更多空间并再次调用。成功的结果是 UTF-8 且以 null 结尾。

## 预定义输入

由宿主提供；你无需声明。

### 技法可用

| 输入 | 读取方式 | 含义 |
|:---|:---|:---|
| `progress` | `GetF32` | 在本段镜头中的进度，`[0, 1)` |

### 调度器可用

| 输入 | 读取方式 | 含义 |
|:---|:---|:---|
| `clip` | `GetF32` | 存在多少个分镜头 |
| `clip.$id.duration` | `GetF32` | 分镜头 `$id` 的时长，单位**毫秒** |
| `clip.$id.name` | `GetBuffer` | 分镜头 `$id` 的名称，UTF-8 以 null 结尾 |
| `duration` | `GetF32` | 自调度器启动以来的毫秒数 |

`$id` 是从 0 开始的分镜头下标，代入到输入名称中。因此读取第三个分镜头的名称，就是去请求 `clip.2.name`。

请注意：**技法的 `progress` 是 `[0, 1)`** —— 半开区间、不含 1 —— 而你传给 `Single` 与 `Mix` 的 `progress` **参数**记为 `[0, 1]`、含端点。这种不对称是有意的：一段镜头永不报告自己已完全走完，但你可以显式地要求一次已完全完成的混合。
