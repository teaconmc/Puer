# 鉴定

## 手册是物品，不是工作站

**鉴定手册**在你手持使用时打开自己的界面。它不与修复台或任何方块绑定——你可以在任何地方鉴定，包括在野外。

这一点值得明说，因为模组同时还提供了一张看起来理应是鉴定站、而[实际什么都不做](01_getting_started)的修复台。

## 界面

| 元素 | 详情 |
|:---|:---|
| **输入** | 一个槽位，仅接受 `#living_unvanished:identifiable` 物品标签 |
| **输出** | **六个槽位**，按 2 列 × 3 行排列 |
| **鉴定按钮** | 标注为「Identify」 |
| 玩家物品栏 | 完整的 27 + 9 |

输入槽的限制由槽位自身强制执行，因此你根本无法放入不合格的物品——不存在需要处理的「放错物品」状态。

鉴定按钮是否可用由一个同步数据值驱动，该值追踪**当前输入是否有匹配的鉴定表**。若某个带标签的物品恰好没有对应表，按钮只会保持不可用，而不会白白消耗物品。

## 按下鉴定时发生什么

按下鉴定会先做四项检查：

1. 输入不为空，
2. 输入在可鉴定标签内，
3. 输出槽**未满**，
4. 该物品存在对应的鉴定战利品表。

四项全部通过时，**消耗一件输入物品**并掷取对应战利品表。结果进入输出槽；放不下的部分会**退还给玩家**而不是丢失。

最后这一点很重要：输出栏满时会直接阻止鉴定，而部分满时也不会静默吞掉结果。

## 幸运会影响结果

战利品掷取是以 **`withLuck(player.getLuck())`** 构建的。

也就是说，**你的幸运属性会被喂进鉴定**。一瓶**幸运药水**，或任何能提升该属性的东西，都会实实在在改善你从一件奇异发现中得到的东西。界面里没有任何地方提到这一点。

这是关于本系统最有用的未文档化事实：**成批鉴定之前先喝幸运。**

## 四张鉴定表

鉴定是数据驱动的。存在四张战利品表，每种未鉴定物品各一张：

| 输入 | 战利品表 |
|:---|:---|
| 奇异头骨 | `identify/living_unvanished_strange_skull` |
| 奇异羽毛 | `identify/living_unvanished_strange_feather` |
| 奇异骨骼 | `identify/living_unvanished_strange_bones` |
| 奇异皮革 | `identify/living_unvanished_strange_leather` |

由于它们是位于数据包可见位置的普通战利品表，整合包可以**在不改动模组的前提下重新调整鉴定概率或增加产物**；又因为输入是以标签而非硬编码清单来把关的，整合包还可以**让新物品变得可鉴定**——把它加入 `#living_unvanished:identifiable` 并提供一张同名的表即可。

这是一套真正开放的设计，也是本模组主要的扩展点。

## 会出什么

| 来自 | 可能结果 |
|:---|:---|
| 奇异头骨 | **鸟类头骨**（鸟）、**兽类头骨**（有袋类） |
| 奇异羽毛 | **蓝色正羽**、**橙色正羽** |
| 奇异骨骼 | **龙骨突**、**肋骨**、**股骨** |
| 奇异皮革 | **条纹皮革** |

龙骨突是鸟类胸骨的隆脊，因此指向蓝鸠；条纹皮革指向袋狼。按物种整理你的收藏，正是这份藏品的预期读法。
