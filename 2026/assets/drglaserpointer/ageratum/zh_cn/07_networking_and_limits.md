# 网络与限制

指示器做的每件事都由客户端驱动，再由一个小型自定义数据包确认。模组把数据包注册在网络版本 `"1"` 之下。

## 数据包

| 数据包 | 方向 | 用途 |
|:---|:---|:---|
| `drglaserpointer:laser_color_switch` | 发往服务端 | `Shift`+滚轮改变了颜色；服务端循环主手物品堆 |
| `drglaserpointer:laser_play_sound` | 发往服务端 | 指示器进入或离开手中；播放 `laser_on` / `laser_off` |
| `drglaserpointer:laser_pick_block` | 发往服务端 | 在方块上生成标记（命中点、方块坐标、颜色、语音标志） |
| `drglaserpointer:laser_pick_entity` | 发往服务端 | 在实体上生成标记（命中点、实体 ID、颜色） |
| `drglaserpointer:laser_distance_update` | 发往服务端 | 上报你自己的光束长度，供他人绘制 |
| `drglaserpointer:laser_distance_request` | 发往服务端 | 索取一组附近玩家的光束长度 |
| `drglaserpointer:laser_distance_response` | 发往客户端 | 应答：实体 ID 与光束长度的配对 |
| `drglaserpointer:switch_inventory` | 发往服务端 | 把给定背包槽位与选中的快捷栏槽位互换 |

## 其他玩家的光束如何保持同步

你的光束长度被量化为以 1/64 格为单位的 `short`，通过 `laser_distance_update` 发送，但只在数值实际改变时才发。服务端把这些长度存在一个以玩家实体 ID 为键的全局映射里；玩家登出时对应条目被移除。

每客户端 tick，你的客户端收集 `laserRange` 之内所有可见、手持指示器且非旁观者的玩家，并为整份名单发送一个 `laser_distance_request`。应答会整体替换客户端的本地映射，渲染器据此把每条远端光束的远端点放在那名玩家的视线向量上。

值得知道的后果：

- 若某位玩家的长度从未被上报，映射返回 `0`，其光束会以零长度绘制 —— 也就是实际上看不见 —— 直到第一次更新到达。
- 应答每次都整体替换映射，因此从你的请求名单中掉出的玩家，其光束会立刻消失。
- 距离请求直接在网络线程上处理，没有被调度到服务端主线程。

## 服务端的信任程度

服务端对传入的标记几乎不做校验：

- **方块标记**只要请求位置所在的区块已加载就会被接受。命中位置、方块坐标与颜色全部来自客户端，没有距离、视线或权限检查。
- **实体标记**被无条件接受；客户端提供实体 ID 与命中位置。
- **槽位互换**对任何范围内的槽位索引都被接受，且不检查该槽位是否装着指示器。

对于公开服务器，这意味着标记行为的可信程度完全等同于连上来的客户端。标记实体本身是无害的 —— 无法被伤害、不造成任何效果、10 秒后过期 —— 但音效、成就触发器与槽位互换都可以被构造的数据包触达。

## 源码中可见的其他粗糙之处

- 清理旧标记时，每放置一个标记都会遍历**世界中的全部实体**。
- 若实体标记引用的实体在服务端无法解析，标记体仍会被生成，但没有所有者名称、没有目标、颜色为 `-1`；它随后只是在世界原点静静度过 10 秒寿命。
- 末影龙存在两张脸部贴图（`ender_dragon_face.png` 与 `enderdragon_face.png`）；只有前者与实体 ID 路径匹配并被实际使用。
- `laser_make` 音效没有限流，因此即便语音被节流，快速点击右键对附近所有人仍然清晰可闻。

## 兼容性

- **Iris** —— 模组的激光渲染管线会可选地映射到 Iris 的闪电（lightning）程序，使光束在光影下仍能正确渲染。Iris 只是编译期依赖：若运行时缺少该类，模组不会报出异常，只是继续使用自己的管线。Iris **未**在模组元数据中声明为依赖。
- **Mixin** —— 一个客户端 mixin 作用于 `Minecraft`，强制 `shouldEntityAppearGlowing` 对被标记的生物返回真。
- **枚举扩展** —— 指示器添加了自己的 `ArmPose`（`DRGLASERPOINTER_LASER_POINTER`），复制自弓的姿态，使手持的指示器指向你瞄准的方向。
- **专用服务器**可用：所有仅客户端的部分都由 `Dist.CLIENT` 守卫，而物品、实体、声音与触发器在两侧都会注册。
