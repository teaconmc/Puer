# 合成系统

## 组成部件

| 方块 | 层级 | 作用 |
|:---|:---|:---|
| **`crafting_system`** | `l4` / `l6` / `l9` | 控制器 |
| **`crafting_parallel_core`** | `l4` / `l6` / `l9` | 同时作业量 |
| **`crafting_pattern_bus`** | —— | 承载样板 |
| **`crafting_worker`** | —— | 实际执行合成 |
| `crafting_vent` | —— | 热量出口 |
| `crafting_interface` | —— | 访问点 |
| `crafting_casing` | —— | 结构填充 |
| `input_hatch` / `output_hatch` | —— | 流体进出 |

请注意这个形态：**样板放在总线里、工作由工作单元完成、热量从排风口离开。** AE2 把样板放在接口里、把工作放在 CPU 里；这里三者是你**分别放置、分别扩容**的方块。

blockstate 清单中含 `casing_formed`、`pattern_bus_formed` 与 `vent_north_formed` 变体，说明多方块**在正确组装后外观会明显变化**——这是很有用的建造校验。

## 批量合成快速路径

这是让本附属「快」的部分，而它从外部完全看不见。

模组为合成执行实现了一条专门的快速路径：

| 组件 | 用途 |
|:---|:---|
| **批量合成请求** | 把工作成组下发，而不是逐件下发 |
| **批量合成作业** | 批量化后的执行单元 |
| **快速路径缓存** | 记住已解析的路径，避免重复计算 |
| **已提取样板执行** | 执行一个已被取出并准备好的样板 |
| 快速路径键 / 结果 / 堆栈 | 缓存的键与载荷类型 |

实际效果是：AE2 逐步遍历每一个合成步骤，而这套东西**先解析并缓存路线、再成批执行**。这正是模组自述「更高性能」而非「更大规模」的含义。

有两个后果值得知道：

**有缓存意味着同类请求的第一次是最慢的那次。** 重复的相同请求收益最大。

**批量化与并行核心相互作用。** 批量只有在「有东西能并发执行多个单元」时才有用，而这正是[合成](03_crafting_system)与[计算](02_computation_system)两套系统的并行核心所提供的。

## 样板编码被打了补丁

本附属有两个 mixin 针对 AE2 的样板编码终端——一个在菜单、一个在界面。因此模组是**在你已经使用的那个终端上**扩展你能编码的内容，而不是另加一台平行的编码设备。

另有一个 mixin 直接访问 AE2 的合成样板内部，这正是「已提取样板执行」背后的机制。

## 合成状态同样被打了补丁

四个 mixin 触及 AE2 的合成状态与 CPU 选择界面：

- CPU 选择列表及其条目，
- 合成 CPU 菜单，
- 合成状态菜单。

**这就是本附属的系统会与 AE2 自家 CPU 并列出现在你已熟悉的界面里的原因**——你不需要另学一套监控界面。

## 合成系统里的流体

`input_hatch` 与 `output_hatch` 是与[计算系统](02_computation_system)共用的流体仓。**跑得热的合成系统需要同样的冷却剂管路**，界面也带有同样的冷/热冷却剂仪表。

## 建造建议

- **注意 `formed` 贴图。** 若外壳仍显示未成形变体，说明多方块无效。
- **先加样板总线容量，再加并行核心。** 无事可做的核心是浪费。
- **排风口需要空间。** 它们是热量出口，blockstate 带有朝向变体。
- **同时建计算系统。** 快速路径的批量化收益与并发执行能力成正比。
