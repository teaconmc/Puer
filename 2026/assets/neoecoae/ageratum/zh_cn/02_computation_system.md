# 计算系统

这是本附属的旗舰多方块，也是它存在的理由。AE2 给你一个合成 CPU，唯一变量是外挂多少协处理器；这套东西把它换成了**一台需要你去做工程设计的机器**。

## 组成部件

| 方块 | 层级 | 作用 |
|:---|:---|:---|
| **`computation_system`** | `l4` / `l6` / `l9` | 控制器 |
| **`computation_parallel_core`** | `l4` / `l6` / `l9` | 同时运行多少任务 |
| **`computation_threading_core`** | `l4` / `l6` / `l9` | 单个任务内的吞吐 |
| **`computation_cooling_controller`** | `l4` / `l6` / `l9` | 管理冷却回路 |
| `computation_drive` | —— | 承载计算介质 |
| `computation_transmitter` | —— | 把系统接入你的 ME 网络 |
| `computation_interface` | —— | 访问点 |
| `computation_casing` | —— | 结构填充 |

**两种核心分开**是关键的设计决定。**并行核心**与**线程核心**是各有层级的不同方块，因此「同时跑更多任务」与「每个任务更快」是你**分别购买**的东西，而不是同一根滑条。

## 层级是 4 / 6 / 9

层级后缀为 `l4`、`l6`、`l9`，界面带有对应的状态贴图。请按你的外壳能支撑的层级建造：低端用铝合金，顶端用黑钨合金。

## 冷却回路是真实存在的

计算接口的贴图明确告诉你这台机器在追踪什么：

| 元素 | 含义 |
|:---|:---|
| **冷却剂进度** | 还剩多少冷冷却剂 |
| **热冷却剂进度** | 已消耗了多少 |
| **冷却 开 / 关** | 由你控制的开关 |
| **上限进度** | 系统距其上限还有多远 |
| **并行状态** | 当前生效的并行容量 |

所以冷却控制器不是装饰。**核心会产热、冷冷却剂会被消耗、热冷却剂会累积**——这意味着一套计算系统需要的不只是电力与频道，还需要**冷却剂供给**。

冷却剂是**低温冷却液（Cryotheum Solution）**，模组把它注册为流体并配有方块与桶，还随包**两条 `neoecoae:cooling` 配方**——模组自有的配方类型，用于产出或再生冷却剂。

流体处理正是合成侧存在 **`input_hatch`** 与 **`output_hatch`** 方块的原因：冷却剂进去，废冷却剂出来。

## 超频

界面还带有**超频 开 / 关**状态。超频开关与冷却仪表并列是一个熟悉的契约：**更高吞吐、更多热量、更快烧掉冷却剂。** 模组把开关与仪表都给你，让你自己决定。

**若系统停滞，先看热冷却剂条，再考虑加核心。**

## 它如何连接

`computation_transmitter` 是把系统接入 ME 网络的方块。这个分离很重要：**计算多方块本身不是一个 ME 设备**，而是你附加上去的机器——这正是它可以独立于网络布局单独建造与升级的原因。

`computation_drive` 承载系统运作所需的介质，就像 AE2 的驱动器承载元件那样。

## 建造建议

- **先冷却再扩容。** 冷却控制器层级低于核心层级，是系统表现不佳最常见的原因。
- **并行与线程不可互换。** 跑很多小任务就买并行；跑少量大任务就买线程。
- **把仓接好管路。** 没有冷却剂路径的计算系统会一直跑到冷冷却剂耗尽然后停下。
- **发射器是唯一的网络接入点。** 一个发射器、一个接入点，请据此规划频道预算。

## 它对合成意味着什么

**计算系统正是让[合成快速路径](03_crafting_system)有价值的东西**：把请求批量化只有在「有东西能同时执行多个」时才有意义。这两套系统被设计为搭配建造。
