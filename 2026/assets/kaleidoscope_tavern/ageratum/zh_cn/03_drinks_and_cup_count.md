# 饮品与杯数系统

这是模组的核心机制，而它比「喝酒施加一个药水效果」有意思得多。

## 一个自定义数据包注册表

饮品定义在 **`data/kaleidoscope_tavern/kaleidoscope_tavern/drink_effect/`** —— 一个含 **24 个条目**的自定义注册表，每种饮品一份。每个文件指定一件物品，并列出**按杯数分级**的效果：

```json
{
  "item": { "id": "kaleidoscope_tavern:brandy" },
  "effects": {
    "1": [ { "effect": "minecraft:nausea", "duration": 30, "amplifier": 0, "probability": 1.0 } ],
    "2": [ { "effect": "kaleidoscope_tavern:slightly_tipsy", "duration": 45, ... } ],
    "3": [ slightly_tipsy 30, high_heels 80 ],
    "4": [ slightly_tipsy 30, high_heels 240 ],
    "5": [ slightly_tipsy 20, high_heels 720 ],
    "6": [ slightly_tipsy 10, high_heels 2160 ]
  }
}
```

**键 `"1"` 到 `"6"` 就是你已经喝了几杯。** 同一件物品会根据你处在序列中的哪一步而做六件不同的事。

## 读一下数值，设计意图就清楚了

以白兰地的递进为例：

| 杯数 | `slightly_tipsy` | `high_heels` |
|---:|---:|---:|
| 1 | ——（换成恶心） | —— |
| 2 | 45 | —— |
| 3 | 30 | 80 |
| 4 | 30 | 240 |
| 5 | **20** | 720 |
| 6 | **10** | **2160** |

两个相反的趋势同时在跑：

::: tip
**微醺时长在*下降*，而主效果时长在*上升*。** 从第 3 杯到第 6 杯，`slightly_tipsy` 从 30 → 30 → 20 → 10 缩短，而 `high_heels` 从 80 → 240 → 720 → 2160 增长。

这读起来就是**建立耐受**：每多喝一杯，你晕得更轻，但携带的效果持续更久。这是一种极优雅的纯数据表达方式，用来表现「习惯了」这件事，完全没有代码分支。
:::

::: warning
**第一杯是刻意难受的。** 白兰地的第 1 杯给 `minecraft:nausea` 30 刻，别的什么都没有——完全没有有益效果。有几种饮品共用这个模式。

因此一个玩家试喝一次、觉得恶心、然后断定这酒不好——**他只看到了第 1 杯**。系统在第二或第三杯之前不会给你回报。
:::

## 并非每种饮品都以同样方式递进

对比**佳丽酿**，它把第二个效果换成了按*放大等级*而非时长递增的治疗：

| 杯数 | `slightly_tipsy` | 其他 |
|---:|---:|:---|
| 1 | —— | 恶心 30 |
| 2 | 45 | —— |
| 3 | 30 | `instant_health` **放大 0** |
| 4 | 30 | `instant_health` **放大 1** |
| 5 | 20 | `instant_health` **放大 2** |
| 6 | 10 | `instant_health` **放大 3** |

`instant_health` 的 `duration: 0` 是因为它是瞬时效果——递增完全体现在放大等级上。**香槟**则沿用白兰地的 `high_heels` 模式。

::: info
所以那 24 个条目不是同一条曲线的 24 份副本。有些饮品递增时长、有些递增放大等级，而用哪一种是它身份的一部分。**读一种饮品的文件是知道它第六杯做什么的唯一办法。**
:::

## 两个自有效果

| 效果 | 作用 |
|:---|:---|
| `kaleidoscope_tavern:slightly_tipsy` | 醉意标记，从第 2 杯起出现 |
| `kaleidoscope_tavern:high_heels` | 若干饮品上那个递增的效果 |

模组也直接使用原版效果——第一杯用 `minecraft:nausea`，佳丽酿用 `minecraft:instant_health`。

## `probability` 是一个字段，而这里它是 1.0

在查看过的文件里，每个效果条目都带 `"probability": 1.0`，因此那些施加是确定的。**这个字段存在**，意味着数据包可以定义基于概率的饮品效果——但随包的饮品没有用它做随机。

## 这对数据包作者意味着什么

这个注册表是完全数据驱动的，因此添加一种饮品不需要代码：

1. 注册或复用一件物品。
2. 往 `drink_effect/` 里放一份按 `"1"` … `"6"` 分级的 JSON。
3. 决定你的递增体现在时长、放大等级还是概率上。

六个杯数等级看来是随包的约定而非这些文件所声明的硬上限；**本页不断言第七杯会发生什么**，因为数据没有说。
